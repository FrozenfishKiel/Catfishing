## 制作一件可使用物品

程序编写行为流程。策划在物品定义的 `UCatItemUseFragment` 选择程序提供的 C++ 行为类，填写成本、前摇、蒙太奇、GE 和命名数值；音效和特效由 GE 关联的 GameplayCue 配置。新增同类内容复用行为类；新的交互机制需要程序实现新的能力行为，策划不编排蓝图执行节点。

| 配置 | 含义、单位与默认值 | 读取者和限制 |
| --- | --- | --- |
| AbilityClass | 使用动作，无默认类 | 随身归属授予对应 Spec；抽象类不可配置 |
| ConsumeCount | 每次成功消耗件数，默认 1，0 为保留原物品 | `UCatAbilityCost_Item` 在服务器支付；装备装配/拿出为 0，正式窝料沿原配置迁为 1 |
| CommitDelay | 生效前摇，秒，默认 0.5 | GA 两端启动任务；正式鱼为 1 秒，装备瞬时入口为 0 |
| Montage | 使用动作，可空 | GAS 负责启动、取消及复制；不再用额外多播重播同一动作 |
| Effects | 提交成功施加给使用者的 GE，默认空 | 自用效果与进食行为读取；领域型装备行为不自动解释这组效果 |
| Magnitudes | GE 使用的 SetByCaller 命名数值，默认空 | 值须有限；鱼经验由实物重量覆盖，客户端不能传经验值 |

物品身份、重量、鱼竿耐久属于实例事实。物品定义和 Fragment 不申请效果、不保存一次使用的执行上下文。`UCatEquipmentItemDefinition` 是库存物品配置；`UCatEquippableItemFragment` 引用独立 `UCatEquippedDefinition`，后者配置装备 Actor 和 AbilitySets。`UCatEquippedInstance` 在装备生命周期内授予/回收能力，SourceObject 指向装备实例，实例关联原物品。

编辑器从物品定义递归验证 Fragment，报告无效能力、负数量、非法秒数和效果参数，并核查装备片段所引用的能力集与世界类。效果型使用必须配置 GE；鱼进食还要求单条成本和成长经验效果类型；装备操作与窝料拒绝不会执行的自用效果。这里不检查 GE 内部修饰器数量，也不把通用 Fragment 限制为经验效果。保存不会自动证明玩法条件、表现或任意自定义 GE 组合正确。

鱼竿选格即拿出，切到其他物品或空格时收回原实例；服务器校验使用锁与身份，切换失败恢复原持有并回执旧选中格。自动拿竿与 `UCatGA_DeployFishingRod` 共用 `PlaceRodFromInventoryUseOnAuthority` 的原格预留、部署及失败释放。其他物品选格只改焦点，左键和菜单仍通过 `UCatItemAbilityComponent` 按行为类及具体 SourceObject 匹配 Spec。随身来源离开库存即取消并撤销其能力；物品正在提交时由 GAS 作用域锁延迟收尾，已付成本后的既定结算不会被同步通知打断。公共/嘴叼进食由默认角色 AbilitySet 授予无固定来源的进食能力。

能力或来源尚未复制时，本机只保留一次输入意图，最多等 2 秒。等待中的取消丢弃意图；连续输入在等待期间松开，随后准备完成时按零蓄力执行。已经激活的释放绑定原 Spec，切格不换结算对象，也不会让同类物品一起响应。

## 网络与提交边界

使用 `AbilitySpec`、`PredictionKey`、`TargetData` 和标准输入事件。动画、蓄力及本地预览可以预测；库存、经验、图鉴、三选一和世界产物只在服务器确认后生效。

每次提交再次核对原来源、可访问性和数量。公共鱼被拿走或先消费后，后来者失败；不能扣另一条同类鱼。前提交取消不扣量，后提交取消不撤销已确认收益。TargetData 最多接受一次；5 秒未收到目标结束等待。日志用 RequestId、物品实例和能力类关联请求及终态。

`CommitAbility` 不是跨系统事务。窝料的环境准备阶段在调用付款前完成水域、范围和配额校验；付款入口仅调用 GA 成本，不接收任意效果执行。库存只扣精确资源，暂缓通知直到窝点终态确认，不保存整包快照回滚。新增成本/GE 若引入同步外部副作用，需要单独审核提交顺序，不能承诺任意效果自动原子回滚。

开发存档版本为 9。旧版本保留磁盘文件并明确拒绝恢复；物品数字编号及实物 GUID 不重编号。
