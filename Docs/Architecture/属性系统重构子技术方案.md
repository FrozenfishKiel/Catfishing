# 属性系统重构子技术方案

文档状态：当前源码同步稿，不是测试报告或验收报告。

更新时间：2026-09-09

适用范围：Catfishing 当前 GAS AttributeSet、GameplayEffect、ExecutionCalculation 与玩法数值归属。本文只描述当前应遵守的结构，数值入口以 Run、FishContainers、Inventory、Equipment、Fishing 和 UI 的当前写口为准。

## 当前结论

属性系统只承载两类适合进入 GAS 的事实：

- 猫身体属性：`Poison`、`FishingStrength`、`FightStamina` 及其恢复、消耗和表现读取。
- Run 公共数值：每日供品目标、最近供品点、世界进度和世界进度变化。

鱼实例、鱼容器数组、正式库存槽位、商店货架、偷鱼协议、钓鱼会话和 UI pending 都不是 Attribute。它们继续由各自领域系统持有，GAS 只在需要统一公式、复制和 GE 写入时参与。

## 当前源码入口

- `Source/Catfishing/AbilitySystem/Attributes/CatSurvivalAttributeSet.*`：猫身体属性。
- `Source/Catfishing/AbilitySystem/Attributes/CatRunAttributeSet.*`：Run 最终公开属性。
- `Source/Catfishing/AbilitySystem/Attributes/CatRunModifierAttributeSet.*`：Run 公式来源倍率。
- `Source/Catfishing/AbilitySystem/Effects/CatRunOfferingSettlementEffect.*`：夜晚供品结算即时 GE。
- `Source/Catfishing/AbilitySystem/Executions/CatRunSettleOfferingExecutionCalculation.*`：供品计数到供品点和世界进度的唯一公式。
- `Source/Catfishing/Framework/Game/CatfishingGameModeBase.*`：Run 命令、阶段、Revision、StateTree 事件和 Run ASC 投影。
- `Source/Catfishing/FishContainers/`：实物鱼和鱼容器事务。
- `Source/Catfishing/Inventory/`：正式道具实例、随身背包和营地公共仓库。

## 设计边界

`ACatCharacter` 继续拥有 Character ASC。`ACatfishingGameState` 拥有 Run ASC。PlayerState 不保存身体属性、鱼容器、正式库存或本地 Profile。

Run 供品结算由 `FCatOfferingSettlementCommand` 进入 `ACatfishingGameModeBase`。GameMode 校验身份、阶段、Revision 和 Run ASC 依赖后，把供品计数写入 `CatRunOfferingSettlementEffect`，再由 `UCatRunSettleOfferingExecutionCalculation` 计算最近供品点、世界进度变化和新的世界进度。UI、FishContainers、Inventory、StateTree Task 和 Ability 都不能直接改世界进度。

FishContainers 只负责实物鱼的唯一归属和容器事务。供品结算消耗的是已经冻结并汇总后的供品计数；Run 不保存第二份鱼数组，不回查鱼定义，也不维护鱼容器预留状态。

Inventory 负责正式道具实例和库存槽位。装备定义、装备选择和鱼竿耐久仍属于 `Equipment/`；背包和营地公共仓库的移动由 `Inventory/` 处理，不复用鱼容器数组。

## 保留规则

- 不新增全局数值注册中心。
- 不把事务 ID、RequestId、Revision、数组或高频模拟状态塞进 AttributeSet。
- 不在 UI、GameMode、Session、Component 各自手写同一供品公式。
- 不为单个调用点提前抽公共公式文件；只有出现真实重复且行为风险明确时再提升。
- 修改 Run、FishContainers、Inventory、Equipment、Fishing 或 UI 的数值入口时，必须同步搜索被替换写口，并让正式运行链只保留一个当前写口。

## 验证要求

当前工作区测试源码修改被运行模式限制；本文件不创建测试计划或验收报告。可执行验证应优先使用现有构建、现有静态检查和现有测试。验证结果必须区分：

- `contract`：源码能否构建，属性/GE/ExecCalc/命令入口是否存在并可链接。
- `runtime_behavior`：进入 Lake、夜晚供品结算、库存移动和存档恢复是否真实运行。
- `presentation_delivery`：正式 UI 是否只显示真实状态，不通过本地假值或过时控件表达进度。
