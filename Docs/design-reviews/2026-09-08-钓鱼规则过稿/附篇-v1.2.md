# 2. 合力钓鱼

<a id="assist"></a>

## 2.1 加入、操作与退出

队友可以搭手帮持竿猫拉鱼。

参与角色有主钓手、辅助手和岸上替补；合力发生在搏斗拉竿阶段，收鱼见[主文收鱼](钓鱼规则-主文.md#landing)。

| 位置 | 操作 | 力量计入 | 消耗倍率 K_pos | 恢复 |
|---|---|---|---|---|
| 钓鱼位（主钓手） | 左键收线／顶住，右键放线 | 100% | 1.0 | 搏斗中不恢复 |
| 辅助位（辅助手） | 左键顶住，无放线权 | 75% | 1.5 | 搏斗中不恢复 |
| 岸上（替补） | 无 | 不计入 | 不适用 | 基础恢复 ×2.0 |

以上倍率均为快照，参数页为准。

入位：靠近搏斗中的主钓手 1.5 米内按 F，统一交互半径加万能交互键，没有单独的帮忙按钮。退出：再按 F 或走出半径，自由来去无惩罚。辅助手体力归零就弹出辅助位，2 秒喘气演出、不落水，恢复到 20% 以上才能重入（快照，参数页为准），防止 1 点体力反复进出抖动。辅助人数不另设上限，受 4 人上限自然约束，主 1 加辅最多 3。

F 的基础选目标规则在[主文](钓鱼规则-主文.md#target)：看着鱼按 F 是抓鱼，看着主钓手按 F 是入位。两者都在视角中心附近分不清时先算抓鱼，可抄窗口比入位稀缺。准星态提示当前 F 目标。

候选鱼继续按[当前可用协作能力](钓鱼规则-主文.md#input-fish)过滤；加入、退出、换人与在局人数变化是能力变化的来源，鱼侧的具体过滤条件由鱼表给出。

<a id="team-force"></a>

## 2.2 力量组成与消耗倍率

`总力量 = 主钓手当前力量 × 100% + Σ 辅助手当前力量 × 75%`，辅助力量不设上限；位置差异收进 `K_pos`（主 1.0、辅 1.5），两者都在上表。合力变化（辅助加入或退出、换人）触发[主文强度检查](钓鱼规则-主文.md#strength)，提交 F_total 与各参与者的 K_pos；猫体力消耗由[主文统一公式](钓鱼规则-主文.md#cost)结算。操作不改变力量。

<a id="team-exit"></a>

## 2.3 归零与放线权限

位置落水只判持竿者；辅助手归零弹出辅助位、不落水，重入条件见 [2.1](#assist)。辅助手没有放线权；主钓手放线时全员零消耗，辅助手不必退出。只有主钓手能触发[主动放弃](钓鱼规则-主文.md#abandon)，辅助自由退出不触发放弃。

<a id="swap"></a>

## 2.4 换人

岸上替补可以接过这根鱼竿。

主钓手任意时刻可按 E 发起换人请求，再按 E 取消。请求无时限挂起，本竿结束自然失效，没有超时出口；挂起期间没有特殊状态，消耗照[主文位移公式](钓鱼规则-主文.md#cost)扣，归零走[持竿者落水](钓鱼规则-主文.md#position)。体力不高于 5% 时 UI 给濒死强提示（快照，参数页为准）。

岸上替补自愿按 E 接手，先按先得，同刻并列按席位序；体力恢复到 50% 以上的替补才能接手（快照，参数页为准）。接手瞬间完成：鱼与竿的状态完全继承，猫体力各是各的，接手者用自己的；图鉴归属不变，原始上钩者保留。被换下者的恢复乘 2，与岸上替补是同一个场景乘数，不叠加（[场景恢复](#scene-recovery)）。

# 3. 抢收、贡献、求助与展示

<a id="competition"></a>

## 3.1 配合与抢收

队友可以抢先把鱼叼走。

多人搏斗到收鱼仍是两条路：可抄鱼贴岸抢抄，或鱼翻肚、碾压落岸后抢拾。资格、实物归属与并列判序见[主文判序](钓鱼规则-主文.md#order)。

搏斗中的猫不能掏窝料，队友可以替他补窝，队友自己得处于可用道具状态（[主文补窝闸门](钓鱼规则-主文.md#nest)）。别人补料不能替持竿者解除道具闸门。

<a id="contribution"></a>

## 3.2 操作贡献与展示

合力拉过竿的猫都算这条鱼的贡献者。

这条鱼的操作贡献者：上钩钓手、有过合力拉竿操作的猫、抄中或拾取的猫；打窝与围观不算。上钩者与实物持有人的分离、剪影与收集的事件时点由[主文捕获事件](钓鱼规则-主文.md#capture)持有。「有过合力拉竿操作」＝合力中按过左键至少一次。贡献只用于演出（合影名单、头衔类），不进图鉴、不刷新个人最佳重量；救援不是玩法，不列救援资格。

举鱼展示、围观互动和巨物合力成功的慢镜头合影保留，演出由内容层补。连携激励只做演出（慢镜头、合影、头衔类），没有任何数值加成，形式由钱成澔在这个边界内发挥。

<a id="help"></a>

## 3.3 手动求助与角色反馈

求助由玩家手动发出：急促猫叫加头顶图标；只有巨物保留全体提示。震动参数与求助输入的定稿归张佳。主辅位的反馈与角色区分归张佳，不做力量百分比条。基础漂主的咬钩感知与铃铛漂的全场声音见[主文反馈](钓鱼规则-主文.md#signals)。

# 4. 合力移动

队伍往大家合力的方向走。

WASD 或方向键控制移动。`F_net = Σ(猫力量 × 方向单位向量)`，按键者才贡献；`S = Σ 猫力量`（按键者）；对齐度 `ρ = |F_net| / S`。无人按键（S = 0）不进入 ρ 计算，直接走全员静止休息档（[4.1](#move-cost)），不存在除零。任意方向的输入都直接进合力求和，不需要归类。

| 档位 | 条件 | 结果 |
|---|---|---|
| 齐步走 | ρ ≥ 高阈（建议 0.8 起测） | 正常移动 |
| 拖行 | 中间 | 队伍朝 F_net 方向龟速走；输入与合力夹角大于 90° 的是被拖者 |
| 僵局 | ρ ≤ 低阈（建议 0.2 起测） | 两组共线反向就对顶：恰 2 人顶牛，4 人 2v2 拔河，其余组合自然推拉、无特定演出；方向散乱就打转 |

阈值均为快照，参数页为准。打转持续超过 5 秒：恰 3 人随机甩飞一只打破僵局，4 人连环摔倒，两者互斥（快照，参数页为准）。移动合力是全额力量相加，钓鱼合力才有辅助位 75% 的折扣，两处口径独立。

直觉校验：缅因 130 对拉两只普通猫（合 100），ρ≈0.13，僵局、自然推拉；对拉一只，ρ≈0.44，拖行。

<a id="move-cost"></a>

## 4.1 移动消耗与归零

移动中体力归零的猫直接趴下、四肢张开、不能主动移动，没有主动拖或背的交互；趴着恢复并随队被拖行，不阻塞编组。这个归零出口不替换[主文搏斗落水](钓鱼规则-主文.md#position)。

| 移动状态 | 体力消耗 |
|---|---|
| 正常移动 | 1 点/秒/人 |
| 龟速移动（拖行） | 被拖者 8 点/秒，顺行者 2 点/秒 |
| 原地打转 | 5 点/秒/人 |
| 顶牛／拔河 | 6 点/秒/人 |
| 无人移动（静止） | 恢复 5 点/秒/人 |

数值均为快照，参数页为准。按体力上限 100 算，拖行档里被拖者 12.5 秒就趴下，顺行者到那时还剩 75 点：走错方向的惩罚来得很快。

<a id="scene-recovery"></a>

## 4.2 场景恢复与摸鱼

不按键的猫不耽误队伍，只占自己便宜。

恢复基数由[主文基础自然恢复](钓鱼规则-主文.md#recovery)提供，场景乘数：全员趴下休息 ×2.0、岸上替补 ×2.0、摸鱼与归零随队被拖 ×2.0（快照，参数页为准）。「静止恢复 5」和「替补 200%」是同一个数（2.5×2）的两种写法，参数页一处基数管三处，不叠加。归零的猫趴着按 ×2 从 0 恢复，到 20% 可起身重入；趴下的猫不进计票，被队伍拖着走。

不按键者不进计票：不贡献力量向量、不拖慢队伍，随队被拖、自己按 ×2 恢复。两档捣蛋由此分明：故意按反方向是真捣蛋，把全队拖进龟速或打转，人人多耗；摸鱼是无害偷懒，只占自己便宜。编组就是同房间全员一队、没有子编组，加入退出即入局离局。

<a id="move-feedback"></a>

## 4.3 群体演出与可读性

UI：屏幕上方按 W/A/S/D 图标显示每个队友当前方向；移动状态文字「齐步走／被拖行／原地打转／顶牛中」；每个角色头顶体力条，趴下时变灰。演出触发只读本页的合力档位，动作表原来的触发条件不作为第二套判定。反馈定稿归张佳与内容层；演出不带奖励，不加彩蛋。

| 动作 | 效果 |
|---|---|
| 顶牛 | 猫头顶头，四肢刨地，3 秒后弹开 |
| 被拖着走 | 被拖的猫脚底摩擦出火星 |
| 原地打转 | 蚊香眼，屏幕旋转模糊特效 |
| 连环摔倒 | 全员趴地 2 秒 |
| 被甩飞 | 随机一只飞出屏幕再跑回来 |
| 拔河拉长 | 队伍拉长成一条线，弹回摔倒 |
| 趴下休息 | 全员原地坐下或趴下，舔爪子 |

动作资源细目见〈动作表现集〉页。
