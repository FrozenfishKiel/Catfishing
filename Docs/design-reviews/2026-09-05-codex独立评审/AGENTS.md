## 材料

`材料/` 下是飞书知识库全库快照（2026-09-05 导出，41 份，约 29 万字）。`材料/00_目录.md` 是索引，含每份的飞书路径与字数。

三件事你应该知道：

- **`40_设计修改记录.md` 是决策账本**，按日期正序记录了每一条已拍的裁决和理由。已经拍板的**偏好**不必重新争论（比如「不做个人排名」「营地不做建造」），但**已拍决定的内部矛盾、连带后果、以及它和别处的冲突，正是要查的**。
- **`43_数值模拟与参数记录.md` 是数值出处**，`06_GDD 系统分册.md` 是索引页（含术语总表、跨册接口、统一模板、出处规则）。
- 三份「裁决同步」页是给三位同事的待办清单，`36`/`38`/`39`。

材料就是全部。**没有别的上下文，也不需要向我要**——你看到什么就是什么，这正是这次评审的意义。

**不要读本目录以外的任何文件。** 上级目录 `../` 下有十几个历史评审文件夹，里面是别人做过的评审结论和待裁清单。读了它们，这次评审就不独立了，等于白做。你只能读 `材料/`。

## 你要找什么

**结构漏洞，不是错别字，也不是版式。** 典型形态：

- 某条规则在某个人数、某个时刻、某个状态下**没有定义**
- 两条规则各自成立，**合起来产生一个没人想要的最优解**（摆烂、挂机、只做某一件事最划算）
- 某个系统**失去了它唯一的下游消费者**，或者从来就没有下游
- 某条明写的禁区**被另一条机制从侧门违反**
- **同一个词在不同页指不同的东西**，或同一个数在不同页对不上
- 某项工作**没有属主**，或属主与实际改动的人对不上
- 招牌玩法投入很大，但**在核心目标上不产生对应回报**

## 三条硬要求

1. **算给我看。** 凡涉及数值松紧、时长、人数缩放、概率，把算式跑出来贴上来（你可以用 PowerShell 或 Python）。不要写「可能偏紧」，要写「按 X 算是 N，要求是 M，差 K」。
2. **引用到节。** 每条发现注明是哪份文件的哪一节，最好带原文短句。
3. **只读。** 不要修改任何文件，不要尝试访问飞书。

## 输出

写到 `codex评审报告.md`，结构：

```
## 一句话判断
## 严重发现（按严重度排序）
每条：标题 / 事实（引原文+节号）/ 为什么是问题（含算式）/ 至少两条解法与各自代价
## 次要发现（一条一行）
## 我看不懂或材料没说清的
## 我检查过但认为不成问题的（一条一行）
```

最后一节很重要——它让我知道你的覆盖面，而不只是命中面。

不要给「建议改成 X」式的单一结论，给选项和代价。判断权不在你。
