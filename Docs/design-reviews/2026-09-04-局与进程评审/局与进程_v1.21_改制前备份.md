<title>局与进程</title>

> 本分册范围：纵向骨架，管「局」与「天」的双层结构、每日献祭额度与失败判定、跨局归属清单、单 / 多人形态。祭坛的目标结构定义在此（联机册持社交层、营地册持动线、形象包装归 A4）。

# 1. 设计意图

**1.1 北极星贡献。**热闹和治愈各占一段：白天限时，忙和闹都压在这段；夜晚不限时，是白天拼出来的放松。每天一个献祭额度，全队盯同一个数；失败全队一起摊，能当故事讲。

**1.2 体验设计。**

| 体验 | 🎯 想塑造的体验 | 🛠️ 当前设计 | 🔍 达成度与缺口 |
|-|-|-|-|
| 白天的心跳 | 「缸里还差三条才够今晚交！」全队为同一件事忙起来 | 白天限时纯生产（钓鱼攒缸，白天不可献祭），压力对照缸存量 | 有时间压力，捣乱才刺激，也逼着大家合作；压力只在白天有 |
| 夜晚先交作业再放松 | 献祭仪式交齐额度，「今天稳了」 | 入夜由时间驱动；夜晚开场＝全队献祭仪式，交齐后无时限：火边、观赏、闲逛 | 治愈的部分固定放在夜晚，而且是白天拼出来的，玩家会更珍惜 |
| 团灭的戏剧 | 失败也是全队共同的故事，「差两条鱼，全员饿在湖边」这结局能笑着讲 | 额度未达＝这一局失败，进结算 | 失败演出的喜剧化归内容层；照片还在，失败不清跨局持久 |
| 翻天的仪式 | 「都好了吗？出发！」 | 全员同意开始新的一天（单人＝自己确认） | 夜晚待多久玩家自己定，系统不催 |

**1.3 玩家策略路线。**今天多钓存缸（给明天减压）vs 献完就玩（享受当下）；冲额度 vs 蹲稀有（额度紧张的日子没空追图鉴）；偷缸里的储备＝偷明天的粮，代价是实的。

**1.4 设计禁区。**

- ❌ **夜晚出现任何计时或催促**。
- ❌ **失败回滚跨局持久**（图鉴 / 印记 / 解锁永不回滚）。
- ❌ **局外元进度**（每日任务 / 赛季）。局与局之间只有收集与解锁，没有义务。

# 2. 核心循环（双层）

**天循环：**

1. 清晨：全员在营地醒来，按在场人数确定当日额度
2. 白天（限时）：钓鱼 / 捣乱 / 攒缸——白天不可献祭
3. 入夜（时间驱动）：不再有鱼上钩，进行中的搏斗打完（压哨鱼照常可献）
4. 夜晚开场：全队献祭仪式，从缸中挑鱼上供当日额度
5. 火边 / 观赏 / 闲逛（无时限，玩家主动才结束）
6. 全员同意翻天＝结算点：额度已交齐 → 新的一天；未交齐 → 局失败进结算夜

**局循环：**开局初始化（营地 / 祭坛 / 时间）→ 天循环 × N → 结束（额度未达＝失败；或坚持到第 10 天（暂定）毕业＝圆满结局）→ 结算：图鉴 / 印记 / 解锁入册（跟人走），营地与缸清空（跟局走）。

# 3. 机制清单

## 3.1 设计意图核心

### 1. 天的时间结构

白天＝时间驱动弧线（清晨→黄昏），到点即入夜、入夜不判定额度；入夜后不再有鱼咬钩，进行中的搏斗允许打完（压哨鱼进夜后照常可献）。夜晚＝没有钟，时间不走；额度结算点＝翻天确认时。天弧线的光影细节归环境册。

**⚠️ 最容易破的实施陷阱。**夜晚偷偷藏着隐形计时（比如挂机踢人）。夜晚不能有任何钟。

### 2. 每日献祭额度

每天一个额度，逐日上升（一局的压力曲线）；前期纯数量，后期附鱼种指向（把图鉴与装备准备串进白天）。首版快照（2026-08-19 第二轮模拟，参数页为准）：额度＝条/人，首日 5、第 10 天 12，线性插值取整（5/6/7/7/8/9/10/10/11/12），乘当日清晨在场人数——约为零道具基线 26 条/人/天的两成到五成，给吃／卖／贴岸留余量；世界进度总量＝200 点 × 开局在场人数。额度每天清晨按在场人数确定、当天内不变（2026-08-16 拍定）。献祭是夜晚限定的主动仪式——白天只攒不献，夜晚开场全队从缸中挑鱼上供；结算点＝翻天确认时：交齐 → 新的一天，未交齐 → 局失败（不翻天可一直留在夜里，视为玩家自由）。臭臭鱼可献：计入额度数量、世界进度 -1（进度下限 0）。献祭同时累积「世界进度」（融合案，2026-08-15 拍定）：进度驱动森林复苏演出，进度条按第 10 天毕业时约满校准；它是额度之上的累计层，不改变额度判定与局终点，也不做个人供奉排名（局末结算用非排序趣味头衔＋全员合影）。

**⚠️ 最容易破的实施陷阱。**额度松到形同虚设，白天就没人着急了。

### 3. 失败与结算

失败＝这局立刻进结算夜：商店收摊、买卖冻结，吃鱼与篝火照常（毕业夜同口径）——火照样生，该待还待，然后局结束。跨局持久永不因失败回滚。

**⚠️ 最容易破的实施陷阱。**失败画面做成冷冰冰的结算板。失败要演成喜剧，不是事故。

### 4. 翻天

夜晚全员同意（就绪确认）→ 结算当日额度 → 交齐进新的一天、未交齐＝局失败；确认时强制打断一切进行中互动，翻天后全员清晨在营地醒来（未获救的倒地者自动救起）；单人＝自己确认；离开的玩家不阻塞（按在场者算）；恶意不翻天由房主踢人兜底（组局规则见联机册）。

### 5. 局的终点

毕业终点：坚持到第 10 天（暂定）并达成额度＝圆满结局，一轮下来有头有尾；无尽模式后置。

### 6. 跨局归属清单

跟人走＝图鉴、印记相册、外观解锁（A5 已关账＝解锁是表达型；装备属团队装备库、跟局走）；跟局走＝营地、鱼缸与局内图鉴（跨天留存、局末随局清空）、消耗品数量、公款与团队装备库（公有、随局清空，已确认；局末收摊仪式见商店册）、猫状态、祭坛进度与世界进度。解锁触发源＝天数 / 额度里程碑。一句话：身份跟人走，物资跟局走。

### 7. 单 / 多人形态

同一套局结构，靠参数调：额度按人数缩放、翻天＝自己确认、聚鱼时刻与回看照常；鱼的刷新按在场协作能力设上限（单人局不出巨型鱼，规则归鱼册）；不做独立单人模式。

## 3.2 实施考量

白天时长 × 额度松紧是全游戏的节奏命门（数值阶段的第一优先参数）；「白天有钟、夜晚无钟」把压力和治愈分开，是本册最重要的不变式；鱼缸跨天留存让「今天多钓」变成策略，被偷的损失也变大，偷取权限开关更要紧（联机册）。

# 4. 系统边界

**硬性。**

- 夜晚无计时。
- 失败不回滚跨局持久。
- 无局外元进度。

**软性。**

- 翻天与失败都要有猫味演出（内容层）。
- 额度进度的呈现归交互层（方向：祭坛本体即进度可视化）。

# 5. 涌现案例

- 额度快到截止时全队疯狂冲刺，这段最容易出印记素材（positive）。
- 缸里储备够多的「富裕日」，全队提前开始度假（positive）。
- 额度紧张的日子有人偷吃储备，被追着打，格外热闹（positive / negative，皮不毒护栏见联机册）。
- 最后一条鱼献不献（保命还是留着观赏）的全队争论（positive）。

# 6. 体验锚定数字

- **白天时长**：决定每天有多赶。
- **每日额度曲线**（首日宽松度 / 爬升斜率）：一局的压力怎么爬，看这条。
- **失败率预算**：多久团灭一次。
- **一局天数**（暂定 10）：一轮的故事有多长。

# 7. 视觉反馈通道

白天全队可见「缸内可献存量 vs 今日额度」（形式归交互层）；夜晚献祭仪式中祭坛即进度条；缸存量告急的全场氛围信号归环境册（声音与光线）。

# 8. 何时回审

额度曲线与天数数值定稿时。A5 与 A6 均已关账——解锁＝表达型；单人不刷需要多人的鱼、不做独立单人模式。

# 9. Playtest 验收预期

- 团灭时大家在笑还是在互相埋怨。
- 夜晚会不会被急性子秒过，无时限是否形同虚设。
- 「再来一天」与「再来一局」的意愿分别有多强。
- 额度压力是否侵入夜晚（不应该）。
