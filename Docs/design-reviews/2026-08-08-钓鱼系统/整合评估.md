> **评审方法**: 4 个并行 game-designer Agent，分别从**体验与节奏**、**愿景一致性**、**数值与经济**、**系统交互与冗余**视角评审，结果整合

**整合结论速览**：四视角共产出 58 条发现，交叉比对后归并为 **22 个共识问题**（其中 3-4 视角强共识 13 个）+ **6 项独特发现**。数值评审的全部发现均获其他视角呼应，交叉验证度极高，说明问题真实集中。四视角对"骨架优秀、应修剪而非重写"的判断完全一致；问题集中于三条主线：**压力机制未被治愈基调消化**、**参数与判定层整体缺失**、**对 7 个空分册的大量未声明依赖**。

## 一、多位评审员共识（多方都指出的问题）

### P0 级共识（必须修复才能并入分册）

#### 共识 1：等待阶段被设计成"注意力测试"，与愿景"看花观鸟/离开钓位"直接冲突 🔴（4视角）

| 视角 | 发现 |
|------|------|
| **体验** | 体验1 🔴：专注盯漂 + 极短反应窗口与"看花观鸟/偷鱼"不可兼得，等待从治愈时光退化为强制值守；建议预警链（试探期远距离信号、镜头拉回）+ 轻惩罚 + 守株/专注双轨钓法 |
| **愿景** | 愿景01 🔴：信号链训练出的最优行为是"全程紧盯屏幕"，恰是愿景反面；等待期是时间占比最大环节，这里失守则治愈感整体失守；建议宽容窗口 + 远距离可感知信号 + 低投入架竿钓法 |
| **系统交互** | 交互3 🔴（等待部分）：等待阶段玩家"能做什么"完全空白，环境交互窗口未设计，恰是本作与普通钓鱼游戏的差异化时刻 |
| **数值** | 数值D1-P08 / D12：咬钩间隔是"治愈节奏的第一参数"（要长到能看花观鸟、短到不流失），当前无分布约束、无上限兜底 |

**核心问题**：这是全文档最核心的定位冲突——决定本作是"盯漂的钓鱼游戏"还是"湖畔的治愈游戏"。四视角解法方向一致：宽容窗口 + 远距离可感知预警链（猫耳朵音效/震动）+ 错过低惩罚 + 低投入钓法双轨。必须在并入分册前拍板。

#### 共识 2：刺鱼判定只定义 0.3 秒暴击窗，普通有效窗口完全缺失 🔴（3视角）

| 视角 | 发现 |
|------|------|
| **体验** | 体验2 🔴：0.3 秒接近人类反应极限（格斗游戏级精度），治愈系新手会被挡在门外；建议两层窗口（有效 1.5~2.5s + 暴击放宽至 0.5s），弹性难度放装备上 |
| **数值** | 数值D2 🔴：决定可达性的普通窗口反而没写；"试探→真咬"间隔固定还是随机对应完全不同的"技巧 vs 运气"定位，必须显式拍板；建议窄幅随机 1.5~2.5s + 暴击只缩短搏斗不决定成败 |
| **愿景** | 愿景01（内含）：真咬期建议 1.5~2 秒起判；0.3 秒暴击窗保留为纯增益、错过零惩罚——奖励盯漂党，不惩罚看花党 |

**核心问题**：三视角给出的修复参数高度一致（普通窗 1.5~2.5s、暴击为纯增益锦上添花）。若不补普通窗口定义，实现者极可能把 0.3 秒当唯一窗口做出来。

#### 共识 3：失败惩罚链顶端过重（扑空前功尽弃 / 被拖下水昏迷），损耗规则不成体系 🔴（4视角）

| 视角 | 发现 |
|------|------|
| **体验** | 体验3 🔴：扑空清零发生在兴趣曲线最高点，是"高潮坠崖"；"昏迷"措辞与机制双重出戏；体验8 🟡：四种失败的善后流程（饵/鱼群/窝点状态）均无描述。建议二次机会结构 + 剪影补偿 + 删除昏迷改为落水喜剧 |
| **愿景** | 愿景02 🔴：昏迷=剥夺控制权，是挫败放大器，且单人玩家无解，打破"单人可玩"承诺；愿景05 🟡：失败链与饥饿系统可能咬合成死亡螺旋 |
| **数值** | 数值D9 🟡：四种失败场景损耗规则各说各话；"扑空=前功尽弃"因果存疑（鱼还在钩上为何直接跑掉），建议统一损耗表 + 扑空退回搏斗阶段；数值D14 🟢：昏迷未量化，无法计算风险期望值 |
| **系统交互** | 交互5 🔴（昏迷部分）："昏迷"是幽灵状态——猫咪与状态分册只有饥饿/疲劳/淋湿三项，昏迷无人承接，时长/苏醒/救援全空白 |

**核心问题**：四视角一致要求"失败轻量化 + 规则一致化"：删除昏迷（改为落水→爬上岸→淋湿的猫式喜剧）、扑空改二次机会（鱼退回挣扎区/恢复部分体力）、建立统一损耗表（越早期失败成本越低、试探空竿零成本）。数值D9 的损耗表可直接作为落地载体。

#### 共识 4：渔获去向缺"吃"，生存循环供给链断裂；"上供古神"是世界观外幽灵概念 🔴（4视角）

| 视角 | 发现 |
|------|------|
| **体验** | 跨系统发现：结算选项（放生/上供/鱼缸）中没有"吃"——北极星的"吃鱼维持饥饿"动机闭环在本文档断裂；"上供古神"全项目无出处 |
| **愿景** | 愿景03 🔴：上供古神（克系意象）、大渔旗（人类渔业符号）、点赞撒花（直播语汇）全部出现在情绪峰值位置，破坏"自然湖畔猫世界"统一性；建议逐个替换为猫世界等价物 |
| **数值** | 数值D5 🔴：吃鱼是钓鱼产出与生存循环的唯一接口，缺失导致全项目最重要的跨系统数值等式（上鱼率×饱食值≥饥饿消耗）无锚可依；建议补"产出率承诺"小节 |
| **系统交互** | 交互1 🔴：钓鱼是生存循环的供给端，结算处把主干数据流切断；与鱼类图鉴分册的去向枚举两套清单冲突；"上供古神"需删除/立项/入未定项附录三选一 |

**核心问题**：唯一被四视角全部标红的问题。修复动作明确：去向清单加"吃掉（回复饥饿）"，"上供古神"移出正文提交项目级决策，与鱼类图鉴分册对齐唯一的去向枚举。

#### 共识 5：经验/称号/稀有奖励/合作重量加成暗示未立项的成长系统 🔴（3视角）

| 视角 | 发现 |
|------|------|
| **愿景** | 愿景10 🟡：外在数值进度会让玩家"为效率钓鱼而非为湖畔时光钓鱼"；建议成长载体改为表达解锁（外观/动作）与记忆（合影页），先拍定项目成长观 |
| **数值** | 数值D11 🟡：合作加成加在重量上污染图鉴客观数据（最大重量纪录变成"是否合作纪录"），单人玩家在收集维度被系统性压制；建议改结算积分×1.5 + "协力"标签独立成轴 |
| **系统交互** | 交互2 🔴：经验+称号+稀有奖励合起来是完整成长/激励系统，8 个分册均无归属，不应由钓鱼文档两处顺带提及事实上拍板项目级决策 |

**核心问题**：成长观是项目级决策。共识方案：移除"经验"或改为图鉴/印记类非数值表达；重量保持客观；称号/稀有奖励明确归属分册后再保留。

#### 共识 6：恶作剧零成本零冷却、可清零他人数分钟投入，皮/毒边界未定义 🟡→P0（4视角，共识提升）

| 视角 | 发现 |
|------|------|
| **体验** | 体验11 🟡：清零 2~3 分钟投入超出玩闹阈值；全局开关是钝器；建议冷却+场次上限、鱼群 15~30s 自动回窝、单向损失改双向演出（追打滑稽互动） |
| **愿景** | 愿景06 🟡："设置里可关"是免责声明不是设计；建议高赌注阶段（搏斗/稀有鱼）免疫、后果可恢复、被发现的恶作剧猫被扑倒滚成一团 |
| **数值** | 数值D10 🟡：7 人围观 1 钓手的骚扰频率无上限；免费动作可摧毁 3 份魔法料投资甚至一场盛宴，是全游戏 EV 最高的"玩法"，必然被滥用；建议道具化/长冷却+目标共享冷却+效果降级 |
| **系统交互** | 交互8 🟡：恶作剧与愿景"偷鱼"同属负面社交互动，重叠/互补关系未定义；"关闭友好伤害"作用域不明（个人关闭会导致 8 人房规则不一致） |

**核心问题**：四视角独立指出且方案高度互补（成本/冷却 × 阶段免疫 × 损失可恢复 × 开关分层）。原始严重度均为 P1，四视角共识提升为 P0——若以当前形态并入分册，毒性交互将固化并在联机场景产生真实愤怒，属基调级风险。

#### 共识 7：单人内容自相矛盾与天花板：中型鱼"单人可完成"vs"必须双人抄网"；巨物/盛宴单人零份额 🔴（3视角）

| 视角 | 发现 |
|------|------|
| **数值** | 数值D3 🔴：§一宣称"支持单人完成"，§6 又说双人抄网"专门针对中型以上的鱼"——规则级自相矛盾；稀有度与体型两轴混用，若稀有=巨物=多人，单人收集线断裂；建议四级体型表 + 中型鱼单人可捞但窗口更严 + 稀有小型鱼保障单人收集线 |
| **愿景** | 愿景07 🟡：巅峰体验（盛宴/巨物/慢镜头合影/称号）单人份额为零，"这游戏最好的东西不属于我"是内容存在性问题；建议单人可遇"巨大的影子"+ 低概率单人巨物通道 |
| **系统交互** | 交互10 🟡：单人天花板止步中型鱼可以是有意取舍但必须显式写下；建议"单人可遭遇但无法捕获（断线逃脱演出+生成印记）"；同时 5-8 人场景无设计（协作最多消耗 4 人） |

**核心问题**：先修文字矛盾（D3 的体型分级表），再拍单人/多人内容配比决策（建议采纳"单人可遭遇、多人可捕获"折中案，兼顾感知可能性与联机动机）。

#### 共识 8：经济闭环断裂——窝料/鱼饵只有消耗端，获取端完全未提 🔴（2视角）

| 视角 | 发现 |
|------|------|
| **数值** | 数值D4 🔴：断线惩罚的威慑力=鱼饵获取成本，当前完全悬空；鱼饵稀缺则新手陷入"没饵→钓不了→没资源"死锁，违反"玩家不会卡死"底线；建议保底饵免费无限 + 进阶饵有成本 + 断线损失锚定 1~3 分钟采集时间 |
| **系统交互** | 交互6 🟡：窝料、抄网、逗猫棒、小石头均超出「装备与道具」分册规划范围；背包/装备栏是未立项全局系统；建议"道具依赖清单"表格推动分册扩围 |

**核心问题**：钓鱼系统的全部风险决策（断线丢饵、窝料三档）意义寄生在空白的装备分册上。以"接口清单+价格量级承诺"形式显式化依赖，勿等对方分册启动后返工。

#### 共识 9：数值/节奏参数层整体缺失（约 24 项待参数化，全流程无时长量级） 🔴（2视角）

| 视角 | 发现 |
|------|------|
| **数值** | 数值D1 🔴：全文唯一硬数字是 0.3 秒；24 项待参数化清单（P01~P24）已盘点完毕，每项附体验锚；建议升级为"参数字典"，先定 4 个顶层体验锚（单轮时长/失败率<20%/稀有频率/骚扰上限）反推其余 |
| **体验** | 体验7 🟡：7 阶段无一给出目标时长，兴趣曲线无时间轴无法校验；已给出目标节奏表建议（普通鱼单轮 1.5~3min、巨物 4~6min）；体验4 🟡：咬钩保底节奏未设计 |

**核心问题**：体验7 的节奏表 + 数值D1 的参数字典可直接合并为分册的"参数字典"章节地基。原则：数值从体验锚反推，每个数字可被指认、可被测试、可被推翻。

#### 共识 10：图鉴术语混用（个人钓鱼图鉴/鱼类图鉴/印记图鉴），记录模型未对齐 🔴（2视角）

| 视角 | 发现 |
|------|------|
| **系统交互** | 交互4 🔴："个人钓鱼图鉴"是第三套图鉴还是别名？自动记录模型 vs 上交模型对结算流程要求完全不同；§6 慢镜头拍照与印记图鉴疑似重复建设；建议统一命名 + 结算数据分流（鱼种/重量/稀有度→鱼类图鉴；搏斗时间/协作时刻/慢镜头→印记图鉴） |
| **愿景** | 愿景13 🟢：鱼类图鉴（收集进度）与印记图鉴（时刻相册）职责完全不同，混用导致分册踩线；"营地鱼缸""放生"是未声明接口 |

**核心问题**：纯文字层面修复成本极低但必须在并入前完成，否则信息源不唯一将污染两个下游分册。

## 二、体验视角独特发现

### 体验5+6 🟡 搏斗核心反馈层未设计：阶段切换信号与张力呈现双缺失

## 三、愿景视角独特发现

### 愿景04 🟡 拟人度执行不一致：自立"无人类双手"规矩又多处破戒
第三节声明"无人类双手，依靠嘴巴+前爪操作钓具"，但抄网猫"双手举着抄网杆"、双人庆祝"击掌"、拔萝卜"抱腰"均为人类身体逻辑。"所有动作都是猫的真实行为"是差异化命脉，执行标准必须二值。建议建立**猫性检查表**作为并入 GDD 的过稿红线：抄网→嘴叼网杆+前爪压杆；击掌→碰鼻子（文档已有）；抱腰→咬尾巴/叼后颈皮，与"拽尾巴救援"统一为同一套猫式发力语言。

## 五、系统交互视角独特发现

### 交互5 🔴 钓鱼状态机的进出边界未定义（昏迷部分已归共识3）
如何主动退出（等待中能否收竿？搏斗中能否弃鱼？展示动画能否跳过）、被打断后回到哪一环、协作者的状态机（抄网手须先收竿吗？窝料进度作废吗？抱腰者如何退出）、钓鱼中的猫对外暴露哪些可交互性——全部未写。建议新增"状态机与打断规则"一节，画状态转换图，逐状态标注退出代价与回退目标。协作机会成本直接影响联机社交分册的协作节奏设计。

### 交互13 🟡 "自动求助表情"违背玩家主动性与信噪比，窝点指示双轨冗余
每次上钩自动全队广播"快来帮忙！"：小鱼也广播造成噪音、恶作剧空竿会触发假求助（规则不一致）、单人模式发给谁？且剥夺玩家表达主动权（把"求助"从社交行为降级为系统通知）。建议分级：小鱼仅头顶图标→中型以上提示可主动按键求助→Boss 才自动广播。窝料光环与猫爪标记双轨表达同一信息，建议合并。

### 交互14 🟢 章节与分册边界错位：§三动画规范等应按映射表拆出
本文档实际覆盖至少 6 个分册的内容，§三"动作捕捉与动画系统"通篇是全局猫表现技术方案，应归「猫咪与状态」。已给出完整"章节→分册映射表"，并入时按表拆分，拆出内容以"接口引用+链接"保留，接缝用统一 `[依赖: 分册名]` 标注。

### 交互12（部分） 🟢 手柄方案整体缺失
手柄震动已深度写入咬钩信号设计（试探轻震/真咬剧震是核心信息通道），但手柄键位映射不存在——表现层引用了输入层未定义能力。建议 §三 增加手柄小节或文首声明"v0.1 仅覆盖键鼠"。

## 九、总体评价

**四视角的一致判断：这是一份骨架质量显著高于典型 v0.1 的初稿，评审结论是"修剪与补齐"，不是重写。** 7 阶段构成完整的经典兴趣曲线，张力-体力搏斗自带分形节奏，贯穿全程的猫行为观察级描写是全项目最有辨识度的资产，打窝机制则是"无强制任务框架下机制自发诱导协作"的教科书样板。体验瞬间的质量与北极星愿景高度同频。

**当前核心风险集中在三条主线**：

1. **压力机制尚未被治愈基调消化**（共识1、2、3、6）——专注式等待、格斗级判定精度、清零式惩罚、昏迷、零成本恶作剧，都是传统钓鱼/生存/派对游戏的硬核逻辑残留。修复方向四视角完全一致：窗口宽、失败轻、重试快、失败也好笑、损失可恢复，并用印记纪念品把挫败转译为社交货币。

2. **参数与判定层整体缺失**（共识2、9、11、12、17）——全文唯一硬数字是 0.3 秒，约 24 项参数悬空，所有"同时"判定无窗口定义。数值评审的参数字典 + 体验评审的节奏表已提供现成骨架，先定 4 个顶层体验锚（单轮时长 / 失败率 / 稀有频率 / 骚扰上限）反推其余，再用灰盒原型验证搏斗手感。

3. **系统边界意识未建立**（共识4、5、8、10、14、15，议题1-7）——本稿不自觉扮演了"整个游戏的设计"，向 7 个空分册伸出大量未声明依赖（体力、分布表、背包、图鉴、恶作剧），并夹带两个分册表外的幽灵系统（上供古神、经验/称号成长），最严重处是钓上来的鱼竟然不能"吃"——愿景钦定的生存循环供给端在结算处断裂。需按"依赖显式化 → 内部一致性修订 → 幽灵系统项目级裁决"三步走，7 个跨系统议题建议启动 Teams 讨论。

**建议的修复次序**：先做零成本文字修复（渔获加"吃"、古神移出、单人矛盾、图鉴术语、抛竿二义性），再拍三个结构性决策（等待模式、失败惩罚基调、成长观），然后补参数字典与接口清单，最后灰盒原型验证搏斗手感与判定窗口。完成后，本稿核心循环部分即可作为「钓鱼系统」分册的合格底稿，其余内容成为各空分册开工的第一批需求输入——这正是第一份实稿能为项目做出的最大贡献。
