# 分册整理 · 上下文包（所有整理与定稿 Agent 必读）

## 一、北极星（一切内容对齐它）

一句话：「一群猫好友的湖畔钓鱼派对：为大鱼合力，为整蛊炸毛，篝火边翻翻今天的照片。」
情绪排序：**热闹为主**（好友聚在一起）＞ 快乐与搞怪并存（失败与翻车是内容）＞ 治愈是底色与余味（不与热闹抢戏）。单人可玩是功能底线，设计资源向多人倾斜。

**设计语言四问**（每个机制都要能回答）：① 好笑吗，笑点是不是猫？② 让一群人更热闹还是更安静？③ 被整 / 失败的人也笑得出来吗？④ 会留下值得回看的瞬间吗？

## 二、已拍定的世界结构与系统决策（整理时视为事实，不得违背）

1. **没有真实时间**：时间为局内推进；昼夜天气可以存在，但时钟源是局内时间流，不跟随现实时钟。
2. **没有沙盒房间**：不做"房间＝持续保存、长期成长的共享世界"。游戏是**局制**：开一局、玩、结束。
3. **营地跟局走**：营地是一局内的固定据点（篝火 / 共用大鱼缸 / 烹饪休息 / 仓库修竿 / 标本位），局末清空。**跨局持久载体＝图鉴与印记相册**（装备/装饰解锁是否跟人走待确认）。
4. **营地建设玩法已删除**：无自由布置、无装饰收集、无营地成长、无搬迁。玩家个性表达转移到猫外观、图鉴与照片。
5. **王霸比拼已删除**：整个机制不存在了，任何引用都要清掉。
6. **渔获流已拍定**：钓到瞬间图鉴自动记录 → 入随身**鱼护**（钓点边暂存，可被偷）→ 带回营地入**共用大鱼缸**（鱼带主人色环）→ 献祭 / 吃掉回饥饿（生吃有中毒风险、烹饪安全）/ 留缸观赏（可被偷吃）→ 局末剩鱼放生回湖。
7. **偷了就吃**：偷鱼对象＝他人鱼护 + 共用大缸；叼起就跑、进食需时间（唯一追回窗口）；被抓＝物归原主＋被扑倒滚成一团＋双方进印记；**不设保护机制**；护栏＝偷取权限开关＋图鉴不丢。偷吃回复饥饿（懒猫觅食路线）。
8. **祭坛存在**（献祭是渔获主要去向、全队共同目标）；但「失败触发灾害事件」与治愈底色冲突，**待重议**——整理时把灾害惩罚标为待定，可给替代方向（失败滑稽化 / 只失进度）。
9. **钓鱼系统册是正式版**（讨论过的），整理其他册时以它为接口基准，不改它。
10. 等待期已拍定：不盯漂也能钓，咬钩信号远距离可感知，等待中玩家可自由活动。

## 五、写作规范

- 统一模板 §1-§10（1.1 北极星贡献 / 1.2 体验设计🎯🛠️🔍 / 1.3 策略路线 / 1.4 禁区 / 2 核心循环 / 3 机制清单含"最容易破的实施陷阱" / 3.2 实施考量 / 4 边界 / 5 涌现 / 6 锚定数字 / 7 反馈通道 / 8 回审 / 9 Playtest / 10 速查）。
- **大白话**，说人话，少术语；原稿作者的好内容尽量保留原话，删改要有依据（依据＝本文件的决策与四问）。
- 云文档风格：只写结果，不写讨论过程；**不用日期状态标记**；未定的事用「（待定：…）」。
- 每册必须做两件事：**补①**（每个机制过一遍"笑点是不是猫"，给出猫味演出）与**补④**（值得记住的时刻显式写"抛印记事件"）。
- 不写数值（数值阶段另办），锚定数字只写"调它会改什么"。
