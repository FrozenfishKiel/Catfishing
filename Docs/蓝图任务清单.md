### 1.5 挥网的重定向与多人表现

抄网由选中实例的 Use 捕获视线与目标，服务器校验物品身份后将捕获排入帧末裁决。统一库存回执先处于 Pending，收到钓鱼终态才结束；重放同一请求不重复捕获。成功直接叼嘴，挥空沿用原冷却。

正式 `/Game/Character/BP_CatCharacterBase` 的 `BP_PlayCosmeticEvent` 接收 `Cat.Cosmetic.Fishing.ScoopSwing`，在 Character 上调用 **Play Anim Montage**。该入口经过 `ACatCharacter::PlayAnimMontage` 的角色映射，CuteCat 使用重定向后的 Montage。不要把原猫 Montage 直接接到新猫的 Get Mesh → Play Montage；已删除的旧抄网 Ability 蓝图正是这条绕过映射的路径。

挥网由服务器多播，发起者与旁观者都接收一次。统一 Use 不再有旧 Ability 的本地预测播放，不能继续跳过本地控制端。提竿同样沿用现有服务器确认播放契约。多播是非可靠表现事件，最终捕获事实和回执走原权威链。

当前能力来源：已部署鱼竿由 `DA_CatAbilitySet_RodOperations` 授予操作能力；窝料由选中实例授予 `DA_CatAbilitySet_ChumUse`；抄网是瞬时 Use，不加入默认能力集。不要恢复旧 F/Q Ability 或在默认能力集常驻授予这些操作。

### 1.6 验收入口

选中窝料，按住左键后松开，只消耗按下时的实例；取消不扣量。选中抄网，左键瞄鱼使用，客户端与房主应看到挥网和同一条鱼进入嘴部。持杆时左键继续操作鱼竿，需要换网时先 R 放杆，再切换快捷栏。Q 保留丢嘴叼物，E 保留交互，X 保留收杆。

Automation 入口：`Catfishing.Unit.Fishing.Inventory`、`Catfishing.Editor.Inventory.Tools`、`Catfishing.CharacterVariants`。资产迁移脚本 `Scripts/migrate_scoop_chum_left_click.py` 审计旧包引用、正式 AbilitySet 和 IMC 后清理无消费者的旧资产；不能仅凭源码搜索删除蓝图。

## 任务 2：Rod / Hook 表现蓝图与鱼种库表现

**目的**：给场景里的竿、钩（浮漂）、鱼挂上真实 Mesh。权威边界详见《FishingActorBlueprintHooks_zh-CN.md》，这里只列操作。鱼不再使用一个全局表现蓝图。

### 2.1 创建（目录 `/Game/Catfishing/Fishing/Actors/`）

| 蓝图 | 父类 | 只读状态里有什么 |
|---|---|---|
| `BP_FishingRod` | `CatFishingRodActor` | ItemInstanceId / bDeployed / OperatorPlayerStates / HolderPlayerState / bBroken / Skin ID |
| `BP_CatFishingHookActor`（`/Game/Blueprint/Actors/`） | `CatFishingHookActor` | Phase: CastFlight / Landed / Failed |
| 原生 `CatFishEncounterActor` | 不创建平行蓝图 | FishDefinitionId / MotionIntent / CurrentLineLength；Mesh/ABP 由鱼种库直连 |

### 2.2 每个里面做什么（共同套路）
1. Components 面板：在 **`VisualRoot`**（Hook 则是它下面的 HookVisualAnchor/BobberVisualAnchor/BaitVisualAnchor）下加 Static/Skeletal Mesh。
2. **每个 Mesh 的 Collision Preset 设为 `NoCollision`**——这是硬性要求：放竿改成 AlwaysSpawn 后，表现碰撞会把猫/竿顶飞或干扰移动。
3. Event Graph 实现对应事件切外观：
   - Rod：`BP_OnRodPresentationChanged` —— Current.OperatorPlayerStates 第 0 项有效→有人操作中的外观；bDeployed→架起；**R 的"架竿/离开"动作动画就播在这里**（比钩子准确）。
   - Rod 竿尖标记：在 VisualRoot 下加一个 Scene/Arrow 组件挪到你 Mesh 的视觉竿尖处，Details→**Component Tags 添加 `RodTipMarker`**——调试青色竿尖球和"竿尖→钩/鱼"的连线会优先跟随它（没有标记时回退权威锚点）。仅表现用途：服务器抛竿原点/线长判定不受它影响。
   - Hook：`BP_OnHookPresentationChanged` —— Phase==CastFlight 隐藏浮漂只留钩、Landed 显示浮漂漂浮、Failed 灰显。
   - Fish：基础 Mesh、Skeleton、AnimBP 和 Calm/Struggle/Exhausted 动画由原生 Actor 沿 `FishDefinition → PresentationDefinition` 应用；`BP_OnFishPresentationChanged` 只留给附加 VFX/SFX，不得按 ID 重选基础资源。
4. **每鱼表现参数**（打开对应 `FishPresentation_*`）：

   | 参数 | 作用 | 怎么调 |
   |---|---|---|
   | `Encounter Mesh Relative Transform` | 水中 Mesh 的轴向、深度、前后左右和基础比例 | **先调旋转**使鱼头对准 Actor +X，再调位置 |
   | `Landed Mesh Relative Transform` | 岸上鱼的局部摆放 | 调整地面高度和朝向，不改拾取 Sphere |
   | `Carried Mesh Relative Transform` | 嘴叼状态的局部对齐 | 与角色 Mouth Socket 联调 |
   | `Exhausted / Landed Actor Roll Degrees` | 水中力竭与岸上侧翻角 | 只调表现，不改抄网/线长判定 |
   | `Mesh Reference Weight / Min / Max Scale` | 本鱼重量到统一视觉比例的映射 | 不在蓝图里再次随机 Scale |

   **调参顺序**：先定 Encounter Transform 的旋转（把鱼头方向掰对），再调前后左右上下，最后分别调 Landed/Carried。

   注意：这些**全部只影响观感**。线长、近岸、抄网半圆等一切判定只用 Actor 的权威位置，与朝向和三个偏移无关。debug 球和鱼线会自动跟随 Mesh 的实际位置（读 `GetVisualWorldLocation`），所以调完能立刻看出对不对齐。
5. **禁止**：Set Actor Transform/Location/Rotation、Tick 模拟位置、从表现事件里调任何 Submit，以及在蓝图中维护 `FishDefinitionId → Mesh/ABP` 映射。

### 2.3 注册到设置
Project Settings → **Catfishing Fishing Presentation** 只注册 Hook/FishEncounter/Chum 等表现类，其中 `FishEncounterActorClass` 保持原生 `/Script/Catfishing.CatFishEncounterActor`。鱼竿 Actor 类从 `Equip_Rod_*` 的 `UseActorClass` 读取，给每个正式鱼竿 DataAsset 填 `BP_FishingRod`；鱼资源只在正式 `Fish_*` 的 `PresentationDefinition` 配置。保存资产并重启 Editor（DeveloperSettings 和 DataAsset 软引用都别靠热加载赌运气）。

### 2.4 验收
PIE 完整走一遍：R 放竿看到竿 Mesh；抛竿看到钩/漂飞出与落水切换；真咬提竿后看到鱼 Mesh 且红球（debug）与鱼 Mesh 同位置；挣扎/顺从时鱼动画切换。位置对不上以 debug 球为准（球=服务器事实）。

## 任务 4：搏斗持续状态动画（AnimBP / 角色层）

**目的**：拖拽循环、松线姿态这类"按住期间一直播"的动作。数据源是 **ViewBridge**（不是 Ability 钩子——钩子只有瞬间）。

在角色 AnimBP（或角色 BP 里定时 0.1s 刷新）：
```
CreateFishingViewBridge(Outer=self)   ← 存成变量，只建一次
FindFishingSessionForPlayerState(自己的 PlayerState) → BindSession
绑定 OnViewStateChangedBP →
    Phase == HookedFight 且 bReeling  → 拖拽循环姿态
    Phase == HookedFight 且 bSlacking → 松开线杯的喘气姿态
    Phase == ExhaustedReel            → 鱼耗尽体力后的持续收线姿态
```
会话是抛竿后才生成的 Actor，所以 **Find 要轮询到非空再 Bind**（比如 0.5s Timer，绑上后停）；会话终结后 ViewBridge 会收到终态一次，之后重新开始轮询下一次会话。

验收：搏斗中按住左键/右键，姿态实时切换，与屏幕 debug 文案 `[拖][松线]` 一致。

## 总验收（全部做完后关 debug 试一次）

控制台 `cat.Fishing.Debug 0`，纯靠你的表现走完整流程：
选中窝料、左键蓄力打窝见圈 → 选中鱼竿拿杆 → 左键抛竿见漂飞落水 → 咬钩提示 → 提竿见鱼 → 左右键搏斗姿态切换 → 鱼进入抄网范围后放杆、选中抄网并左键使用，直接叼嘴（体力不限），或耗尽鱼体力后继续收线并用 E 拾取岸上的鱼。
哪一环看不见了，就说明那一环还依赖 debug——回对应任务补。测完记得 `cat.Fishing.Debug 1` 打开继续开发。

## 常见坑速查

| 症状 | 原因 |
|---|---|
| 新事件在蓝图里搜不到 | 没重启 Editor（反射变更） |
| 换了 BP 类后按键失灵 | BP override 了 ActivateAbility |
| 放竿失败/猫被顶开 | 表现 Mesh 不是 NoCollision |
| Project Settings 改了没生效 | DeveloperSettings 启动才读 ini，重启 |
| PIE 运行中保存资产"成功"但重启丢失 | PIE 中保存被静默拒绝——**停 PIE 再保存** |
| 鱼 Mesh 和 debug 球位置不一致 | 蓝图写了 Actor Transform（禁止），删掉 |
