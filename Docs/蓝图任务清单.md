## 任务 1：六个 Ability 蓝图子类（输入动作 Montage 挂点）

**目的**：把"按键瞬间的动作表现"搬进蓝图，以后换动画不碰 C++。

### 1.1 创建
Content Browser → `/Game/Catfishing/Abilities/`（建议新建此目录）→ 右键 → Blueprint Class → All Classes 搜父类：

| 蓝图资产 | 父类（搜索名） | 键位 |
|---|---|---|
| `BP_GA_RodInteract` | `CatGA_FishingRodInteract` | R |
| `BP_GA_Primary` | `CatGA_FishingPrimaryAction` | 左键 |
| `BP_GA_Slack` | `CatGA_FishingSlack` | 右键 |
| `BP_GA_Chum` | `CatGA_FishingChum` | Q |
| `BP_GA_Scoop` | `CatGA_FishingScoop` | F |
| `BP_GA_Cancel` | `CatGA_FishingCancel` | X |

### 1.2 每个蓝图里做什么

**先搞清生命周期（谁来开始/结束 Ability）——全部由 C++ 自动管理，蓝图一律不用管**：

| 类型 | 键位 | 生命周期（C++ 已写死） | 蓝图能挂的事件 |
|---|---|---|---|
| **一次性** | R（RodInteract）、F（Scoop）、X（Cancel） | 按下瞬间：激活 → 调 `BP_OnLocalInputActivated` → 提交命令 → **同帧自动 EndAbility**（提交失败则自动 CancelAbility）。Ability 只存活约 1 帧 | 只有 `BP_OnLocalInputActivated` |
| **按住型** | 左键（Primary）、右键（Slack）、Q（Chum） | 按下：激活 → 调 `BP_OnLocalInputActivated` → **保持存活等松开**；松开：调 `BP_OnLocalInputReleased` → 提交松开边沿 → **自动 EndAbility**。按下时若命令提交失败会立即 CancelAbility（此时**不会**再调 Released） | `BP_OnLocalInputActivated` + `BP_OnLocalInputReleased` |

所以蓝图里的操作就是：Event Graph 右键 → 搜 `BP_OnLocalInputActivated` 添加事件（按住型三个再加 `BP_OnLocalInputReleased`）：

```
Event BP_OnLocalInputActivated
 → Get Avatar Actor from Actor Info → Cast to Character
 → Play Anim Montage（现在没动画就先 Print String 占位）
```

**四条规矩**：
1. **不要 override `ActivateAbility` / `InputReleased`**（会断命令链——蓝图漏调 Parent 时按键直接失灵）。只实现上面两个事件。
2. **不要调 `EndAbility` / `CancelAbility` / `CommitAbility`**——收尾时机 C++ 已按上表自动处理，蓝图再调一次会提前掐断按住型的松开检测（右键线杯会无法重新锁住）。
3. 钩子在**提交前**触发、不带结果——只放"成败都要播"的动作（挥网、甩杆、提竿抬手）。结果动画（完美中鱼/断线/上鱼）不在这里，见任务 4/5。
   **但"不带结果"≠"不能判断阶段"**——这两个是不同的东西：
   - **结果**（这次提竿中没中）：要等服务器回包，一个 RTT，钩子里等不了，也不该等；
   - **阶段**（我现在是在瞄准还是在搏斗）：**已经复制到本地的事实**，读它零延迟，该读就读。

   左键（Primary）尤其需要分支——同一个键按下在服务器上有**三种语义**（`CatFishingCommandComponent.cpp:446/544/548`）：无会话=举竿瞄准、有会话非搏斗=提竿、搏斗中=开始收线。不分支就是三种动作播同一个动画。本地这样读阶段：

   ```
   Event BP_OnLocalInputActivated
    → Get Avatar Actor from Actor Info → Cast to Pawn → Get Player State
    → Find Fishing Session for Player State    （UCatFishingViewBridge 的静态函数，BlueprintCallable）
    → Is Valid ?
        ├─ 否 → 【举竿瞄准】
        └─ 是 → Get Replicated Snapshot → Break → Phase → Switch on ECatFishingPhase
                   ├─ Hooked Fight → 【收线起手】
                   └─ 其他          → 【提竿】
   ```
4. R 键（RodInteract）建议先留空或播通用鱼竿交互动作：它是一键三态（现在还有多人接管别人竿），具体是"架竿"还是"离开"只有服务器知道，那类动作等任务 2 的 Rod 事件再播。E 已专用于准星拾取，不进入该 Ability。
5. **这两个钩子只有本人看得到**（服务器镜像在 `IsRemoteAuthorityMirror` 处直接 return）。要让其他玩家也看到，见下面 1.5。

### 1.5 让其他玩家也看到你的动作（多人必做）

Montage **本身不复制**（`Play Montage` / `Play Anim Montage` 都是纯本地 `Montage_Play`）。让所有人看到的正确做法不是"同步动画"，而是"每台机器各自本地播一次"——靠的是**权威状态复制到每个客户端后各自触发表现事件**。

按动作分两类，**不要重复接，否则同一动作会播两遍**：

| 动作 | 别人怎么看到 | 你要接哪里 |
|---|---|---|
| 放竿 / 上竿位 / 离开 / 收竿 | Rod 的 `PresentationState` 复制 → 每个客户端各自触发 | 任务 2 的 `BP_OnRodPresentationChanged`（**已天然全同步，不用额外做事**） |
| 断线 | Session 的 `Outcome=LineBroken` 复制 → 每个客户端各自触发 | ViewBridge 的 `OnViewStateChangedBP`；只隐藏线/播断线表现，不修改 Rod |
| 抛竿 / 打窝 | Hook Actor 生成、ChumField 复制 | 各自的表现事件 |
| **挥网（F）/ 提竿（左键按下）** | ❌ 失败时**不产生任何权威状态变化**，没有可读的复制事实 | **`BP_PlayCosmeticEvent`**（见下） |

最后一行是唯一的缺口：挥网落空、提竿空竿在服务器上什么都没改变，但派对游戏里朋友挥空网恰恰是最好笑的部分。为此在 `ACatCharacter` 上开了一条多播通道：

```
（在 BP_CatCharacter 的 Event Graph 里，不是 Ability 蓝图）
Event BP_PlayCosmeticEvent (EventTag)
 → Switch on Gameplay Tag
     ├─ Cat.Cosmetic.Fishing.ScoopSwing → Get Mesh → Play Montage（挥网）
     └─ Cat.Cosmetic.Fishing.HookPull   → Get Mesh → Play Montage（提竿抬手）
```

- **本地控制端收不到这个事件**（C++ 里直接跳过了）——因为发起者已经在 Ability 钩子里零延迟播过同一个动作，再播一次会从头打断自己的 Montage，视觉上是"抽搐"。所以同一个动作你要在**两处各接一次**：Ability 钩子（自己看）+ 这里（别人看）。两边可以用同一个 Montage 资产。
- 权威侧在**裁决之前**广播，和本地"按下就播"的时机口径一致；成败由后续状态变化各自呈现。
- Unreliable：丢包只是少看一次挥网，不影响任何玩法事实。

**⚠️ 播动画只能用这两个节点，千万别用 `Play Montage and Wait`**：

| 节点 | 绑 Ability 生命周期？ | 有回调引脚？ | 能不能用 |
|---|---|---|---|
| **`Play Montage`**（推荐） | **否**（底层 `UPlayMontageCallbackProxy`） | 有（OnCompleted / OnBlendOut / OnInterrupted / OnNotifyBegin / OnNotifyEnd） | ✅ 首选 |
| `Play Anim Montage` | 否（Character 的同步函数） | 无（只返回时长） | ✅ 不需要回调时够用 |
| ~~`Play Montage and Wait`~~ | **是**（GAS AbilityTask） | 有 | ❌ **禁用** |

原因：`Play Montage and Wait` 是 AbilityTask，Ability 一结束引擎就销毁它，而它 `OnDestroy` 里默认 `bStopWhenAbilityEnds=true` → 直接 `StopPlayingMontage()`。一次性技能（E/F/X）在 `BP_OnLocalInputActivated` 返回后**同帧**就 EndAbility，所以动画播了不到一帧就被掐断，看起来"完全没播"。把 `bStopWhenAbilityEnds` 勾掉也只解决一半——引擎注释明写 *"It is always stopped when the ability is explicitly cancelled"*，而命令提交失败时 C++ 会 CancelAbility，那条路径照样掐。按住型（左键/右键/Q）用它会"看起来能播"，但松手 EndAbility 时同样被掐。

**动画时长与 Ability 时长无关**：用上面两个正确节点时，一次性技能同帧 EndAbility **不会**掐断动画，Montage 自己播完即可。反过来，按住型如果 Activated 里播的是循环动画（蓄力循环），要在 `BP_OnLocalInputReleased` 里自己 `Stop Anim Montage`；另外别把"必须收尾"的逻辑只放在 Released 里（按下即失败被取消时它不触发）。

**⚠️ `Play Montage` 的 `In Skeletal Mesh Component` 引脚必须接**：从 Cast 节点的 `As Character` 拖出 → `Get Mesh` → 接上去。**留空时该节点什么都不做且不报任何错**（引擎源码是 `if (InSkeletalMeshComponent){...}`，为空直接跳过并广播 `OnInterrupted`），表现就是"动画完全不播但没有任何提示"。嫌麻烦就用 `Play Anim Montage`（Character 函数，Target 接 `As Character` 即可，内部自取 Mesh，没这个坑）。

**`then` 引脚 ≠ 动画播完**：`then` 在发起播放的那一帧就同步触发，所以接在 `then` 上的 Print String 一定立刻输出——**这不能用来判断动画有没有播**。要等播完请接 `On Completed`。

**动画不显示的排查顺序**（逐层证伪，别一上来就怀疑 Slot）：
1. Montage 资产：骨架是否 = 角色骨架、SlotName 是否 = ABP 里 Slot 节点的名字、有没有实际动画段
2. 角色 Mesh 组件：SkeletalMesh / AnimClass 有没有配、AnimationMode 是不是 `Use Animation Blueprint`、Visible
3. ABP 的 AnimGraph：Slot 节点不仅要**存在**，还必须真的接在**最终输出姿势链路上**（`… → Slot(Source)`、`Slot(Pose) → Output Pose`），而不是挂在旁边没接
4. 调用方节点的**对象引脚**（Mesh / Target）是不是空的 ← **实际最常中招的一层**

## 任务 2：三个表现 Actor 蓝图（Rod / Hook / Fish）

**目的**：给场景里的竿、钩（浮漂）、鱼挂上真实 Mesh。权威边界详见《FishingActorBlueprintHooks_zh-CN.md》，这里只列操作。

### 2.1 创建（目录 `/Game/Catfishing/Fishing/Actors/`）

| 蓝图 | 父类 | 只读状态里有什么 |
|---|---|---|
| `BP_FishingRod` | `CatFishingRodActor` | ItemInstanceId / bDeployed / OperatorPlayerState / bBroken / Skin ID |
| `BP_FishingHook` | `CatFishingHookActor` | Phase: CastFlight / Landed / Failed |
| `BP_FishEncounter` | `CatFishEncounterActor` | FishDefinitionId / MotionIntent / CurrentLineLength |

### 2.2 每个里面做什么（共同套路）
1. Components 面板：在 **`VisualRoot`**（Hook 则是它下面的 HookVisualAnchor/BobberVisualAnchor/BaitVisualAnchor）下加 Static/Skeletal Mesh。
2. **每个 Mesh 的 Collision Preset 设为 `NoCollision`**——这是硬性要求：放竿改成 AlwaysSpawn 后，表现碰撞会把猫/竿顶飞或干扰移动。
3. Event Graph 实现对应事件切外观：
   - Rod：`BP_OnRodPresentationChanged` —— Current.OperatorPlayerState 有效→有人操作中的外观；bDeployed→架起；**R 的"架竿/离开"动作动画就播在这里**（比钩子准确）。
   - Rod 竿尖标记：在 VisualRoot 下加一个 Scene/Arrow 组件挪到你 Mesh 的视觉竿尖处，Details→**Component Tags 添加 `RodTipMarker`**——调试青色竿尖球和"竿尖→钩/鱼"的连线会优先跟随它（没有标记时回退权威锚点）。仅表现用途：服务器抛竿原点/线长判定不受它影响。
   - Hook：`BP_OnHookPresentationChanged` —— Phase==CastFlight 隐藏浮漂只留钩、Landed 显示浮漂漂浮、Failed 灰显。
   - Fish：`BP_OnFishPresentationChanged` —— 按 FishDefinitionId 选 Mesh；MotionIntent（StruggleOutward=猛甩尾 / SwimInward=平游）切局部动画。
4. **Fish 蓝图的表现参数**（Details 面板 → `Fishing|Presentation` 分类；改完下一条上钩的鱼即生效，不用重启 Editor）：

   | 参数 | 作用 | 怎么调 |
   |---|---|---|
   | `Visual Yaw Offset Degrees` | **Mesh 前向轴修正**（默认 0）。Actor 朝向已经等于鱼真实的游动方向，但美术资源的前向不一定是 +X | **先调这个**：让鱼游起来看，侧着走填 ±90，倒着走填 180 |
   | `Visual Depth Centimeters` | 沉到水面以下多少厘米 | 鱼浮在水面上就调大；0 = 不下沉 |
   | `Visual Forward Offset Centimeters` | **前后**微调：正=往前（鱼头方向），负=往后 | 让钩子看起来咬在嘴上而不是穿在身体中段 |
   | `Visual Right Offset Centimeters` | **左右**微调：正=鱼的右侧，负=左侧 | 修模型轴心不在中线的情况 |
   | `Maximum Turn Rate Degrees Per Second` | 转向速率上限（默认 180），防止挣扎↔收线切换时朝向瞬移 | 想让鱼调头更灵活就调大，更笨重就调小 |

   **调参顺序**：先定 `Yaw Offset`（把鱼头方向掰对），再调前后左右上下——因为"前/右"是 Actor 本地轴，等 Yaw 修正完之后才和你眼睛看到的鱼头方向一致。

   注意：这些**全部只影响观感**。线长、近岸、抄网半圆等一切判定只用 Actor 的权威位置，与朝向和三个偏移无关。debug 球和鱼线会自动跟随 Mesh 的实际位置（读 `GetVisualWorldLocation`），所以调完能立刻看出对不对齐。
5. **禁止**：Set Actor Transform/Location/Rotation、Tick 模拟位置、从表现事件里调任何 Submit——位置和朝向全部由服务器复制，蓝图只做 VisualRoot 局部动画。

### 2.3 注册到设置
Project Settings → **Catfishing Fishing Presentation** 只注册 Hook/Fish/Chum 等表现类；鱼竿 Actor 类现在从 `Equip_Rod_*` 的 `UseActorClass` 读取。给每个正式鱼竿 DataAsset 填 `BP_FishingRod` 后保存资产并重启 Editor（DeveloperSettings 和 DataAsset 软引用都别靠热加载赌运气）。

### 2.4 验收

## 任务 4：搏斗持续状态动画（AnimBP / 角色层）

**目的**：拖拽循环、松线姿态这类"按住期间一直播"的动作。数据源是 **ViewBridge**（不是 Ability 钩子——钩子只有瞬间）。

在角色 AnimBP（或角色 BP 里定时 0.1s 刷新）：
```
CreateFishingViewBridge(Outer=self)   ← 存成变量，只建一次
FindFishingSessionForPlayerState(自己的 PlayerState) → BindSession
绑定 OnViewStateChangedBP →
    Phase == HookedFight 且 bReeling  → 拖拽循环姿态
    Phase == HookedFight 且 bSlacking → 松开线杯的喘气姿态
    Phase == ExhaustedReel            → 鱼耗尽体力后的持续收线姿态
```
会话是抛竿后才生成的 Actor，所以 **Find 要轮询到非空再 Bind**（比如 0.5s Timer，绑上后停）；会话终结后 ViewBridge 会收到终态一次，之后重新开始轮询下一次会话。

验收：搏斗中按住左键/右键，姿态实时切换，与屏幕 debug 文案 `[拖][松线]` 一致。

## 总验收（全部做完后关 debug 试一次）

控制台 `cat.Fishing.Debug 0`，纯靠你的表现走完整流程：
Q 蓄力打窝见圈 → R 架竿见竿 → 左键抛竿见漂飞落水 → 咬钩提示 → 提竿见鱼 → 左右键搏斗姿态切换 → 鱼进入抄网范围后 F 直接叼嘴（体力不限），或耗尽鱼体力后继续收线并用 E 拾取岸上的鱼。
哪一环看不见了，就说明那一环还依赖 debug——回对应任务补。测完记得 `cat.Fishing.Debug 1` 打开继续开发。

## 常见坑速查

| 症状 | 原因 |
|---|---|
| 新事件在蓝图里搜不到 | 没重启 Editor（反射变更） |
| 换了 BP 类后按键失灵 | BP override 了 ActivateAbility |
| 放竿失败/猫被顶开 | 表现 Mesh 不是 NoCollision |
| Project Settings 改了没生效 | DeveloperSettings 启动才读 ini，重启 |
| PIE 运行中保存资产"成功"但重启丢失 | PIE 中保存被静默拒绝——**停 PIE 再保存** |
| 鱼 Mesh 和 debug 球位置不一致 | 蓝图写了 Actor Transform（禁止），删掉 |
