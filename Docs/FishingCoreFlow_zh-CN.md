# 钓鱼核心流程（实现对照基准）

依据：`Knowledge/Design/GDD 系统分册/钓鱼系统/钓鱼规则.md`（实现规格书；本文按 2026-08-18 那版写，之后试探期选鱼、竿强瞬断、恢复闸退役、苏醒逃跑已实现等未回写，逐条见 `Docs/Development/2026-09-15-文档盘点与处置.md`）。2026-09-16 已删除力量碾压，收鱼由实际物理拖岸或抄网触发。范围只含钓鱼；渔获去向/供奉不在本文。
所引规格书提供设计背景；当前运动实现以 [鱼运动与遛鱼逻辑实现导读](FishFightImplementationGuide_zh-CN.md) 及其源码入口为准。页内数字为快照，运行参数读取当前会话实际引用的资产。待实现方向与现行行为必须分开阅读。

## 0. 总览

```
[准备] 带饵/窝料/竿(/网/护) 走到任意水边
   ├─ 选中窝料，左键蓄力抛窝料 → [窝料场] 三轴贡献按距离、时间衰减后在落点叠加   （可选、可重复）
   └─ 左键点水面 → [抛竿] 射程/精准校验，采样冻结的落水点
                      ↓
                   [等待/试探] 等待结束抽定鱼种和重量，试探期无实体鱼      ← 咬钩前可收竿，零损失
                      ↓
                   [真咬] 正式逐鱼 8～15s 响应窗；有效提竿才生成实体鱼
                      ├─ 超窗 → 鱼跑
                      └─ 提竿 → [遛鱼] 左键收 / 右键松开线杯 / 不动；鱼 向外游⇄向内游
                                  ├─ 主动切线 → 鱼逃（保留既有磨损，可开始新会话）
                                  ├─ 猫脚点持续进入危险水深 → 落水失败
                                  ├─ 鱼体力归零，或被绷紧鱼线拖过岸线 → 翻肚成鱼干，同一约束系统零猫体力消耗地继续收近
                                  └─ 鱼进入抄网射线范围（体力不限）→ 可抄
                                        ↓
                                  [收鱼] 选中抄网，左键抄（范围合法即直接叼嘴）/ 翻肚收至竿尖表面投影后 E 拾取
```

## 1. 打窝
- 当前操作：快捷栏选中窝料，左键按住蓄力、松开投出。统一 Use 固定启动实例，`UCatGA_FishingChum` 等待释放后交给服务器裁决，只扣该实例的数量；取消不消耗，菜单 Use 为即时使用。旧 Q 打窝入口已删除，Q 用于丢嘴叼物。
- 当前窝料 = `{腥X, 香P, 酵J}` 三维向量；`UCatChumFieldSubsystem::SampleChumAtPoint` 将同一水域、覆盖落点且未过期的各场贡献乘距离/时间衰减后相加。它没有增加真实鱼数或维护水域鱼种库存。
- 2026-09-07 将 `InfluenceAreaMultiplier` 从 2 改为 8：相对于此前直径再翻倍、面积变为此前四倍。四种正式窝料基础半径均为 300 cm，实际半径约 848.53 cm、直径约 16.97 m。`PrepareField` 缩放一次，采样和客户端圆环使用同一最终半径。
- 四种正式 `Equip_Chum_*` 的 `ChumInfluence.DurationSeconds` 从 60 s 改为 180 s；时间衰减曲线形状不变，按新时长归一化。自然事件共用正式 BugChum，因此同样扩大、延长。到期立即不再贡献，圆环由默认 5 s 周期清理并复制移除。
- 正式红虫、发酵谷物、果香、圣光窝料当前都使用 `(1, 0.5, 0.2)`，所以同数量、同距离、同年龄下换类型不会改变提速或选鱼概率。不能依据名称认定其已有不同鱼种偏好。
- 2026-09-16 用户确认以浓度场为正式方向，不维护鱼库存、不按抽鱼扣浓度，不再要求水域面积单元守恒重分配。`Docs/Architecture/项目技术方案.md` §7.1.1 已标为历史方案。
- 对照实验与现有日志使用方法见 [操作指南：窝料效果测试](FishingMVPOperationGuide_zh-CN.md#窝料效果测试2026-09-07)。
- 2026-09-17 聚鱼：成功玩家投料首次发布后，在投料落点检查三类有效浓度分别达到 6／3／1.2（试玩配置），每次合格投料抽一次 8%。事件沿用新场范围，45 秒内等待速度 ×2.5；活动区域相交不重复、不续时，结束无冷却。`ACatFishGatheringActor` 复制独立事件并提供原生亮环／鱼影；`SampleChumAtPoint` 单独返回倍率，不改变浓度、鱼种权重或窝料寿命。自然投料不触发，翻天／终局清理事件。正式表现和打包验收不由原生占位代替。

## 2. 抛竿
- 左键点水面，无蓄力（有预览不蓄力）；无饵不能抛
- 射程：D_click ≤ 浮漂射程，否则"够不到那边"
- 精准：落点 = 点击点 + 随机偏移（半径由浮漂精准度定；3 种浮漂）
- 窝料查询：当前直接采样冻结的水面落点，叠加所有覆盖该点的有效窝料；无面积单元库存
- 咬钩前任意时刻可收竿，收回饵，零损失

## 3. 等待 → 咬钩
- `ACatFishingSession::ScheduleWaitingProbeFromStateTree` 建立每漂独立进度。无窝120秒，有窝 `15/(1+A/K)` 秒，A为冻结落点三轴有效浓度，K暂定17/3；单份中心约11.54秒、五份6秒。角色间隔成长仍生效；旧随机均值、3秒慢浮下限、40秒封顶及饵的等待倍率不再参与。
- 飞行不消耗等待进度；服务器每0.1秒采样曲线，投放和移除即时刷新。按旧间隔结算已等待部分后，剩余按新旧间隔比例换算，补窝不会重开一轮。最后至多1.5秒预警，高浓度允许缩短，预警不增加等待。
- 试探时重新采样浓度，按三轴占比选类别，再按正式鱼表的饵权重选鱼；无有效窝或候选时使用正式基础池。基础池饵权重及窝料目标鱼种倍率仍待接入。本次不改变抽鱼和真咬扣饵入口。
- 等待结束进入逐鱼试探，正式响应窗和基础完美窗继续使用既有配置；有效提竿才生成实体鱼。
- 入夜后不再咬钩；进行中搏斗允许打完

## 4. 真咬 → 提竿
正式16鱼读取逐鱼8～15秒响应时间，基础完美窗为1秒并叠加成长；选鱼在试探开始时完成，实体鱼在有效提钩时才生成。2026-09-14已接入真咬扣当前饵1份、超时 `HookWindowExpired` 终局和所有结果不返饵；D₀在真咬冻结，超出竿Lmax直接逃走，响应窗移动不重算。细节与验证见 `FishingArchitecture_zh-CN.md` 顶部。

- 响应窗按鱼种 8~15s
- 完美提竿：咬钩后 1s 内（服务器时间戳）→ 普通鱼 力量×0.80/体力×0.85；稀有鱼 ×0.85/×0.90
- 普通提竿：1s 后至窗口结束前 → 正常遛鱼
- 超时：真咬响应窗到期仍未提竿，结束本次钓鱼并触发掉竿；手持竿短抛落地，架设竿不抛起、直接倾倒，随后朝鱼的方向沿地面限速拖动。停止后保持实际倒地姿态，必须重新对准按 E 拿起；拖动中也可拿回，鱼不会因此重新进入搏斗。等待/试探期提前提竿、入夜自动收回不触发此惩罚。
- 饵：进入咬钩后无论结局（上鱼/超时/放弃/切线/断竿/落水）扣 1 份，上鱼也扣

超时掉竿由 `ACatFishingSession::FinalizeSession(HookWindowExpired)` 单次裁决，`UCatFishingPhysicalRodComponent` 接管短暂的物理运动和 Hook 鱼线表现；Session 的扣饵、终局和销毁时点不延长。原鱼竿质量保持 0.35 kg；速度驱动按 cm/s 和 cm/s² 控制，避免轻竿因鱼力加速失控。`Config/DefaultGame.ini` 的 `CatFishingSettings` 节配置手持初速度水平 120、向上 100，地面拖速上限 33、加速度 66、拖动时间 2.5 秒、累计水平路径上限 220 cm。停止或 E 成功拾取销毁临时 Hook；水域边界、前方缺少地面时回退到最近可达支撑。拾取仍复用原实例入栏事务，失败保持掉落状态；普通 Operate/快捷栏回退及收包不能绕过目标 E。

诊断过滤词：`fishing_rod_escape_started`、`fishing_rod_escape_grounded`、`fishing_rod_escape_stopped`、`fishing_rod_escape_received`、`fishing_rod_escape_pickup_rejected`、`fishing_rod_interaction_*`，日志分类 `LogCatFishing`，以 `SessionId` 和 `RodActorId` 串联。正式 Development 包日志位置仍为 `<打包根目录>/Catfishing/Saved/Logs`，不要求 `-log` 窗口。

## 5. 遛鱼

当前角色和鱼竿改由真实刚体、身体支撑与持续抓握约束驱动；合作通过抓竿或抓队友传力，只有主控进入会话。鱼端保留连续出力、固定正常水阻、持久鱼速度与共同鱼线张力，仍按水面固定步求解。完整公式、配置来源、接入验证边界和诊断事件见 [实现导读](FishFightImplementationGuide_zh-CN.md)。

- 正常搏斗由鱼树在外冲/横切/缓游三行为间按受阻、局部时长与整轮对抗时限转移；横切维持较强斜向出力，受阻或到期可重新外冲。连续外冲/横切共用整轮计时，达到上限后优先缓游；低体力缩短入态时限，不立即截断刚开始的外冲。Runner 固定步推进反馈和树，Steering 连续控制主动游向与出力u。推力、惯性和固定水阻先求自由运动，再由同一鱼线约束解析实际运动。主控体力归零且仍持竿时，暂停普通树及整轮计时，覆盖为满力远离猫外冲。正式资产、运行回归与真人/打包验收边界以实现导读中的本轮证据为准。
- 不按键锁线，左键缩短已放线长，右键在线杯有余量时允许被动出线并优先于左键，按配置速度回体至上限、鱼和猫均不扣体；没有实际出线本身不阻止主控回体；但身体受任何抓握/推挤负载、待施加冲量或杆上线力时不回体，两侧抵消也算受力，零体力强制拖拽仍优先。已放线长度达到上限后右键失效，停止回体和该项免耗，恢复仍按住的左键，否则锁线；鱼向外发力且绷线时走同一角力与个人账本，不额外增加一笔满线费用或磨损。到达上限当步即不回体；鱼游近形成余线仍不回体，实际收短到上限以下才重新允许持续右键放线回体。满线判据使用已放线长度，不使用鱼与竿尖距离；右键首按重设转向意图的入口保留。后退移动猫/竿端点。实际收线使用同一线约束求取有限出力能完成的缩短量，负载超出能力时停转，不按请求量预支收线。
- 最终鱼线张力只在真实竿尖施加一次，经抓握约束传到身体；CMC不再积分身体位移，旧杆模型不再写姿态。求解器读取实际竿端点与速度，不重复预支运动或费用。
- 僵持与强对抗标记只供观察和表现，力量差由双端约束处理；不再以力量超过承载阈值直接结束搏斗。耐久只使用绑定鱼竿装备实例的 `RodDurability`，按固定步累计写回，归零产生 `RodBroken`；会话快照只是该值的镜像，重新抛竿、切线、换人或收杆都不恢复磨损。
- 有效右键放线以外（包括已放线达到上限），猫的身体移动按方向意图缺失米价独立结算，收线按实际完成距离、转杆按主动转矩加权的真实转角计正功费用，受阻支撑按用力比例平方和持续时间计费；共享沿线支撑与转杆支撑取较高者，收线、转杆与去重后的持竿支撑费用生成一次，只由主控本人支付，辅助不注册会话而独立支付自身推拉/站稳费用，正功费用不抵扣支撑，也不再叠加鱼阶段耗体倍率。鱼使用独立每米价格×沿主动意图未完成的米数，意图为实际出力u×参考游速×dt，实际进展取最终位移扣除历史纠偏后的主动方向投影；反向拖动增加缺失，同向超额或完整前进同时侧移不增加费用，不再按鱼线夹角和张力门控；达到意图速度的自由游动与零出力不扣此费，起步或转弯的缺失可能收费；主控耗尽触发强制外冲后，鱼不会自行游到力竭；旁人仍能靠真实物理约束抵抗。
- 鱼耗体系数可关闭对抗费用；零耗体步骤不触发低体力尾数归零。实际对抗耗尽或被猫端牵引上岸后，鱼停止主动运动，并关闭猫端正向扣费，继续拖到干地竿尖附近交接 Pickup。上岸清空体力与力竭后零猫消耗仍是玩法特例。
- 主控有正体力时保持ASC原力量，归零停止主动出力，恢复正体力后恢复力量；零体力保留主控权限。辅助推拉与站稳共用本人力量上限，体力归零主动地面力量为零并放开自己的抓握；仍可被拖动。松方向键在负载下主动站稳并耗体，完全卸载后等待 2 秒，以 5 点/秒恢复，重新受力重置等待，恢复到上限 20% 才恢复辅助出力。抓竿不成为会话成员、不贡献虚拟辅助系数、不转移体力。具体方向公式与单位见 `FishFightImplementationGuide_zh-CN.md` 顶部。危险落水由Condition确认，主控退出后不自动接任。

- 危险落水阈值为脚点低于水面 35 cm 并持续 0.2 秒；已进入危险状态后，回到 25 cm 或更浅才退出，保留缓冲区避免水面抖动反复切换。
- 力竭外冲默认使用鱼满出力参考游速的 2 倍，倍率由正式搏斗平衡资产配置。拖拽期间锁线、不放线回体，猫承担沿线位移；通过现有角色移动与碰撞进入水域，不瞬移。暂停新增竿磨损和距离逃脱，危险落水后保留现有湿身/落水表现；主控离竿转无人值守，旁人不自动补位。主控恢复正体力、离竿或鱼已力竭时退出强制外冲；原按键状态和行为树意图继续有效。岸线反馈仍可让鱼避开陆地。

## 6. 收鱼
- 抄网通过快捷栏选中实例的统一 Use 发起，服务器复核具体实例、数量和定义。有效长度只读取全局 `ScoopReachCentimeters`；调试范围同样读取当前选中的网，不再依赖旧 Equipment 快照。获取来源归库存/商店，不由抄鱼动作补发。
- 可抄：鱼已上钩且进入“水平抄网线段 ∩ 鱼目标圆”范围；活鱼/翻肚均可，鱼的剩余体力不参与判定
- 选中抄网后左键使用 → 视线、目标、站位、范围及物品身份校验 → 帧末捕获裁决 → 直接叼嘴。统一库存 Use 等待该次请求的最终回执；挥空保留原 3s 冷却，成功清除挥空冷却。持杆时先 R 放杆，再选中抄网。
- 无网：鱼体力耗尽或被拖上岸后翻肚 → 水内贴水面、岸上逐步贴地拖至竿尖附近 → E 拾取，必中，先到先得
- 翻肚后的苏醒逃跑已实现，等待时间读取 `ExhaustedFishRevivalSeconds`（默认 30s）。同帧捕获在苏醒与落水裁决之前处理。
- 多人：沿用服务器帧末队列的稳定裁决顺序，只有一人取得同一条嘴叼世界鱼；失败者仍按原失败分支处理冷却，不能靠重复 RequestId 再执行捕获。
- 两轨记录：渔获归抄/拾者；图鉴首钓与个人纪录归上钩钓手
