## 2. 显示策略与生命周期

`UCatWorldInfoComponent` 是可附着的 `USceneComponent`，不是交互接口。它的世界位置仍作为遮挡采样锚点，默认相对位置为 `(0, 0, 120)` 厘米；不再决定面板的屏幕位置。保留场景组件及变换，以维持既有 Blueprint 附着和遮挡配置。

| `DisplayPolicy` | 可读距离内未被准星命中 | 被准星命中 |
| --- | --- | --- |
| `NearbyFull` | 完整信息 `Full` | 完整信息 `Full` |
| `NearbySummary` | 摘要 `Summary` | 完整信息 `Full` |
| `FocusOnly`（默认） | 隐藏 `Hidden` | 完整信息 `Full` |

当前正式祭坛和鱼缸只采用默认 `FocusOnly`。另外两项保留为已公开的 Blueprint 可选策略，不再作为本项目这两个对象的默认行为；切换成它们会显式改变本节的准心显示约定。每名玩家单独读取自己的准心和距离，一个玩家看见信息不代表另一个玩家也看见。

父类 `EvaluateDisplay` 先检查 `bInfoEnabled`、有效 Viewer 和有限距离；超过 `DisplayDistanceCentimeters` 就隐藏，等于阈值仍可显示。默认可读距离为 500 厘米、`DisplayPriority=0`、`bHideWhenOccluded=true`、`bInfoEnabled=true`。距离是 **Pawn 身体原点到对象 Actor 原点**，不是相机到锚点，也不改变交互距离。

生命周期与数据流如下：

1. 组件 `BeginPlay` 调用父类后注册到本世界 `UCatWorldInfoRegistry`；注册表去重并保存弱引用，不持有业务状态。
2. 现有 `UCatLocalPlayerUISubsystem::AttachPlayerLakeUI` 在局内 UI 装配成功后创建、绑定 `UCatWorldInfoController`。这是本地玩家链路；任意测试地图若缺少正常玩家/UI 宿主，单放 Actor 不保证有展示。
3. 控制器每 0.2 秒刷新注册候选、距离、焦点、显示层级和遮挡；每帧按玩家屏幕尺寸在固定列放置可见信息牌，不随相机转动重新投影。只有内容序号变化或显示层级切换等失效情形才重读 `BuildInfo`。
4. 组件 `EndPlay` 注销；控制器后续候选刷新移除失效对象的 WBP。玩家 UI 解绑时立即移除全部信息牌并清除观察距离预算。派生组件覆盖入场/退出时必须调用 `Super`，自己的事件订阅也要成对解除。

## 3. 接入一个普通或非交互 Actor

### Blueprint 静态信息

1. 打开目标 Actor Blueprint，在 Components 添加 `CatWorldInfoComponent`，附着到对象的场景根或需要跟随的组件；在视口调整遮挡采样锚点高度，这不会移动屏幕面板。普通静态说明无需新建组件子类。
2. 选中组件，在 `World Info` 分类设置策略、厘米距离、优先级和遮挡开关。填写 `StaticInfo.Title`、可选 `Status` 和 `Rows`；默认 `BuildInfo` 遇到空标题返回 false，信息牌会隐藏。
3. `WidgetClass` 选择正式 `WBP_CatWorldInfo` 或自己的兼容 WBP。默认软类为 `/Game/UI/WorldInfo/WBP_CatWorldInfo.WBP_CatWorldInfo_C`。这是逐组件配置，不需要修改公共控制器的类型分支。
4. 编译、保存 Blueprint 后放入正常玩法关卡。需要聚焦展开时，让该 Actor 自己的可命中组件阻挡 `CatInteractionSettings.TargetingTraceChannel`（默认 `Visibility`）。焦点以命中的 Actor 和组件 Owner 相等为准，命中 Child Actor 不会自动归属父 Actor。

非交互 Actor 不需要实现 `ICatInteractable`，也不需要伪造 `CanInteract=true`。默认 `FocusOnly` 必须能够被现有观察射线命中；只有显式改为可选 `NearbyFull` 才会在没有准星命中时展示。关闭鱼缸等对象的交互开关，也不会自动关闭其信息组件。

### C++ 装配与覆盖

包含 `UI/WorldInfo/CatWorldInfoComponent.h`，在 Actor 中用带 `UPROPERTY` 的组件成员保存锚点，并在构造函数中创建、附着。以下是已有根组件的 Actor 构造片段，成员 `WorldInfo` 需由所属 Actor 声明：

```cpp
// 只读说明锚点跟随对象根；生命周期注册由组件父类完成。
WorldInfo = CreateDefaultSubobject<UCatWorldInfoComponent>(TEXT("WorldInfo"));
WorldInfo->SetupAttachment(GetRootComponent());
WorldInfo->DisplayPolicy = ECatWorldInfoPolicy::FocusOnly;
WorldInfo->StaticInfo.Title = NSLOCTEXT("WorldInfoExample", "Title", "营地告示");
```

动态信息可派生 `UCatWorldInfoComponent`。C++ 覆盖以下 `_Implementation`，调用方仍调用 `EvaluateDisplay` / `BuildInfo` 事件入口，才能保留 Blueprint 覆盖：

```cpp
// 声明：结合观察条件和对象状态返回隐藏、摘要或详情，不授予交互权限。
virtual ECatWorldInfoDetail EvaluateDisplay_Implementation(
    APlayerController* Viewer, bool bFocused, double DistanceCentimeters) const override;
// 声明：读取已有业务事实并输出新的显示快照；false 表示本次不能展示。
virtual bool BuildInfo_Implementation(
    APlayerController* Viewer, ECatWorldInfoDetail Detail,
    FCatWorldInfoViewData& OutData) const override;
```

`EvaluateDisplay_Implementation` 通常先调用 `Super::EvaluateDisplay_Implementation`，保留距离/开关保护，再按领域状态收紧显示层级。完全替换父类时应自行处理这些条件；控制器仍独立检查 Pawn、Owner 隐藏和组件总开关。`BuildInfo_Implementation` 先将 `OutData` 重置为 `FCatWorldInfoViewData()`，再读现有状态生成标题、状态和行，成功返回 true。不要在这些入口扣库存、发送交互 RPC 或推进 Run。

### Blueprint 动态信息与失效通知

1. 创建以 `CatWorldInfoComponent` 为父类的 Blueprint 组件，用它替换普通组件；在 Overrides 中选择 `EvaluateDisplay` 和 `BuildInfo`。它们是带返回值的 `BlueprintNativeEvent`，按覆盖函数连接返回节点。
2. `EvaluateDisplay` 可通过 Parent 调用保留三策略，再根据对象状态返回 `Hidden`、`Summary` 或 `Full`。
3. `BuildInfo` 使用 `Make CatWorldInfoViewData` / `Make CatWorldInfoRow` 构造 `OutData`，连接布尔返回值；字段来自对象现有状态。暂不可用但仍需要解释时，返回 true，并填明确状态文本；完全不显示才返回 false。
4. 数据写入后调用该组件的 `NotifyInfoChanged`。复制数据在本客户端的 RepNotify 中调用，房主本地写入路径也要调用；只在服务器调用不能通知远端 UI，因为通知序号不复制。

`NotifyInfoChanged` 仅递增本地序号，不广播网络命令。只改 `StaticInfo` 或动态源字段而不通知，已显示内容可能保持旧值。策略与距离按候选刷新重新求值；即使是按 Viewer 计算的文本，Viewer 相关数据变化也必须触发失效。组件本身不提供业务复制或存档能力，跨端事实仍由所属系统负责。

## 4. 正式 WBP 与行模板

正式资产位于 `/Game/UI/WorldInfo/WBP_CatWorldInfo`、`/Game/UI/WorldInfo/WBP_CatWorldInfoRow`，以及 `/Game/UI/Run/WBP_CatDayTransition`。生成器合同检查与双端 PIE 已使用这些资产；打包后的完整表现仍未验收。

### 信息牌合同

面板父类为 `UCatWorldInfoWidget`，行父类为 `UCatWorldInfoRowWidget`。在 Designer 中保留以下名称、控件类型和 `Is Variable`；控件必须实际位于可达布局树中。

| WBP | 必需控件 | 结构要求 |
| --- | --- | --- |
| 信息牌 | `DetailSwitcher`：WidgetSwitcher | 两个直接子页面；索引 0 是摘要，索引 1 是详情 |
| 摘要页 | `SummaryTitleText`、`SummaryStatusText`：TextBlock；`SummaryInfoList`：ListView | 三者属于索引 0 页面 |
| 详情页 | `TitleText`、`StatusText`：TextBlock；`InfoList`：ListView | 三者属于索引 1 页面 |
| 信息行 | `LabelText`、`ValueText`：TextBlock；`RowIcon`：Image；`RowProgress`：ProgressBar | 图标和进度值可以缺省，具名控件本身仍是必需绑定 |

两个 ListView 的 `EntryWidgetClass` 配置为正式行 WBP。标准资产生成器要求它们精确引用 `WBP_CatWorldInfoRow` 的生成类。面板、行和根布局保持 `HitTestInvisible`（自身及子项不接受命中），关闭焦点；列表 `SelectionMode=None`、关闭焦点与滚动输入。信息牌只供阅读，不能依靠列表滚动露出必要字段。

默认生成布局宽 320，行高 36，摘要列表预留两行、详情列表预留八行，标题/状态另占空间；这里是 UMG 布局单位，不是世界厘米。长单行文本使用省略，超出行数不会自动增高。新提供者应控制行数，或在自己的正式 WBP 调整尺寸与排版。默认祭坛使用 `FocusOnly`，对准后显示详情；若显式改为摘要，其当前多行数据都标记了 `bSummary=true`，不能直接假定两行摘要框能容纳全部字段。

每行 `Id` 是稳定语义键，`Label` 是概念名称，`Value` 应包含格式化值及单位。`bSummary=true` 的行进入摘要，详情显示全部传入行。`Icon` 为空时隐藏图标；`Progress=-1` 表示没有进度，有限非负值按 0～1 显示，不能把“未知”做成零进度。

需要逐对象外观时，可复制正式面板与行 WBP，保留父类和绑定合同，修改布局后把对象组件的 `WidgetClass` 指向新面板。自定义面板可覆盖 `RenderInfo(Data, Detail)` 按 `Row.Id` 更新自己的正式控件；如需默认列表行为，显式调用 Parent。即使覆盖渲染，继承的必需绑定仍须满足。标准生成器只核验其固定目标资产，不会自动检查新路径的自定义 WBP。公共控制器拒绝非 Blueprint 类或非 `UCatWorldInfoWidget` 子类，缺失时不创建原生替代布局。

## 5. 固定位置、遮挡与交互边界

控制器读取本玩家 `GetPlayerScreenWidgetGeometry(...).GetLocalSize()`，使用已去除 DPI 缩放的 UMG 布局单位，再以 `SetPositionInViewport(..., false)` 放置。默认列起点横向为玩家区域宽度的 50% 加 48，纵向为高度的 20%；保持同一面板与窗口尺寸时，转动镜头不改变位置。WBP 内不要再除一次 DPI，也不要每帧自行覆盖视口位置。

窗口缩小时，首个面板向内收至 16 单位安全边距，不自动换边或缩小字体；面板大于可用区域时隐藏，不裁切正文。默认 `FocusOnly` 只显示当前命中对象。显式使用可选附近策略的消费者仍按焦点、较大 `DisplayPriority`、较近距离、对象路径排序，并在固定列向下排列，间隔 8 单位，剩余高度不足的面板隐藏。旧世界投影、锚点离屏判定和四向寻位均已移除；附近策略不再另以锚点离屏隐藏，默认准心策略仍在移开时隐藏。组件坐标保留给遮挡检查，不是第二套定位入口。

每次绑定本地玩家仅记录一次 `LogCatUI / Event=WorldInfoScreenLayoutBound / Layout=FixedScreenColumn`，包含 World、NetMode、Authority、LocalRole 和 Player，供 Development 日志确认布局版本；不逐帧写日志。既有交互提示与其他 HUD 的最终重叠情况、小窗口及分屏表现仍待用户实玩核验。

`bHideWhenOccluded` 使用相机到组件锚点的射线，沿 `TargetingTraceChannel` 检查遮挡，忽略观察者 Pawn 和该组件 Owner。关闭此开关只跳过信息牌遮挡检查，不会让准星穿透前面的阻挡 Actor。没有 Pawn、Controller 显示鼠标光标、或翻天输入被锁时，信息层整体收起。

`TraceInteractableFromCrosshair` 先把命中的 Actor 记为 `ObservedTarget`，再按原 `MaximumTargetingDistanceCentimeters`、交互接口和 `CanInteract` 求 `CurrentTarget`。信息层提供的观察距离预算可以延长只读射线，并计入第三人称相机偏移，但不扩大 E 键范围。看到信息、聚焦展开、允许按键和服务器接受命令是不同条件；WBP 不应通过可见性推导交互权限。

### 数据归属与未知值

鱼缸的 `UCatFishTankWorldInfoComponent::RefreshSummary` 只在服务器从正式鱼库存读取实例、实际槽位容量，以鱼的真实千克重量调用 `UCatRunSettings::TryClassifyOfferingWeight` 汇总点数。它复制的是整份 `OfferingSummary`，客户端不依赖尚未到齐的鱼实例重算点数。库存变化触发刷新；复制到达和房主本地发布都会调用 `NotifyInfoChanged`。

`TryGetOfferingSummary` 返回 false 时输出为 `INDEX_NONE`；必须先分支判断再显示。有效空库存可以是 0 点，缺组件、复制未就绪、重量分类失败或无效库存则不是 0 点。今日目标还需检查 Run 是否就绪，默认鱼缸文案显示“待同步”。鱼缸摘要两行为 `OfferingReserve`、`DailyOfferingTarget`，详情增加 `FishCountCapacity` 和非负 `OfferingShortfall`。

祭坛地面预览由服务器 `CollectOffering` / `RefreshGroundOfferingPreview` 发布，使用范围内 `Available` 且未附着的落地鱼，与冻结供品共用筛选。`TryGetGroundOfferingPoints` 返回 false 时即便输出被清为 0，也必须显示“暂不可用”。地面待献、缸内储备和已提交点数是三种事实；显示鱼缸储备不会自动把缸内鱼作为本次供品。

祭坛从正式 Run 公开态、复制的地面摘要/确认人数和显式鱼缸摘要构建 `WorldProgress`、`DailyTarget`、`TankReserve`、`GroundOffering`、`Confirmed` 等行。确认分母是服务器认定的 Active 且非倒地玩家，不只是当前到场人数。复制通知及提供者对 Run 修订、鱼缸引用/序号的低频观察使内容失效；UI 不维护第二份参与者或库存状态。

## 7. 翻天结果与上一献祭记录

结算展示使用 `FCatRunDayTransition.LastCommittedOffering` 中的 `FCatOfferingResultSnapshot`。GameMode 在调用唯一结算写口前冻结旧天 `SettlementDay`、`TargetPoints`、`WorldProgressBefore`，GAS 接受且冻结供品全部消费成功后才写入 `OfferedPoints`、`bMetTarget`、`WorldProgressAfter` 并公开整份结果。

此快照按成功提交保留，不能用次日已重置的当日属性重算。新过渡初始化时保留上一份；失败或尚未提交时不会把它改成一次零献祭，下一次成功提交才替换。无有效 `RequestId` 表示没有历史结果；这不构成跨 Run 或跨存档永久保留的承诺。

祭坛通过有效的历史 `RequestId` 显示 `LastOffering` 和 `LastWorldProgress`。翻天页则更严格：本轮 `bCommitted=true`，且历史结果 `RequestId` 等于当前过渡 `RequestId` 时才显示本轮献祭明细，防止上一轮成功被误读为本轮成功。

正式翻天 WBP 父类为 `UCatDayTransitionWidget`，必需 `BlackOverlay`（Border）、`ResultText` 与 `SettlementText`（TextBlock）。`[/Script/Catfishing.CatUISettings]` 的 `DayTransitionWidgetClass` 当前指向 `/Game/UI/Run/WBP_CatDayTransition.WBP_CatDayTransition_C`。在该 WBP 编辑全屏遮罩及文本布局，保留绑定；`RenderTransition` 只更新透明度、文本和焦点。已有 Slate 焦点 API 用于保存/归还用户焦点，不负责创建 Slate 界面。过渡时序、操作锁与结算仍由既有 Run / PlayerController 链路负责，不能由 WBP 动画结束反向提交。
