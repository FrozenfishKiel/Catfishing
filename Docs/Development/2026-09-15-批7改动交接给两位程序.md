### 编译过了但行为变了

**一、三个窗口彻底分家，别再把它们混用。** 这是 T10 存在的全部理由。

| 窗口 | 现在的值 | 从哪来 |
|---|---|---|
| 试探期 | 逐鱼，1.5／2.0／2.5／3.0 秒 | 资产字段 → ini 逐鱼覆盖 → 档位折中 → 随机 2~4 秒兜底 |
| 真咬响应窗 | 逐鱼，9／11／13／15 秒 | 同上链条 |
| 完美窗 | **恒 1 秒**＋成长加宽（+0.5，上限 +1） | 不进上面那张表 |

**响应窗从全局 3 秒变成 9~15 秒，这是 3~5 倍。** §3.4:141 规定按鱼种 8~15，3 秒根本不在
区间里。副作用要有心理准备：**「超时鱼吐钩」这个失败出口现在几乎不会发生了**，
如果试玩觉得提竿没难度，先动这组数、不要动完美窗。

**二、总余额＝绿＋黄。** `CatFishingFightRunner` 不再只读绿段，黄色体力现在真能在钓鱼里花出去。
连带：绿段归零不再把力量清零，所以**猫在低体力下仍然有力量**，碾压判定会比以前更容易达标。

**三、真咬那一刻冻结 D₀，之后移动不重算。** `OpenTrueBiteWindowFromAuthority` 新增两道闸：
竿定义解不出来 → `Invalidated`；D₀ > 竿的 Lmax → **鱼逃**，不 clamp、不先套完美乘数。
写夹具时要给 `AttemptSnapshot.RodDefinitionId` 和有效的 `FisherCharacter`，否则真咬开不了窗。

**四、鱼体力 ≤0 才翻肚。** 删掉了「剩余低于阈值就吸附归零」。正余额一律继续游动。
不会导致搏斗打不完——扣体是「未完成距离 × 每米价」，与剩余体力无关，定速到零。

**五、完美线长系数从空转变成 0.9。** 之前值从性格资产搬到全局 Config、ini 没配，
`SanitizePerfectMultiplier` 把 0.0 当未配置静默退回 1.0，**完美提竿有一整段时间根本不缩线**。
现在 `PerfectInitialLineLengthMultiplier=0.9`。完美提竿现在是三项一起削：力量 ×0.8、
体力 ×0.85、初始线长 ×0.9。

**六、长按收竿 1.5 秒由服务器计满**，客户端只显进度不自行确认；挥空与抢拾失败各进
3 秒独立硬直，硬直接入 ASC、Controller、GameMode、CMC、PhysicalBody 与抓握准入。

**七、同刻结算序固定为收鱼 → 苏醒 → 落水**（§5.4），并列时按席位序。
新增 `CatFishingResolutionSubsystem` 做这件事。

### 编译过了但行为变了

**一、拿鱼的所有入口都收到同一组验证下**（同 World 与触达距离、合法地面鱼容器、
唯一嘴部交接）。被收口的包括：通用 Move/Exchange RPC 及其底层直调、任意 Host 输入、
库存 Drop/Place、**Blueprint 的 `AddItemInstance`/`AddItemDefinition` 发货**、
通用 `ACatItem` 的含鱼批次、地面鱼交互、抄网命令。

**跨库存移动含鱼的端点一律拒绝**——要先 Carry 进嘴再 Store。封住 Move 之后合法入缸会断，
所以补了 `CatFishTankActor::Interact` → `StoreInFishGuardFromAuthority`，复用同一套解析。

**这条有个副作用你要知道**：`CanAcceptInventoryDefinitionAtSlot` 现在拒绝「猫身上的鱼定义」，
所以**任何往角色背包塞鱼的测试夹具都会失败**。这不是 bug，是 道具:64 的规矩。
写夹具时鱼要放嘴里或地面容器里。

**二、存档版本 6 → 7，而且 v6 的含义在批 7 中途被改过。**
`CatRunSaveGame` 现在存多个 `TeamStorageRole`、`FishInventory`、`CapacityTier`、
世界进度与公款。v6→v7 迁移会把旧档里**背包里的鱼清掉并记一条 Warning**
（`inventory_restore_backpack_fish_skipped`，带定义 ID、实例 ID、槽位），其余照常恢复。

**用旧 build 打开新档会静默清零公款、公共架与缸内鱼**——旧 build 判「版本一致」，
把新字段读成空再按旧格式回写。切 build 时别共用存档。

**三、鱼缸容量配置改了不会再拒绝旧档。** 之前拿磁盘里的 Capacity 与当前 ini 算出的档位
容量做等值比较，不等就整份判非法 → 整局起不来。现在只做结构完整性校验，
档位容量当恢复时的目标值按当前配置重算，多的格空着、装不下的走超限路径。
**所以你可以放心调 10/20/30 这三个数了。**

**四、整车成交是一个事务。** 改成完整准备实物后一次扣款：任一步失败恢复两仓、档位、
幂等记录与货架库存且不扣款；付款被拒恢复余额并回滚货物；完整提交后才广播一次。
两档鱼缸升级改用车内子项身份，同 `RequestId` 不再吞掉第二档。

**五、毕业收摊是「整车里的最后一步」，不是准入条件。** 这条踩过坑：一度把小鱼干兑换
当成整笔事务的前提，而 `buff_driedfish` 没有对应资产，结果成功毕业那一夜整笔被拒、
公款不清装备不收。现在缺定义或缺价只记 `shop_settlement_exchange_skipped`、兑 0 条，
清款与退役照做。**`StartingTeamWalletBalance` 从 999999 改成 100**——它现在参与除以单价。

**六、翻天清掉落接进了已有的那条翻天入口**（非首日进入 DayActive），
清未拾 `ACatItem` 与 Available 地面鱼，保留嘴叼对象与库存隐藏载体。没有新建第二条翻天链。
新增 `CatWorldDropProtectionComponent` 在 PostPhysics 扫**整段抛落轨迹**，碰水退回上一安全
姿态并去水平速度，复用原 Actor。

**七、断竿保留真实报废但不自动选另一根**；货架 `CanInteract` 与页面入口读打烊状态；
失败消息分开余额、库存、交付三种原因。

### 测试这件事，有一条教训

**这个工程里有一批测试依赖随机**（咬钩种子来自 `FGuid::NewGuid()`，鱼种与体重每轮都不同），
所以**跑一次的失败列表不能当基线**。批 7 期间我用「改动前跑一次、改动后跑一次」判过一条
回归，事后证明那条测试本来就不稳、猫力从头到尾没变，是鱼的体重 roll 变了。

判据改成：**随机系统里的基线＝同一提交跑 N 次的失败集合**，不是一次运行的失败列表。
另外提交级的闸门请用 `RunTests Catfishing`（整树），不要用 `Catfishing.Unit`。

## 设计侧这一批拍了什么

全部在 `Knowledge/Design/设计修改记录.md` 的 09-13、09-14、09-15 三节，这里只列影响代码的：

- **力竭状态与三道恢复闸全部退役**；黄色体力按完整消费者链接通
- **换人不设体力准入**；无人值守的竿可以被接管
- **删「事件」稀有度档**，湖心巨影归入稀有（资产还没迁）
- **试探期改逐鱼配**；真咬响应窗按鱼种 8~15 秒
- **完美线长系数 0.9**（从四份 Bite 资产的历史值取平均，暂定，待试玩校准）
- **基础池四条概率**由占位提为暂定正式，保底档从此是活的
- **收摊兑换 10 金币 1 条**，装备按道具总表原价折算、不打折
- **待议**：物理抓握下 `F_total` 是什么（见潘志鹏那节）

标着「暂定」的数都可以改，改的时候先改设计文档再改 ini，两边都写了改数流程。
