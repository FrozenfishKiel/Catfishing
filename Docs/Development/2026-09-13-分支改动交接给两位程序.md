### 编译过了但行为变了

**`ST_FishingSession` 里那个 StateTree 节点，同一个节点、完全不同的行为。**
`FCatFishingOpenTrueBiteWindowTask` 这个结构名**故意没改**（资产按结构名序列化，改名会丢节点），但内部从「只把浮漂切猛沉＋开响应计时器，不创建鱼」变成「抽鱼、按真鱼体型生成水里的鱼影、揭图鉴剪影、起试探期停留计时」。停留到点由会话自己转猛沉并开真咬窗，资产不需要再加边。**资产没改，行为变了**——这是你最可能被绊到的一条。

**竿强瞬断从死枚举变成真实出口。** `ECatFishingOutcome::LineBroken` 原来是 `UMETA(Hidden)` 的旧资产兼容值、没有生产者；现在 `CatFishingSession.cpp:2206` 会产生它，并且按 09-12 裁决**报废鱼竿**（一次性把剩余耐久加满即归零，与耐久归零共用同一结局与表现）。枚举序号保持不变。检查序在 `CatFishingSession.cpp:2148`：①竿强瞬断 →②碾压 →③常规搏斗，只在搏斗开始和合力变动时查，不逐帧轮询。

设计给这条加过前置——「鱼影必须先于提竿出现」（`钓鱼规则.md:176`）——那个前置已经接好了，在 `CatFishingSession.cpp:1006` 的 `Encounter->PublishInitialPresentationFromAuthority()`，放在试探期入口而不是搏斗启动。

**放线回体的基础值从 1.5 变成 0。** `CatFishingFightSimulator.h:78` 的结构默认值改了，口径是「基础为 0，猫册三选一『放线回体速度』是唯一把它抬起来的来源」（`钓鱼规则.md:213`）。生产读的是平衡资产不是这个默认值，所以**实机没变**（资产里是 3，见〈接了一半、配了不生效的四条链〉第 4 条）；但你自己搭配置跑测试或工具时，不显式给这一项就是零回体。

**完美削减从挂性格资产改成按稀有度分档。** 原来四份 `Bite_*.uasset` 各配一套倍率（解二进制读出来：力量 0.9／0.8／0.75／0.85，体力同值），现在统一走 `UCatFishCatalogSettings::ResolvePerfectHookReduction()`，普通鱼 0.8／0.85、稀有鱼 0.85／0.9，按 09-09 裁决「稀有度最高档取稀有鱼系数、其余取普通鱼」。性格资产上那三项改成了 `DeprecatedProperty`，值还在盘上但不再被读。

**试探期就绪校验从 `> 0` 放宽到 `>= 0`。** `Data/CatFishPersonalityDefinition.cpp`，原来配 0 秒会让整份性格资产判不就绪；现在 0 表示「这条鱼不覆盖，用全局区间」。

⚠️ 这套混合实现的口径 **2026-09-13 被改掉了**：试探期时长拍定改**逐鱼配**、成为鱼表格的一列（钓鱼规则 v1.9、参数页 v0.39），参数页的 2～4 秒区间降级为该列未填时的兜底。改前的事实是四份 `Bite_*` 都配了值（1.0／2.4／2.8／1.6 秒），所以符合设计的那个区间一次都没用上，其中 1.0 与 1.6 还落在 2～4 之外，而 09-09 晚已裁「四套模板是测试用」——这就是改口径的由来。要做的是把字段从性格模板挪到鱼定义上，16 行各填一个值（值待张佳定）。

### 接了一半、配了不生效的四条链

**这一节是本次回顾里最该先看的。** 四条链都是「编译全绿、测试也绿、实机不按设计跑」，而且每条都横跨两人。

#### 1. 黄色体力在钓鱼里既扣不到、也不顶用

ASC 这一头是对的：`ApplyFishingStaminaDelta`（`CatAbilitySystemComponent.cpp:210-232`）负向 delta 先扣绿，绿段不够就把溢出交给 `ApplyYellowFightStaminaDelta`，黄段不自然回复、清晨清零。

Runner 这一头把它堵死了：
- `CatFishingFightRunner.cpp:352` 是 `Paid = FMath::Min(FrozenOperatorStamina, RequestedDrain)`，而 `FrozenOperatorStamina` 在 `:263` 只读 `GetFightStaminaAttribute()`（绿段）。所以钓鱼**永远不会把超过绿余额的费用交给 ASC**，那条溢出分支从钓鱼这边进不去。
- `:268` 是 `ActiveFishingStrength = IsLocomotionEnabled() && FrozenOperatorStamina > 0.0 ? Strength : 0.0`。绿段一见底力量直接归零，**黄段有多少都不看**——护盾段本该让猫在绿条空了之后还能顶一会儿。

对照：非钓鱼那条路（抓／推／爬，09-11 裁决④的统一出力池）走 `CatPhysicalEffortComponent.cpp:87`，那里不按绿余额封顶，所以**黄条在那条路上花得出去**。同一条裁决，两条路行为不一样。

今天看不出来，是因为**没有一条鱼给黄条**：给的入口在 `CatConditionComponent.cpp:214-216`（按 `FishDefinition->YellowStaminaGrant`），而 16 份 `Fish_*.uasset` 里 `YellowStaminaGrant` 命中 0 份。
**设计已经给了具体值在等**——吃鱼效果 §2（`吃鱼效果.md:27`）的黄色体力来源是小彩鱼／黑鱼／风铃鱼各 +20、猫神的祝福 +50。所以鱼表一填这一列，上面两个问题立刻现形。

谁改：Runner 是潘的（`CatFishingFightRunner.cpp` 分叉前 pzp 57 次／Kiel 3 次），ASC 是蓝的（`.h` pzp 0／Kiel 3）。**得两人先把「钓鱼要不要能扣黄、绿空黄不空时还有没有力量」这个合同谈定**，任一头单独改都会错。

### 存档

**局内档故意不抬版本。** `CatRunSaveGame` 新增 `RunFishCollectionCaptures`、`bRunCompleted`、`TankOfferingPoints`，`FormatVersion` 保持 **6**——三项都是加法字段，旧档反序列化后的默认值（空数组／`false`／`INDEX_NONE`）语义正好就是对的（「没打完、可以继续」「没记过这个量」）。校验在 `CatSaveSubsystem.cpp:1143`，v6 旧档照样通过。`bRunCompleted` 为 true 的槽只能当战绩回看，前端不提供「继续」，读档入口也会拒绝（`CatSaveSubsystem.cpp:96` 也查它，不只是前端置灰）；文件永远保留，删档只能由玩家在前端主动做（09-11 拍）。
