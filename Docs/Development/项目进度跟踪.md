## 0. ⚠️ 当前状态：能编译能联机，但**玩不了**（2026-08-20 17:00）

之前那条"DLL 被 Smart App Control 拦住加载"的阻塞**已经解除**（用户已关闭 SAC），构建、自动化、双进程冒烟全部恢复正常。原文保留在 git 历史里，判据与处置见 `.harness/CODING_LESSONS.md`。

**现在的阻塞换成了另一个，而且是我们自己造成的：**

2026-08-20 下午按用户要求，把开发期白盒命令面板从正式代码里整个删除了（理由：调试工具不该留在正式代码里）。删除本身是干净的、构建与全部测试都通过，但它带来一个**已知且当时就明确接受**的后果：

> **面板是当前唯一的玩法入口。删掉之后，34 个 Server RPC 里有 26 个失去了生产调用方。**

具体说：现在进游戏可以走路、转镜头、跳跃、进水会湿、能看到状态数字，但是——

| 做不了的事 | 对应失去入口的 RPC |

| 献祭 / 确认翻天 / 结算 | `ServerRequestSacrifice`、`ServerSetNextDayReady` |
| 回营休息 / 转鱼进缸 | `ServerRequestCampRest`、`ServerTransferFishToTank` |
| 买东西 / 装备 / 卖鱼 | `ServerSubmitShopPurchase`、`ServerClaimFreeShopEntry`、`ServerConfigureEquipment`、`ServerTakeTeamEquipment`、`ServerSellFish` |
| 全部社交玩法 | 偷鱼、恶作剧、保护牌、权限、踢人、协作钓巨鱼、手动求助（共 9 个，**这 9 个本来就没有入口**，不是这次删掉的） |

**所以下一步"做正式 UI"的性质变了**：它不再是锦上添花，而是**恢复可玩性的必要条件**。在正式 UI 到位之前，PIE 里只能验证移动、镜头、淋湿和联机复制，验证不了任何核心循环。

需要产品侧决定的是：社交那 9 个 RPC 这个里程碑要不要补入口，还是先撤下。事实源在飞书，不由工程侧拍。
