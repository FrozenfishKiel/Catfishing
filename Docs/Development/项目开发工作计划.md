# Catfishing 项目开发工作计划

更新时间：2026-08-14  
文档状态：当前开发工作计划。  
范围：只描述当前需要完成的项目功能、技术责任、依赖顺序和完成标准。本文用于范围核对，不规定 Agent 的资料读取顺序，不记录人员分工，不复制飞书 GDD，也不提前展开尚未开工模块的数据行和资产明细。

## 1. 文档位置与资料边界

本文只是开发范围和工作包的一份输入，不替代其他上下文。Agent 应根据具体任务主动选择并交叉核对所需资料，包括但不限于：

- `Knowledge/Requirements/PROJECT_MAP.md` 与任务相关的飞书正式 GDD、表格和审计材料；
- 当前源码、配置、资产、测试、构建日志和实际运行证据；
- `Knowledge/Framework/` 中的源码地图、规则、决策、术语和已知问题；
- 相关架构、开发、测试与验收文档；
- 任务确有需要时的 Unreal Engine 源码、平台文档和参考项目。

唯一不得进入普通开发上下文的资料是 `Docs/Architecture/项目完整蓝图与开发分工.md`；具体禁读规则见 `AGENTS.md`。这项排除不影响任何其他资料的读取和使用。

飞书「小猫钓鱼」仍是产品规则的唯一持久事实源。本地计划负责确定实施范围和工程顺序，不能反向修改产品规则。遇到 GDD 冲突或缺失时，在 `Knowledge/Framework/DECISIONS.md` 记录唯一 `Engineering Working Decision`；不等待无限期，也不同时实现两个方向。

## 2. 当前工作范围

当前工作负责以下完整产品领域：

- Data：鱼、装备及其他不可变 Definition、Catalog、稳定 ID、版本和内容校验；
- Run：十日局、日夜、Quota、祭坛、ready、成功/失败结算和全域 teardown；
- Online：好友 Session、Host/Find/Join/Invite/Leave、旅行、网络失败和同进程重新准入；
- Environment：区域、WaterRegion、天气、时间条件、自然事件、NearShore 查询、三轴窝料池和环境快照；
- Equipment：局内装备实例、备装、换装、耗材、鱼竿耐久、损坏替换和团队装备库；
- AbilitySystem：Hunger、Fatigue、Poison、FishingStrength、FightStamina 和服务器 Effect；
- Condition：Wet、Downed、恢复及其合法状态迁移；
- Character：猫身体生命周期、ASC Owner/Avatar、交互、搬运、公共动画挂点和输入转发；
- Items：FishInstance、鱼护、共用鱼缸、容量、转移、进食、献祭预留和偷鱼 escrow；
- ShopEconomy：团队钱包、商店库存、购买、售鱼、团队装备交付、交易账本和局终关闭；
- Social：求助、恶作剧授权、防骚扰、偷鱼全终态、成员关系和 Public Catalog Projection；
- Collection：Candidate allowlist、CapturePlan、共同成像、媒体投递、Grant outbox 和重投；
- Profile：图鉴、印记、相册、外观/解锁、本地隐藏、SaveGame、版本和 durable ACK；
- Camp：固定营地、休息、救援落点、共用鱼缸表现、每夜篝火和结算封面入口；
- Framework/Game：GameMode、GameState、PlayerState、PlayerController 的宿主、身份、RPC 路由和公开快照；
- UI/Input：Frontend、Run、营地、商店、社交、图鉴、相册、生存状态等全局与非钓鱼界面和输入；
- Presentation：公共 Character/基础 AnimBP、世界表现、天气、营地、商店、社交、相册、音频、VFX、材质、镜头和 Lake 主地图接线；
- 工程集成：GameplayTags、Settings、Config、Build、Cook、Dedicated Server、多人验证和旧路径删除。

`Fishing/**` 内的 Attempt、Fishing StateTree、鱼运行态、钓鱼专用 UI/Input/动画/VFX/音频/镜头和专用验证不属于本文的默认实现范围。Agent 可以为了理解依赖、核对接口、诊断问题、设计 Adapter 或验证集成而读取全部相关 Fishing 源码、测试和资产；读取不受限制。只有修改 Fishing 内部状态机或专用表现时，才需要一个明确包含该改动的任务，不能在外围功能中顺手改写。

当前范围仍需提供 Fishing 使用的生产外围能力：Data 生成冻结 EncounterSpec，Environment 提供水域/窝料事实，Equipment/GAS 处理资源，Items/Collection 处理捕获结果，Framework 路由身份与 RPC。提供这些端口不等于接管 Fishing 内部玩法。

## 3. 完成标准

每个进入主运行路径的功能原子必须同时具备：

1. 唯一 SSOT；
2. 唯一权威写入者；
3. 完整 Command、State、Command Result、Gameplay Terminal 和 Failure Semantics；
4. 服务器权威与必要复制；
5. 断线、取消、乱序、重试和 Cleanup；
6. UI/表现所需 Snapshot 或 Cue；
7. 正常、非法、边界、重复、并发与超时自动化；
8. 对应的 Dedicated Server、多客户端或实际运行证据；
9. 被替代旧路径的删除证据。

第 3 条要求分别回答：玩家提交什么意图，服务器在哪些状态受理，权威状态怎样迁移，本次请求返回 Rejected/Pending/Committed 中哪一种，整个玩法最终成功或失败为什么，以及系统故障后哪些副作用保留、用哪个键恢复、如何 Cleanup。请求回执不能冒充玩法终态，玩法失败也不能冒充事务错误。

开发可以分原子逐步完成，但未闭环能力不得进入正常入口。测试 Fake、接口骨架、单条成功路径或隐藏旧 UI 都不能作为功能完成结论。

## 4. 工作包

### WORK-00：开发基线与外部集成合同

目标：建立后续系统共享的稳定语义，不把外部 Fishing 状态复制进外围领域。

必须完成：

- 核对当前 Build、Automation、Config、Content 和运行基线；
- 只消费版本化 Fishing Boundary，提供 Start/Cast Context、Bait、Chum、Fight Resource、Terminal Submit/Poll 的生产侧实现；
- 冻结 StableId、AttemptId、OperationId、Revision、Cursor、Receipt、PayloadHash 和错误码语义；
- 实现 Chum Deposit 与 Capture Settlement 的可恢复协调记录；
- 建立 Golden Request/Result、合同测试和 Result Inbox；
- 明确全局 UI 挂点、Input Context 优先级、Character Socket、基础 AnimBP、镜头和移动仲裁；
- 证明外围不能反向推进 Fishing 阶段，Fishing 也不能直接写外围真相。

完成证据：合同自动化、重复/乱序/超时测试、生产 Adapter 接入证据和旧旁路不可达证明。

### WORK-01：Data 与内容基础设施

目标：让运行时只消费经过校验、版本化、可追源的正式内容。

必须完成：

- Fish、Equipment 及相关 Definition/Catalog 的稳定 Schema 和 ID；
- 飞书数据的离线导入或人工落盘流程，禁止运行时读取飞书；
- 重复 ID、缺字段、非法引用、范围反转、未定义枚举和版本不兼容校验；
- EncounterSpec 的确定性生成、SchemaVersion、DataRevision 和 ContentHash；
- Editor/CI 校验、Cook 引用和缺内容 fail-closed；
- 删除仍可覆盖正式数据的旧常量或临时 Seed 入口。

模块开工时再建立具体鱼种、装备、数值和资产清单。

### WORK-02：Run、Online 与 Framework/Game

目标：从 Frontend 建局到十日成功/失败结算再返回 Frontend，形成完整可恢复的一局。

必须完成：

- Host、Find、Join、Invite、Leave、Destroy 补偿和旅行失败收口；
- 1～8 人好友局、中途加入 disposition、同一权威进程内 60 秒重新准入；
- 十日 DayActive/NormalNight/Settlement/Ending 状态和服务器时钟；
- 每日 Quota 冻结、祭坛提交、全员 ready、成功/失败结算夜；
- GameState 公开快照、PlayerState 连接期身份和 Controller RPC 路由；
- Host 退出的有界 teardown；不实现 Host Migration；
- Run 结束时关闭交易、清理局内状态并保留合法 Profile Grant；
- Frontend、Lake、Dedicated Server、多客户端与 Steam 双账号实际证据。

### WORK-03：Environment

目标：提供多人一致、局内有效、可被玩法消费的湖畔环境。

必须完成：

- 区域和 WaterRegion 稳定 ID、合法水边与 NearShore 几何查询；
- 晴、雨、雾、时间段和自然事件的服务器调度与快照；
- 三轴共享窝料池、半衰减、聚鱼统一机制、稀缺预算和 late join 收敛；
- Chum Deposit 按“Equipment 预留 → Environment Deposit → Equipment 消耗”单向完成；
- 夜晚禁钓等 Run 条件接口；
- 天气、时间、聚鱼和自然事件的 UI、音频、VFX 与远距 Cue；
- Run teardown 后环境状态无跨局泄漏。

### WORK-04：Equipment、AbilitySystem、Condition 与 Character

目标：让猫身体、资源、装备和状态只有一套服务器真相，并能完整进入、表现和退出。

必须完成：

- 每名实际入局玩家幂等取得一次初始装备；
- 备装、换装、耗材、团队装备库、鱼竿耐久和 RodBroken；
- Fight Resource Cursor 的幂等资源写入与 FinalFightCursor 封存；
- Hunger、Fatigue、Poison、FishingStrength、FightStamina 的初始化、复制和服务器 Effect；
- Wet、Downed、恢复、搬运到营地和合法救援；
- Character 的 ASC 生命周期、组件装配、输入转发、公共 Socket 和基础表现；
- UnPossessed、EndPlay、重连、掉线和 Run teardown 的顺序化 Cleanup；
- 删除修竿、草药恢复、LineBroken/“断线”等被替代路径。

### WORK-05：Items、Camp 与 ShopEconomy

目标：让鱼和团队资源从产生到消费、交易、展示和局终清理形成完整闭环。

必须完成：

- FishInstance 的唯一身份、所有权和容器 Revision；
- 鱼护、共用鱼缸、容量、转移、吃鱼和献祭预留/提交；
- 捕获结果的 Items materialization 与 Collection outbox 单向 Settlement；
- 固定营地、休息、救援落点、共用鱼缸表现和设施权限；
- 团队钱包、商店库存、购买、售鱼、免费普通饵、团队装备交付和交易广播；
- ShopEconomy 只写订单/钱包/库存/账本，Equipment 只写 EquipmentInstance；
- 重复交易、并发售鱼、容量冲突、离线、Ending 关闭和局终 Cleanup；
- 玩家可见 UI、失败反馈、动画、音频和实际资产。

### WORK-06：Social

目标：把求助、恶作剧和偷鱼做成可控、可拒绝、有完整终态的多人体验。

必须完成：

- 局主设置、成员权限、好友局策略、冷却和 ProtectionSign；
- 附近手动求助与巨物全局提示；
- 恶作剧的授权、关键阶段拒绝、责任归属和猫式反制表现；
- 偷鱼的 escrow、追逐、追回/被抓、吃掉、卖掉三个唯一终态；
- 共用鱼缸追回、原物返回、团队钱包入账和不可逆结果；
- Public Catalog Projection 只作社交展示，不驱动奖励和权限；
- 断线、超时、重复、并发、骚扰保护和 Run teardown；
- 真实多人可见 Cue、UI、动画和行为试玩证据。

任何偷鱼终态缺失时，整项保持关闭，不能上线半套。

### WORK-07：Collection、Profile、媒体与相册

目标：把服务器事件、共同媒体和本地永久记录做成可恢复、可授权的完整链路。

必须完成：

- 图鉴 Unknown/Silhouette/Recorded、首次捕获和个人最佳；
- Imprint Candidate allowlist、频控、聚合和 CapturePlan；
- Listen Host 单次成像、相同媒体字节的有界 Chunk 传输、ACK、重传和 Hash 校验；
- 每个收件人的 Membership/Permission 重新授权与断点续传；
- Profile Grant Journal、原子落盘、重复 Grant 去重、SaveGame 版本与恢复；
- 私有相册、本地隐藏、容量治理、每夜篝火精选和局末封面；
- 成像失败、Host 丢失、收件人离线、空间不足和 teardown 的明确结果；
- UI、相纸表现、音频、实际媒体落盘和多客户端证据。

### WORK-08：全局 UI、Input、Presentation 与世界资产

目标：让所有非钓鱼功能有统一入口、可理解反馈和可运行内容资产。

必须完成：

- Frontend、Run HUD、状态、营地、商店、社交、图鉴和相册的信息架构；
- UI 只提交 Intent、消费 Snapshot/Result/Cue，不直接写领域状态；
- 全局 Input Mapping 与各 Context 的优先级、挂载和移除；
- 公共 Character/基础 AnimBP、Socket、交互、搬运、Wet/Downed 等表现；
- Lake 主地图、水域、营地、鱼缸、商店、保护牌和环境设施实际摆放；
- 天气、昼夜、自然事件、营地、商店、社交和相册的动画、VFX、音频、材质与镜头；
- 分辨率、焦点、手柄/键鼠、可访问反馈、加载失败和 Cook 资产验证。

模块开工时再建立对应 Widget、InputAction、动画、VFX、音频、材质和地图资产清单。

### WORK-09：集成、删除与最终验证

目标：让完整项目只剩一条可运行路径，并以新鲜证据证明结果。

必须完成：

- 双 Target Build、全量 Automation、Cook、Package 和 Shipping 检查；
- Dedicated Server、Listen Server、1/4/8 人、多进程、Steam 双账号和弱网；
- 十日完整 Run、长时运行、late join、60 秒重新准入、Host 退出和重复 RPC；
- 各原子的正常、非法、边界、重复、乱序、并发和超时验证；
- 删除旧代码、RPC、配置、测试、资产入口和 fallback；
- 更新测试、验收和 Review 证据，不引用不可复核的历史报告冒充新鲜通过；
- 人工从 Frontend 到局末相册完成整局试玩，并按飞书体验目标观察结果。

## 5. 依赖顺序

施工顺序只解决依赖，不减少最终范围：

```text
WORK-00 合同与基线
├─ WORK-01 Data
├─ WORK-02 Run / Online / Framework
├─ WORK-03 Environment
└─ WORK-04 Equipment / GAS / Condition / Character
          ↓
WORK-05 Items / Camp / ShopEconomy
├─ WORK-06 Social
└─ WORK-07 Collection / Profile / Media
          ↓
WORK-08 全局 UI / Input / Presentation / Assets
          ↓
WORK-09 集成、删除与最终验证
```

为减少外部集成等待，WORK-00 完成后优先打通 Data、Environment、Equipment/GAS、Items/Collection 和 Framework 的生产端口；同一领域随后继续完成自身全部玩家闭环，不能把“端口可调用”记为模块完成。Run/Online 可以与这些端口并行推进。UI 和表现应随各原子接入，不统一拖到最后；WORK-08 负责全局一致性和最终世界接线。

## 6. 每个模块的开工协议

进入某个工作包时，再为该包建立有限的实施清单：

1. 读取对应飞书正式分册和关联表格，记录 revision、读取时间和未读范围；
2. 审计该模块当前源码、配置、测试和实际资产；
3. 列出该模块所需数据与资产，不提前枚举其他模块；
4. 把模块拆成可独立闭环的原子，每个原子写清 Command、State、Result、Terminal、Failure、复制、UI/Cue 和 Cleanup；
5. 先写验证合同，再实现唯一正常路径；
6. 运行构建、自动化、多人或实际运行验证；
7. 删除被替代路径并记录删除证据；
8. 更新验证证据表和当前 Framework 知识。

## 7. 验证证据记录

每个原子维护一行证据，最低字段如下：

| 字段 | 内容 |
|---|---|
| Work/Atom ID | 所属工作包和稳定原子编号 |
| 来源 | 飞书节点/revision 或 Engineering Working Decision |
| Ownership | SSOT、唯一写入者和生命周期 |
| 行为 | Command、State、Result、Terminal、Failure、Cleanup |
| 自动化 | 正常、非法、边界、重复、乱序、并发、超时 |
| 联机 | Dedicated、1/4/8 人、断线和重新准入 |
| 复制与隐私 | Snapshot/Cue 收敛和字段授权 |
| 资产 | 引用、加载、Cook 和实际触发 |
| 删除 | 旧符号、配置、测试、资产入口和 fallback |
| 人工观察 | 玩家实际看到的结果 |
| 结论 | pass / fail / blocked 及未验范围 |

没有新鲜证据时，只能记录“合同存在”“代码存在”或“资产已接线”，不能记录功能完成。
