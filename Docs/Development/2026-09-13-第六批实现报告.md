## 我故意没改什么、为什么

- **设计未裁**：第 4 条准入表与事件语义、TheftCaught 新锚点；没有把“清单缺失”偷换成“全部事件允许”，也没有补造事件名。挑战硬上限不在 D-29 删除范围。前五批仍未裁的试探期事实源、力竭行为等不在本批处理范围。
- **资产不可动**：所有 `.uasset/.umap`，包括正式商店蓝图、公共板子蓝图/网格/WBP；未制造占位资产，也没有写未存在的 Cook 资源路径。RPC/结构引脚的资产兼容性未确认，留给引擎复核。
- **范围外**：个人 durable Profile 发布链、个人印记归档代码、共享 `FCatDomainCommandContext` 的非商店版本协议、售鱼买家距离门、已知 7 个基线失败、UBA/UBT 配置。`Knowledge/`、`Docs/gap-analysis/`、README、AGENTS、CLAUDE 全未修改。

## 查过但没问题，以及证据边界

- 硬安全门与三带可分离；硬门仍使用原比值公式与 1.35 配置，不依赖已删阈值。
- 基础池明确有独立权重规则；本轮没有改它的挑战豁免、人数/生态门或迁移回退。
- 交互半径 override 和默认值保留；删除的是指定支付检查。保留的售鱼距离属于另一条职责链。
- 钱包 Revision 有 HUD、公开快照、账本与回执消费者，不能随输入参数删除；其他领域仍使用共用 ExpectedRevision。
- 上钩者身份已经在两个正式收鱼出口稳定存在；公共板子直接沿用，不使用最终拾取者或个人 Profile 摘要反推。
- 新公共容器来自 C++ 默认子对象，没有要求现有资产补一个必填字段才能开始记页；新增世界存档字段为空合法、版本仍为 6。
- 个人 FishRecorded 提交在可选印记事件检查之前；删除事件分支不会自动等于删除个人收集，但事件迁移仍没有完整接收方。
- 没有新增的人工业务进度入口；持续缺口已追加到 `需求对齐差距清单.md` 的 Data / World / Profile / Album 模块，模块未关闭。

`contract`：本轮只有静态代码、字段覆盖及 diff 检查证据；3 条新测试与扩充回归尚未执行。

`runtime_behavior`：正式收鱼、远距离支付、全队复制、迟加入、保存/继续、自然局末均待运行。不得用已写的断言替代通过证据。

`presentation_delivery`：正式板子、鱼页、爪印、翻页和营地布置均未交付；Widget/Actor 蓝图资产在本轮禁改范围。
