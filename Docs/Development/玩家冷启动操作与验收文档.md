## 这次写了什么

左上角那块现在不是完整主菜单，也不是通用 RPG 背包。它是 Lake 场景 HUD，用来告诉玩家当前猫状态、钓鱼反馈，并提示按 `Tab` 打开局内菜单。

项目里的“背包”目前准确叫“个人鱼护”：它只管你钓到的鱼。打开菜单后能看到单独的鱼护面板、WrapBox 格子、选中鱼、吃掉、入鱼缸、献祭和商店。商店已经放在同一个 `Tab` 菜单里，不是另一个独立入口。

## 功能怎么用

1. 打开项目后，默认进入 `Frontend`。
2. 点击运行，先走 Frontend 的在线入口。
3. 单人本地验收时点 `Host Session`，游戏会旅行到 `/Game/Catfishing/Maps/Lake?listen`。
4. 进入 Lake 后，左上角 `猫钓鱼湖` 面板是 HUD。
5. HUD 里的状态应该显示为 `中毒值`、`钓鱼力量`、`搏斗体力`，不应再是裸的 `0 / 50 / 100`。
6. 在 Lake 中按 `Tab`，打开鱼护/商店菜单；再按 `Tab` 或点 `关闭` 收起。
7. 菜单里的 `个人鱼护` 是鱼背包。没有鱼时应显示 8 个空格；有鱼时可以点非空格子，或用 `上一格` / `下一格` 切换。
8. 选中鱼后，点 `吃掉`、`入鱼缸`、`献祭`，UI 只发意图，真实结果由服务器事务返回后刷新。
9. 菜单里的 `商店` 区能看到队伍资金和按钮：`买二级竿`、`买窝料`、`领鱼饵`、`领保底竿`。
10. 点 `离开本局` 应走正式离局流程。

## 按键绑定在哪里

`Tab` 不是 WBP 蓝图按钮图标里的硬编码，也不再由 C++ 临时 `NewObject<UInputAction>` / `MapKey` 写死。当前绑定在正式 Enhanced Input 资产里：

- 输入动作：`/Game/Input/InputAction/IA_LakeMenu`
- 输入映射：`/Game/Input/InputContext/IMC_InputContext`
- 默认显示键名：C++ 从 `IMC_InputContext` 里找到 `IA_LakeMenu` 的映射后解析出来。

所以人工验收时，要看“菜单键为什么是 Tab”，应检查 `IA_LakeMenu` 是否在 `IMC_InputContext` 里绑定到 Tab；要看“按钮点了做什么”，才检查 `WBP_CatLakeReach` 里的按钮绑定和 `Request...` 函数。

## 给蓝图/前端开发的对接口径

WBP 只负责展示和发意图：

- 只读展示：`BlueprintPoisonText`、`BlueprintFishingStrengthText`、`BlueprintFightStaminaText`、`BlueprintFishGuardSlot0Text` 到 `BlueprintFishGuardSlot7Text`、`BlueprintFishCollectionText`、`BlueprintShopSummaryText`。
- 鱼护按钮只调用：`RequestSelectPreviousFishGuardEntry`、`RequestSelectNextFishGuardEntry`、`RequestSelectFishGuardSlot`、`RequestConsumeSelectedFish`、`RequestTransferSelectedFishToTank`、`RequestSacrificeSelectedFish`。
- 商店按钮只调用：`RequestPurchaseShopRodT2`、`RequestPurchaseBugChum`、`RequestClaimFreeBugBait`、`RequestClaimFreeStarterRod`。
- 菜单按钮只调用：`RequestCloseMenu`、`RequestLeaveLake`。
- 蓝图不能直接删鱼、改鱼缸、写献祭额度、改队伍资金或绕过 PageController/PlayerController。

后端负责真正改状态：

- 鱼护吃鱼走 Items 消费事务。
- 入鱼缸走 Camp/FishTank 事务。
- 献祭走 Sacrifice/Run 事务。
- 商店购买和免费领取走 Shop 服务端事务。
- 离局走 Online 子系统。

## 人工验收步骤

### A. 默认入口

操作：打开 `Catfishing.uproject`，不手动切图，直接运行。

期望：进入 `Frontend`，能看到可点击的进局入口，不应只看到黑屏或不明状态板。

### B. Frontend 进 Lake

操作：点击 `Host Session`。

期望：进入 `Lake`，日志出现类似 `ProcessServerTravel: /Game/Catfishing/Maps/Lake?listen`，Lake 内不再显示 Host/Find/Join 那套前端按钮。

### C. HUD 可读性

操作：进入 Lake 后观察左上角 HUD。

期望：标题为中文 `猫钓鱼湖`，状态有清楚标签，能看出 `Tab` 用来打开鱼护/商店菜单。

失败判定：仍显示 `CATFISHING LAKE / Current Cat / 0 / 50 / 100` 这种旧英文裸数字，失败。

### D. 鱼护菜单

操作：在 Lake 连续做两组打开/关闭检查：第一组按 `Tab` 打开菜单，再按 `Tab` 关闭；随后再次按 `Tab` 打开第二轮菜单，并再次按 `Tab` 关闭。第二组按 `Tab` 打开菜单，点击 `关闭` 按钮关闭；随后再次按 `Tab` 打开第二轮菜单，并再次点击 `关闭` 按钮关闭。

期望：每一轮菜单都能展开；第二轮打开后，`Tab` 和 `关闭` 按钮仍能正常收起菜单。菜单展开时能看到 `个人鱼护` 主面板、WrapBox 里的 8 个格子、选中鱼、鱼护动作按钮、图鉴数量、关闭按钮和离局按钮。

失败判定：按 `Tab` 没反应；第二轮打开后 `Tab` 或 `关闭` 按钮无法收起菜单；菜单没有鱼护区域；没有鱼时没有空状态提示。

### E. 商店菜单

操作：打开同一个 `Tab` 菜单，查看 `商店` 区。

期望：显示队伍资金和商店按钮：买二级竿、买窝料、领鱼饵、领保底竿。按钮点击后不应在蓝图里直接改钱或物品，而应由后端结果刷新。

失败判定：找不到商店区；按钮可点但没有任何意图或后端日志；UI 自己改状态。

### F. 鱼护动作

前置：鱼护里至少有一条鱼。

操作：打开菜单，切换鱼，分别点击 `吃掉`、`入鱼缸`、`献祭`。

期望：按钮只在有选中鱼且可提交时启用；点击后有等待或结果反馈；成功后鱼护数量、选中鱼和反馈文案刷新。

失败判定：按钮可点但没有反馈；UI 显示成功但后端状态没变；蓝图绕过服务器命令。

### G. 离局

操作：在 Lake 菜单中点击 `离开本局`。

期望：进入正式离局流程，回到 Frontend 或进入明确收口状态。

失败判定：黑屏、卡死、留在 Lake 没反馈，或用旁路 `OpenLevel` 代替正式离局。
