## 先说人话结论

你截图左上角那块不是完整主菜单，也不是传统意义上的大背包。它是 Lake 场景里的 `LakeReach` HUD：用来显示当前猫的状态、钓鱼反馈、个人鱼护、图鉴和局内菜单入口。

现在截图里看到的 `CATFISHING LAKE / Current Cat / 0 / 50 / 100`，按当前绑定代码分别对应猫的毒素、钓鱼力量和搏斗体力。但是它只露出了数字，标签没有正常解释清楚，所以对玩家来说就是一块不知所云的状态板。

当前项目里的“背包”准确说是“个人鱼护 / Catch Bag”：你钓到的鱼会进这里。它不是一个能装所有道具的通用 RPG 背包。

## 当前怎么操作

1. 打开项目后，默认应该进入 `Frontend` 地图。
2. 点击运行后，正常第一步应该看到在线入口 UI，包含 `Host Session`、`Find Sessions`、`Join First Result`、`Join Accepted Invite`、`Leave Session`。
3. 单人本地验收时，先点 `Host Session`。成功后游戏会进入 `/Game/Catfishing/Maps/Lake?listen`。
4. 进入 Lake 后，左上角出现 `CATFISHING LAKE` 面板，这是 LakeReach HUD。
5. 在 Lake 里按 `Tab`，应该打开局内菜单。
6. 打开的菜单里应该能看到 `Catch Bag`，这就是目前项目里的背包/个人鱼护入口。
7. 如果鱼护里有鱼，可以用 `Prev` / `Next` 切换选中的鱼。
8. 选中鱼后，可以点 `Eat` 吃鱼，点 `Tank` 转入营地鱼缸，点 `Sacrifice` 献祭。
9. 点 `Close` 应关闭菜单；点 `Leave Run` 应走正式离局流程，回到 Frontend 或进入对应的离局收口。

## 现在截图为什么会让人懵

当前截图对应的体验不能算合格。

主要问题是：

- 画面主体是黑的，玩家看不到 Lake、猫、路、水面、营地或钓鱼目标。
- 左上角 UI 只显示标题和数字，没有告诉玩家这些数字是什么。
- 没有任何“按 Tab 打开鱼护/菜单”的提示。
- 没有任何“先建房进入 Lake、去哪里钓鱼、如何开始钓鱼”的玩家引导。
- 当前“背包”叫法和项目里的真实功能不完全一致：实现上是个人鱼护，不是完整物品背包。

所以这不是你不会玩，是当前冷启动体验没有把玩家该做什么讲出来。

## 人工验收步骤

### A. 默认入口验收

操作：

1. 打开 `Catfishing.uproject`。
2. 不手动切换地图，直接运行。

期望：

- 应进入 `Frontend`。
- 玩家应看到可操作的进局入口。
- 不应只看到黑屏。

失败判定：

- 如果 Outliner 显示 `Frontend` 但地图里 `0 actors`，且玩家只看到黑底或无明确入口，本项失败。
- 如果一进来就直接看到 `CATFISHING LAKE`，但没有完成 Host/Join 进局说明，本项失败或至少记为流程混乱。

### B. Frontend 进 Lake 验收

操作：

1. 在 Frontend 点击 `Host Session`。
2. 等待旅行完成。

期望：

- 游戏应进入 `Lake`。
- 日志应出现类似 `ProcessServerTravel: /Game/Catfishing/Maps/Lake?listen`。
- Lake 内不应继续显示 Host/Find/Join 那套在线白盒按钮。

失败判定：

- 点 Host 没反应，失败。
- 旅行后仍停在 Frontend，失败。
- Lake 里还显示 Host/Find/Join 主入口，失败。

### C. Lake 场景可见性验收

操作：

1. 进入 Lake 后观察画面。
2. 移动镜头或角色。

期望：

- 玩家能看见猫或可控角色。
- 玩家能看见基本场景，例如地面、水面、天空、光照、营地或钓鱼点。
- 玩家能知道自己大概在哪、要往哪里走。

失败判定：

- 主画面仍是乌黑一片，失败。
- 只有 HUD 没有世界内容，失败。
- 有玩法 Actor 但没有可见场景和光照，失败。

当前证据结论：

- `Lake` 里已有 PlayerStart、水域、窝料锚点、营地和鱼缸等逻辑 Actor。
- 但排查日志没有看到光照、天空、大地形等可见场景要素。
- 因此“逻辑存在”不能替代“玩家看得见并知道去哪”。

### D. 左上角 HUD 验收

操作：

1. 进入 Lake。
2. 观察左上角 `CATFISHING LAKE` 面板。

期望：

- 面板应清楚说明它是 Lake HUD。
- 数值应带清晰标签，例如毒素、钓鱼力量、搏斗体力。
- 应有明确提示：按 `Tab` 打开鱼护/菜单。

失败判定：

- 只显示 `0 / 50 / 100` 这种裸数字，失败。
- 玩家无法从 UI 判断背包入口在哪里，失败。
- HUD 像调试面板而不像正式玩家界面，失败。

### E. 背包/鱼护菜单验收

操作：

1. 在 Lake 中按 `Tab`。

期望：

- 应展开菜单。
- 菜单应显示 `Catch Bag` 或明确中文等价文案。
- 应能看到个人鱼护数量、选中鱼、鱼护操作区、图鉴数量、关闭按钮和离局按钮。

失败判定：

- 按 `Tab` 没反应，失败。
- 菜单打开后看不到鱼护/背包区域，失败。
- 没有鱼时没有空状态提示，记为可用性问题。

当前证据边界：

- 代码和配置显示默认按 `Tab` 打开菜单。
- 自动化证明按钮意图和后端吃鱼链路存在。
- 但命令行测试环境曾出现 `ui_reach_menu_input_unavailable` 警告，所以真实键盘 `Tab` 手感必须人工再验一次。

### F. 鱼护动作验收

前置：

- 鱼护里至少要有一条鱼。没有鱼时，吃鱼、转缸、献祭本来就不应该可用。

操作：

1. 打开菜单。
2. 用 `Prev` / `Next` 切换鱼。
3. 点 `Eat`。
4. 再捕获或准备一条鱼，分别点 `Tank` 和 `Sacrifice`。

期望：

- 按钮只在有选中鱼且可提交时启用。
- 点击后应出现等待或结果反馈。
- 成功后鱼护数量、选中鱼和反馈文案应刷新。
- 后端日志应出现对应动作的提交结果。

失败判定：

- 按钮可点但没有任何反馈，失败。
- UI 显示成功但鱼护/鱼缸/献祭状态没有变化，失败。
- UI 自己直接改状态、绕过服务器命令，失败。

### G. 离局验收

操作：

1. 在 Lake 菜单中点击 `Leave Run`。

期望：

- UI 应把离局意图交给正式 Online 流程。
- 玩家应回到 Frontend 或进入明确的离局收口状态。

失败判定：

- 直接黑屏、卡死或留在 Lake 没反馈，失败。
- 用控制台或蓝图旁路 `OpenLevel` 代替正式离局流程，失败。

## 通过标准

这份冷启动验收只有在下面都满足时才能算通过：

- 默认运行能给玩家一个明确入口，而不是黑屏加不明 UI。
- Frontend 到 Lake 的进局路径清楚可点。
- Lake 场景可见，玩家能看见角色、环境和钓鱼点。
- 左上角 HUD 的每个数字都有玩家能理解的标签。
- HUD 或菜单明确提示 `Tab` 可以打开鱼护/菜单。
- `Tab` 能稳定打开和关闭菜单。
- 有鱼时，吃鱼、转缸、献祭能从 UI 点击走到后端事务，并刷新 UI。
- 无鱼时，菜单有清楚空状态，不让玩家以为系统坏了。
- 离局按钮走正式离局流程。

## 当前未通过项

- `Frontend` 地图目前是空世界，截图看不到可靠的玩家入口承载场景。
- `Lake` 地图目前有玩法逻辑 Actor，但缺少足够的可见世界内容，玩家进入后容易看到黑屏。
- LakeReach HUD 已挂载，但视觉表达仍像工程验证面板，不像玩家能理解的正式 HUD。
- 背包入口没有在首屏告诉玩家，导致玩家不知道按 `Tab`。
- “背包”这个词需要产品口径确认：如果目标是通用物品背包，当前实现不够；如果目标是钓到鱼后的鱼护，当前方向正确但表现和引导不足。

## 修复建议

优先级从高到低：

1. 给 `Frontend` 放入正式可见入口界面或至少可见背景，不要让默认入口像空地图。
2. 给 `Lake` 补齐光照、天空、地面、水面、相机/出生朝向和基础导航参照。
3. 把 HUD 三个裸数字改成玩家文案，例如“毒素 0 / 钓力 50 / 体力 100”。
4. 在 HUD 上加一个短提示：“Tab 打开鱼护”。
5. 菜单空鱼护状态增加“还没有鱼，先去水边钓鱼”。
6. 如果项目真的要“背包”，需要新增或明确物品背包 UI；如果只要鱼护，就统一把文案叫“鱼护 / Catch Bag”。
7. 对 `Tab` 菜单打开、关闭、焦点、按钮反馈做一次真实 PIE 或打包版本人工验收。

## 给开发的对接口径

前端 WBP 只应该做展示和发意图：

- 展示只读状态：毒素、钓鱼力量、搏斗体力、鱼护数量、选中鱼、图鉴数量、动作结果。
- 点击按钮只调用已有请求入口：上一条鱼、下一条鱼、吃鱼、转缸、献祭、关闭菜单、离开 Lake。
- 不要在蓝图里直接删除鱼、修改鱼缸、写献祭额度或绕过后端命令。

后端负责真正改状态：

- 吃鱼走 Items 消费事务。
- 转缸走 Camp/FishTank 事务。
- 献祭走 Sacrifice/Run 事务。
- 离局走 Online 子系统。

一句话：UI 只负责让玩家看懂并点按钮；真正的玩法结果必须由后端系统确认后再刷新回来。
