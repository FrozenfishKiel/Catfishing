# 需求对齐差距清单（代码 vs 飞书 GDD vs 技术方案）

文档状态：持续更新的差距台账。首次建立 2026-08-19。
事实来源：

- 产品事实：飞书知识库「小猫钓鱼」，2026-08-19 全量读取（9 册正文 + 4 张挂号表格 + 参数与校准记录 + 两篇裁决同步）。出处规则见该库「GDD 系统分册」页：**正式说法只认九册正文 + 已登记表格**。
- 代码事实：`Source/Catfishing`、`Config/`、`Content/`，2026-08-19 逐文件读取。
- 架构事实：`Docs/Architecture/项目技术方案.md`、`Docs/Development/项目开发工作计划.md`。

怎么用：每条差距有稳定编号（G-xx）。修完把状态改成 `已对齐` 并留证据；被策划否决的改成 `已裁决-不做`。**这份清单不替代飞书，也不能反向覆盖飞书**。

差距等级：

- `阻断`：链路当前跑不通，玩家碰不到。
- `错位`：代码实现了，但和已裁决的产品规则不一致（会做出错的行为）。
- `缺口`：产品已裁决，代码还没有对应实现或字段。
- `待裁`：飞书自己没定，代码保持 fail-closed 是对的，不要补。
