## 1. 当前已经完成

### Fishing 核心玩法

Catfishing 的钓鱼核心运行链已经接入项目，可以作为后续模块连接的代码基线。这里的“已经完成”指 Fishing 会话、阶段推进、搏斗、抢抄、捕获事务和后续结果出口已经存在，不表示玩家已经能从正式 Lake 场景完整操作，也不表示联机、UI、营地、档案和正式资产已经验收完成。

已接入的主流程包括：

- Run 与天气状态作为钓鱼流程的局内环境。
- 鱼竿及钓鱼所需装备进入玩法流程。
- 玩家抛竿并进入等待阶段。
- 鱼咬钩后进入提竿和搏斗阶段。
- 玩家完成遛鱼、抄鱼和捕获结算。
- 捕获结果可以继续交给后续物品、容器、经济和局内循环模块消费。

项目当前阶段已经从“建立 Fishing 内核”转入“把 Fishing 接成玩家可进入、可操作、可验收的完整游戏循环”。后续模块复用现有 Fishing 主线，不重新建设第二套钓鱼流程；发现 Fishing 内核缺口时，只补阻塞当前纵向链的部分。

### 当前可玩基线

2026-08-24 人工验收结论：当前项目可以打包，打包版本可以通过 Steam 联机正常找到房间，并能与其他玩家进入同一个 Fishing Run 一起钓鱼。这个结论用于给后续 AI 开发建立基线：项目不是“还不能玩”，而是已经具备可打包、可联机、可共同钓鱼的可玩闭环；后续工作是在这个可玩基线上继续补齐地图/输入/交互、UI/Reach、内容资产、成长状态、数据档案和交付验收等模块。

边界：这条人工验收不代表所有模块已经完成，也不替代各模块的自动化、运行时和人工验收；它只说明当前打包版本的 Steam 联机进房和共同钓鱼主链路已经可用，其他模块仍按下文状态继续开发。

## 2. 模块接入顺序与交付目标

| 主模块 | 接下来要完成的交付 | 与 Fishing 核心的连接点 |
| --- | --- | --- |
| Map / Input / Interaction | 统一正式 Lake 地图、输入资产和世界交互入口 | 让玩家通过正式场景与操作自然进入钓鱼及相关玩法 |
| UI / Reach | 建设 HUD、菜单、背包、图鉴和清晰的玩法提示 | 把 Fishing 状态、操作反馈、物品结果和后续入口呈现给玩家 |
| Items / Tank / Sacrifice / Camp | 建设鱼护、共享鱼缸、献祭、营地、休息和结算流程 | 承接捕获结果，并形成从钓鱼到局内推进的循环 |
| Equipment / TeamLibrary / Shop | 建设鱼竿、鱼饵、鱼漂、团队装备库以及商店购买、领取和装备流程 | 为钓鱼提供可获取、可管理、可生效的装备与消耗品 |
| Character / Growth / Condition | 建设猫的状态、Wet、Downed、恢复、成长和 Buff | 让角色状态影响钓鱼、探索和团队协作 |
| Frontend / Online | 建设前端进局、房间、多人游戏外壳以及后续在线能力 | 让玩家从正式入口组队进入同一个 Fishing Run |
| Data / World / Profile / Album | 建设数据目录、世界进度、Profile Grant、相册和印记 | 保存并展示钓鱼产出、收集结果和长期进度 |
| Run / Environment / Social | 建设 RunFlow、环境快照、水域/窝料聚鱼、求助/恶作剧/保护牌和重连边界 | 让 Fishing Run 从“能一起钓鱼”扩展为有局阶段、环境规则和协作边界的完整局循环 |
| Delivery / Harness / Assets | 为每个模块同步建设构建、回归验证、玩家验收和正式资产闭环 | 保证 Fishing 与新增模块组合后持续可运行、可验收、可交付 |

- Fishing 内核作为当前代码基线保留，但“玩家完整可玩”必须由本轮纵向链重新证明。
- 新模块按项目里程碑逐个接入 Fishing 主线。
- 每个模块完成后验证它与钓鱼流程的实际连接，不以孤立接口或开发按钮作为完成依据。
- 项目进度只维护“已经完成”和“接下来要做”两类状态；确认问题是进入对应模块前的阻塞条件，不作为第三种进度状态。
- 如果某个模块的工程闭环已经补齐但产品裁决仍缺，只保留一个模块级未完成结论和少量必须确认的问题，不把内部切面拆成散落的小任务。
- 本清单只维护模块级结论；详细代码入口、配置项、数值问题和历史处理不在这里堆叠。
