## 1. 当前已经完成

### Fishing 核心玩法

Catfishing 的钓鱼核心运行链已经接入项目，可以作为后续模块连接的代码基线。这里的“已经完成”指 Fishing 会话、阶段推进、搏斗、抢抄、捕获事务和后续结果出口已经存在，不表示玩家已经能从正式 Lake 场景完整操作，也不表示联机、UI、营地、档案和正式资产已经验收完成。

已接入的主流程包括：

- Run 与天气状态作为钓鱼流程的局内环境。
- 鱼竿及钓鱼所需装备进入玩法流程。
- 玩家抛竿并进入等待阶段。
- 鱼咬钩后进入提竿和搏斗阶段。
- 玩家完成遛鱼、抄鱼和捕获结算。
- 捕获结果可以继续交给后续物品、容器、经济和局内循环模块消费。

项目当前阶段已经从“建立 Fishing 内核”转入“把 Fishing 接成玩家可进入、可操作、可验收的完整游戏循环”。后续模块复用现有 Fishing 主线，不重新建设第二套钓鱼流程；发现 Fishing 内核缺口时，只补阻塞当前纵向链的部分。

## 5. 当前推进方式

- Fishing 内核作为当前代码基线保留，但“玩家完整可玩”必须由本轮纵向链重新证明。
- 新模块按项目里程碑逐个接入 Fishing 主线。
- 每个模块完成后验证它与钓鱼流程的实际连接，不以孤立接口或开发按钮作为完成依据。
- 项目进度只维护“已经完成”和“接下来要做”两类状态；确认问题是进入对应模块前的阻塞条件，不作为第三种进度状态。
- 如果某个模块的工程闭环已经补齐但产品裁决仍缺，只保留一个模块级未完成结论和少量必须确认的问题，不把内部切面拆成散落的小任务。
- 本清单只维护模块级结论；详细代码入口、配置项、数值问题和历史处理不在这里堆叠。
