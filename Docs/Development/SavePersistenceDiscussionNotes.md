## 需求基线锁定

第九模块 `Save / Persistence` 以 2026-08-31 读取并核对的飞书版本作为实现基线。后续飞书策划案即使继续更新，也不自动改变本模块的实现口径；除非人工明确宣布“重新锁定保存系统需求基线”，否则实现、技术方案和代码审查都按本文记录的版本判断。

当前版本的需求逻辑可以成立：它把“跨局长期事实”和“未结束当前局恢复数据”分开处理，因此不和局末清空冲突；多人读档也只恢复房主本地当前局，并通过稳定玩家身份匹配个人玩家块，不把本地存档升级成共享云档或长期房间。

## 策划已定口径

- 游戏是局制：开一局、玩、结束；不做沙盒房间持续保存、房间成长或局外世界状态。
- 跨局带走的是个人长期事实：图鉴、印记相册、外观解锁；失败不会回滚这些长期事实。
- 跟局走的是本局物资与局内状态：营地、鱼缸与局内图鉴、消耗品数量、公款与团队装备库、猫状态、祭坛进度与世界进度。它们可以跨天留存，但局末随局清空。
- 2026-08-27 的任务进度板把“相册 UI 与存档骨架”收窄为“存档骨架（图鉴／解锁／进度落盘）”：相册 UI、落水扑空触发和双人庆祝触发后置。
- W5 仍有“设置和保存、存档和加载、断线回大厅一键重邀 + 进度保底”的完整度要求，但飞书里没有查到 1 自动档 + 3 手动档、ESC 手动保存、读档替换自动档或删除入口的细化规则。

## 当前聊天补充决策

- 第九模块当前只讨论保存系统，不扩展图鉴系统，不做相册界面、新玩法触发或表现资源。
- 保存系统分两层讨论：第一层是系统怎么保存、读取和展示槽位；第二层是保存哪些数据。
- 自动保存和手动保存使用同一份数据结构，只是触发方式和目标槽位不同。
- 槽位先定为 1 个自动档和 3 个手动档。
- ESC 打开局内菜单后只提供手动保存入口；局内菜单不放读档、不放删除存档，也不做完整设置项。
- 局内保存菜单由 LocalPlayer UI 或同等独立入口打开，不由 HUD 负责创建、承载或转发。
- 所有有效槽位都可以读取。读取任意有效槽位成功后，删除当前自动档，并用读取到的内容新建自动档；旧自动档不保留备份，不做回滚方案。
- 读档/重建自动档过程中提示“保存中，请不要退出游戏”；玩家此时退出导致失败，系统不做额外补救。
- 存档槽列表先显示槽位名、保存时间、天数/进度、金钱、角色等级。
- 删除存档功能要做，但删除入口不放在局内 ESC 菜单里。

## 保存内容边界

- 保存系统不能把“跟局走”误做成“跨局永久保留”。本局未结束时，存档可以用于继续这局；一旦局末结算并清空，营地、鱼缸、物资、公款、团队装备库、猫状态和祭坛/世界进度不进入下一局。
- 当前局进度需要落盘：天数、阶段、额度目标与进度、世界进度、白天剩余时间或等价的倒计时事实。
- 当前局物资需要落盘：鱼护、共享鱼缸、营地公共仓库、消耗品数量、公款、团队装备库和商店当前库存。它们都是跟局走数据，只为继续当前局服务。
- 当前局玩家状态需要落盘：稳定玩家身份、是否已加入本档、位置、朝向、身体状态、成长/等级相关进度和当前装备选择。它们不是跨局成长。
- 已经进入世界并持续生效的短时世界效果可以作为当前局事实保存，例如窝料场、求助信号、防偷保护牌；它们不因为读档变成跨局永久状态。
- 正在进行中的过程状态不保存：钓鱼会话、偷鱼追回窗口、献祭预留、商店交易中间态、动作表现、镜头状态、临时输入锁和 UI pending 不进存档。读档只恢复存档中有的事实，不额外做一套“读档后取消”流程。

## 多人读档口径

- 存档首先是房主玩家的本地存档；多人只是允许其他玩家加入这一局，不把本地存档变成共享云档、在线房间快照或长期房间。
- 房主读取本地存档后，以该存档继续当前局；公共世界数据由房主恢复并同步给加入的客户端。
- 每个玩家自己的状态按稳定玩家身份匹配。旧档里有 A 和 B，但读档时只有 A 进入，则 B 的角色不在世界生成；B 的玩家块保留，等 B 加入后再恢复。
- 新玩家没有旧玩家块时，作为新角色加入。
- 多人读档不保存网络连接、旧客户端在线状态或自动重连关系。

## 当前代码事实

- 现有本地落盘容器是 `Source/Catfishing/Profile/CatProfileSaveGame.h` 中的 `UCatProfileSaveGame`。
- 现有读写入口主要在 `Source/Catfishing/Profile/CatProfileSubsystem.h` 和 `Source/Catfishing/Profile/CatProfileSubsystem.cpp`。
- 当前 `UCatProfileSaveGame` 已保存 Grant Journal、Applied Grant、鱼图鉴、印记索引、RunAlbum 封面、UnlockId 和装备选择。
- 这些代码事实只能说明当前工程已有实现，不等于最新策划需求。尤其是装备/解锁/长期档案相关代码，需要在第九模块实现前按飞书“身份跟人、物资跟局”的清单重新核对。
- 当前代码尚未实现独立局内保存菜单；第九模块需要补一个不依赖 HUD 的保存入口。

## 仍未确认

- 飞书没有给出槽位数量和槽位 UI 细节；当前 1 自动档 + 3 手动档属于聊天补充决策。
- 飞书没有给出保存安全窗口；哪些阶段允许手动保存，哪些事务需要先等结果再保存，仍需实现前确认。
- 旧版本存档是迁移、阻止读取，还是开发期允许丢弃。
- 哪些写入必须立即落盘，哪些可以排队或合并。
- 保存失败时哪些流程必须阻止 ACK，哪些可以只给玩家错误提示。
- 稳定玩家身份的具体来源还需实现前确认，例如平台账号、项目已有 StableNetId，或开发期本地身份。
