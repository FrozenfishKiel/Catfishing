# 用 codex 跑对表的实施记录（2026-09-13）

第一次把 `sync-docs-ahead` 的 Phase 2／2b 从 Claude 子 agent 换成 codex CLI。结论：可行。
下面只记「换成 codex 之后不一样的地方」，skill 本身的流程不重复。

## 为什么可行：3.7.0 的自校验钩子

`collect_gap.py --report <文件> --stage {analysis,review}` 能单份校验。
这是分水岭——报告合同很硬（五状态、Summary 恰好八行、两个比例各有公式、Scan Scope 非空、
`gap-inputs` JSON 依赖块、Code-only 节、出处必须括注且不许写列字母），
靠人对格式会磨死；有了它，codex 自己改到通过再交。

11 份分析报告**全部一次过**，我逐份独立复验也全通过。

## 编排

从 `gap-analysis.config.yaml` 自动生成每系统简报（docs／refs／scope／code 直接取配置），
再用一个 shell runner 按 K=4 分批跑，每批 `wait`。一个后台 Bash ＋ 一个 Monitor 管全程。

监控盯的指标要选对：
- 分析阶段盯「报告数 ＋ rc 文件数」，**不能只盯报告数**——codex 先写 Features 表、后补尾部三节，
  文件出现 ≠ 写完。
- 复核阶段盯「带 `### 复核记录` 节的报告数」，比文件存在可靠。

## 踩到的三个坑

**一、提前校验必然误报。** 报告文件一出现就跑 `--stage analysis`，会报「缺 Summary／缺 Scan Scope」——
那是它还没写到。**只在 `rc_<系统>.txt` 出现后才验那一份。**

**二、宽代码面的系统会把 codex 跑挂，而且是基础设施挂。**
`营地与局进程`（code 面 7 条，含 `Framework/Game/` 里两千多行的 `CatfishingGameModeBase.cpp`）
烧到 **44.9 万 token** 触发自动压缩，压缩服务返回
`Error running remote compact task: Selected model is at capacity`，进程死、产出全丢、rc=1。
跟任务难度无关。

缓解两条一起用，重试后 rc=0、日志里 compact 报错零命中，而且它成了**质量最好的一份**
（66 行、✅33、❌3、覆盖率 72.6%）——**降 effort 没有伤判据强度**：
- `-c model_reasoning_effort="high"`（默认是 xhigh）
- 简报里加窄读约束：先 `rg -n` 定位、再 `sed -n 'A,Bp'` 取窄区间，不整读大文件；
  设计文档可整读（不大），代码一律窄读。

复核阶段索性全部用 `high` 起，不等它撞墙。

**三、我自己数错过一次。** 看到「已结束 4/10、报告 5/11」以为有实例没产出报告，
其实 5 份里含探针那份，4＋1＝5 是对的。**报告总数与本轮 runner 的系统数不是同一个分母。**

## 治好了一个老毛病

上一轮 `环境与氛围` 34 行**全部**铸不出稳定键（RUN.json 里 unknown 34/34），
根因是它的出处写成 `环境与氛围.md rev106:65`——夹了 `rev106` 就解不出锚点。
简报里钉死「只用 `文件名:行号`，要带版本单独写进 Notes」之后，这轮 36 行 **unknown 0**。

## 抽验结果

拿最硬的四条自己复现：`MorningEndFraction=0 跳过清晨`、`天气直接复制 ConfiguredWeather 不随时钟切`、
`RainBloom 要求正在下雨而非雨后放晴`、`白天时长 10 分钟`。**4/4 对。**

最后那条我本来以为是它编的（我记得 20 分钟），结果 `数值模拟与参数记录.md:46` 白纸黑字

而且它是**跳出被指定的文档清单**去参数页取权威数值的——正是提示里「已建专表的数值以专表为准」
要的行为。**我的记忆比它的证据不可靠。**
