<title>图鉴</title>

> 本册范围：图鉴系统。游戏里出现过的东西——鱼、道具，以后可扩——玩家跟它打过交道，图鉴就记一笔。图鉴有两本：个人的跟人走，局内那块板子跟局走。本册持有两本的关系、分层解锁、登记归属与页面呈现；各类对象的数据本体归各自分册（鱼在鱼册、道具在道具册），本册只管怎么解锁、怎么呈现。
> 
> 与印记相册无关：印记记的是照片时刻，图鉴记的是信息，两者不混。2026-08-27 拆分，原「印记图鉴」册只留印记、改名「印记」。

# 1. 设计意图

**1.1 本册定位。**图鉴是猫世界的百科。它不是收集进度条，是「我认识这东西到什么程度」的记录——见过、钓上来过、吃进肚子过，是三种不同的认识。

跨局能跟人走的三样里（图鉴、印记相册、外观解锁），图鉴是唯一记知识的那样。局散了，钓过什么、吃过什么，还在。

图鉴有两本：个人的那本跟人走，局内那块板子跟局走。局内图鉴是营地里的公共陈列，全队钓到什么它就记什么——鱼缸摆今天钓到的实物，板子摆今天认识的记录。

**1.2 体验设计。**

| 体验 | 想塑造的体验 | 当前设计 | 达成度与缺口 |
|-|-|-|-|
| 翻图鉴是治愈的小仪式 | 像睡前翻手账，随时能翻，越翻越厚 | 分层页、个人最佳重量、首次遇上的条件回显、猫味翻页演出 | 个人图鉴的呈现形态未定，见 §10-5；局内图鉴已定为世界内物件 |
| 「待解锁」是钩子 | 翻十秒就知道自己还差什么 | 未到条件的字段写「待解锁」，不给占位数字 | 分层规格只有鱼落地，道具待对齐见 §10-1；开局满图是影时只看得出总数，钩子要靠剪影一个个揭开才立起来 |
| 帮忙也算数 | 帮人抄一网，自己图鉴也添一页 | 对这条鱼有贡献的猫一起登记收集层 | 有贡献的猫是否都刷新个人最佳重量，见 §10-2 |
| 篝火边的谈资 | 「这条你钓过没」「我吃过，麻嘴」 | 局内互看默认开放，不做排名 | 多猫同看的同步表现见 §10-4 |
| 剪影给下一个目标 | 把盲目甩竿换成有针对性地选窝料鱼饵 | 开局全是影，玩家自己的行为一个个揭开；剪影跟人走 | 触发口子开多少要控——开太多影一下全揭没悬念，开太少一直是黑的 |
| 今天我们一起认识了什么 | 回营地一眼看见这一局的账 | 局内图鉴被动记页，页上盖登记归属那几只猫的爪印 | 它只增不减，与鱼缸的会流走形成对位 |

**1.3 设计禁区。**

- ❌ 图鉴发奖励——图鉴只记录，不给任何东西。翻它是因为想知道，不是因为有东西可领；收集节点与集齐里程碑 2026-08-27 整条去掉。
- ❌ 图鉴排名——「谁的图鉴厚」只当谈资，不做排序、不做比拼。
- ❌ 跟印记相册混——照片时刻一律归印记册，图鉴只记信息。
- ❌ 拿占位数字糊弄——没解锁就写「待解锁」，不显示灰掉的假数值。每样东西对每名玩家都保留一次真实的第一次，知识不能靠转手拿到。
- ❌ 图鉴变任务列表——不下达「今日收集目标」，不弹每日提醒。缺口就摆在页面上，玩家自己翻出来当目标，系统不派活。

# 2. 核心循环

1. 出门钓：按已经揭开的线索挑饵、挑水域；一张影都没揭开的时候，就是随便下竿。
2. 碰上：钓空了一竿、或者眼看着一条鱼嫌弃地摆尾走了——黑影亮出轮廓，偏好与出现条件到手。
3. 钓到、吃掉：上岸登记收集层（对这条鱼有贡献的都算），吃下去登记知识层。
4. 回看：营地里翻自己那本，篝火边互相翻，看一眼板子上今天全队攒了几页。
5. 发现还差什么：满图的影和「待解锁」就是下一个目标。

单人能走完整个循环，多人更热闹。

# 3. 机制清单

## 3.1 设计意图核心

### 1. 图鉴记什么

| 对象类型 | 数据本体归属 | 分层规格 |
|-|-|-|
| 鱼 | 鱼册（鱼种档案与鱼表格） | 已定，见第 3 条 |
| 道具（竿／漂／抄网／鱼护／饵／窝料／增效消耗／社交演出类） | 道具册（五张表） | 不设线索层（2026-08-27 拍定，商店货架上就看得见）；也没有「吃」这个动作，剩下几层与条件待与道具册对齐 |
| 其余（环境、猫神、世界观物件……） | —— | 未定，不擅自开 |

### 2. 两本图鉴

图鉴有两本。个人图鉴跟人走，是自己的知识；局内图鉴跟局走，是营地里的一块公共板子——跟共用大鱼缸并列的第二件陈列，不是 UI 面板。鱼缸摆今天钓到的，板子摆今天认识的。

**被动记录，不用手写。**全队谁钓到一条新鱼，板上自动多一页；页上盖着登记归属那几只猫的爪印（沿用献祭记名的爪印语言），谁有份看得见。玩家不为它做任何操作。

**只增不减。**缸里的鱼会被献掉、吃掉、偷走，板上的页不会。这块板子和鱼缸是一对：一个陈列会流走的实物，一个陈列留得住的记录。

**板子不外流。**它记的是「这一局我们一起认识了什么」，不跟人走；自己那本自己记自己的。知识不在玩家之间转手——个人图鉴的每一层都得自己挣。

**单人局照样成立。**一个人玩，板子记的就是自己这一局的账，不因为没人交换而失去意义。

**互看照旧。**局内还能直接翻别人的个人图鉴比收藏，默认开放、不做排名。印记相册不互翻，公共回看只走篝火轮播（印记册口径）。

局末随营地一起清空。

### 3. 分层解锁

一样东西的图鉴页不是一次性开完，字段各有各的解锁条件。没到条件的字段显示「待解锁」。

鱼的三层：

| 层 | 解锁条件 | 这一层给什么 |
|-|-|-|
| 线索层 | 玩家行为触发（见下） | 轮廓、窝料与鱼饵偏好、出现条件——先给线索，让人知道该带什么、什么时候来 |
| 收集层 | 首次钓到 | 名字、彩色立绘、出没区域、个人最佳重量（此后每钓一条刷新一次） |
| 知识层 | 自己吃过；不可食用的鱼（咸鱼、湖心巨影）没有这一层 | 吃鱼效果（限时 buff 与经验值） |

**线索层靠玩家行为触发，不靠世界进度（2026-08-27 拍定）。**开局图鉴上所有鱼都是纯黑影——玩家知道湖里有多少种，别的什么都不知道。做了什么，才揭开哪一个。

| 触发 | 定义在 | 状态 |
|-|-|-|
| 上钩成立——鱼咬上了钩 | 本表（2026-09-07 李前臻补） | 揭给这一竿的钓手。之后跑掉、断竿、主动放弃都不回滚——剪影记的是「你碰到过这条鱼」，收集层要上岸才给 |
| 空钓——用了饵没钓上来 | 道具册「鱼饵丢失时安慰」：空钓时图鉴出现鱼的虚影 | 揭开的是当时咬钩失败的那条；鱼种预抽已落口径（钓鱼册：抽给窝点），揭给下钩的人、围观看见了不算 |
| 错饵被拒——鱼影游到钩边绕一圈，嫌弃地摆尾走了 | 道具册猫味演出 | 接口已落（钓鱼册鱼种预抽），道具册补演出规格 |
| 其余触发 | —— | 待定，口子别开太多 |

**剪影跟人走。**已揭开的线索层跨局保存，老玩家开新局带着上一局攒下的线索，新人开局满图是影。

**剪影只给信息，不当闸门。**揭开一条鱼的剪影＝知道有这条鱼、知道它什么条件下出现——出现条件本身就是这一层给的信息之一。鱼在不在水里由分布与刷新规则决定（归鱼册），跟剪影揭没揭开无关。

**当时看不清，是这一层成立的前提。**水里的鱼影只给存在感不给答案（钓鱼册口径：看得出有东西来了、大致多大，看不出是哪一种），所以「刚才那是什么」才需要图鉴回答。鱼影要是能当场认出鱼种，这一层就没东西可给了。

### 4. 登记归属

**收集层归上钩者。**成功收鱼时写入上钩者一人的图鉴（2026-09-07 N8、09-08 整册过稿）；其他有操作的猫只进演出贡献名单，不登记、不刷新个人最佳重量：

| 角色 | 登记 |
|-|-|
| 上钩钓手 | 算 |
| 合力拉竿的猫（巨型鱼） | 不算——只进演出贡献名单（合影、头衔），不刷新个人最佳重量（2026-09-08） |
| 抄网命中者 | 不算——只进演出贡献名单（合影、头衔），不刷新个人最佳重量（2026-09-08） |
| 拽尾巴救援的猫 | 不算（2026-09-07 李前臻拍改）——救的是猫不是鱼 |
| 打窝的猫 | 不算——窝打给整片水域，不对应哪一条鱼 |
| 围观起哄的猫 | 不算 |

**各层字段按鱼配置。**一条鱼有哪些信息由策划在鱼表上指定，没有的信息在图鉴上不存在、不留「待解锁」空位：不能吃的鱼就没有知识层，咸鱼与湖心巨影的页面只有线索层与收集层（2026-09-08 李前臻拍，销掉 09-07 挂的「两条鱼永远开不完」）。

**知识层不共享。**谁吃谁记。别人钓的鱼被自己吃掉，效果记进自己的图鉴；被偷走吃掉，效果记进小偷的图鉴。

重量一律按真实值记录，无组队加成。此后这条鱼被献祭、被吃掉、被偷走、局末清空，均不影响已记下的内容。

### 5. 图鉴页呈现

- 未解锁：纯黑影，只占一个位子。开局满图都是影，你知道湖里有多少种，别的什么都不知道。
- 线索层：轮廓清晰起来，给窝料与鱼饵偏好、出现条件；其余字段写「待解锁」。
- 收集层：彩页＋名字＋出没区域＋个人最佳重量＋首次遇上的条件回显；吃鱼效果一栏仍是「待解锁」。
- 知识层：吃鱼效果补齐，整页再无「待解锁」。

### 6. 分布线索呈现

剪影一揭开，图鉴就把这条鱼的出现条件摊开给玩家，不用自己试出来——线索层给偏好与出现条件，就是为了让人知道该带什么窝料鱼饵、去哪片水域、什么时候来。没揭开的还是黑影，一个字都不给。

### 7. 猫味演出①

- **翻页**：猫爪一下一下拨页；看到馋的鱼页舔嘴咂舌；对剪影页压耳朵哈气，像记仇；页角留爪印当书签。
- **入册瞬间**：新页展开的一刻，猫尾巴「唰」地竖直抖一下（沿用钓鱼册身体语言体系）。
- **破纪录**：猫对着旧数字歪头，然后一爪子把旧纪录拍掉。
- **多猫同看**：篝火边两只猫头挤在一起看同一页，第三只从背后探头。比图鉴本身就是社交。
- **板上新页**：新页自己翻出来的一刻，在场的猫都扭头看一眼；有份的猫凑过去把爪印按上去。

### 8. 抛印记事件④

- 首钓新鱼种：举鱼定格＋图鉴新页角标。
- 破个人纪录 / 本局全队最佳（局制下无跨局队伍纪录；趣味展示，不做排行）。

## 3.2 实施考量

- **呈现形态**：局内图鉴已定为世界内物件（营地里，跟鱼缸同类）。个人图鉴是纯 UI 还是随身物件仍未定，归「交互总规」（张佳）。猫的世界没有人类手账——A4 已给原则（猫世界讲得通、不用人类文化梗）。不管什么形态，翻页的猫味先保住。
- **分层是统一机制，层数不是**：鱼三层已定；道具不设线索层（货架上看得见），也没有「吃」这一层。各类对象的层数与条件各自定义，本册收口。
- **数据本体不搬家**：鱼的字段在鱼册与鱼表格，道具的在道具册五张表。本册只写「哪个字段属于哪一层」。

# 4. 系统边界

**硬性。**

- 本册是图鉴解锁规则与呈现的唯一归属；各类对象的数据本体归各自分册。
- 图鉴只记信息，照片时刻一律归印记册，两者不混。
- 个人图鉴跨局跟人走（与印记相册、外观解锁同列，清单见局与进程册）；已揭开的剪影同样跟人走。
- 局内图鉴跟局走，局末随营地一起清空。它只被动记录、不可写入，也不外流——个人图鉴的每一层都得自己挣，知识不在玩家之间转手。

**软性。**

- 已开页里没到条件的字段一律写「待解锁」，全库统一用词；整页未解锁的状态是纯黑影，不写字。

# 5. 涌现案例

- 「就差那条闪闪发光的鱼了」——全队一起撒窝料、凑条件开局（positive）。
- 收集党与献祭党抢稀有鱼去向，但图鉴已记，冲突降级成「摆缸里还是献掉」的良性拌嘴（positive）。
- 想解锁吃鱼效果就去偷别人的鱼：偷了就吃，知识层归吃的人（positive，给捣蛋鬼一条正当理由；毒鱼也照样下肚）。
- 专职抄网的帮手猫图鉴一样厚（positive，按贡献登记的直接后果）。
- 毒鱼防盗陷阱：把河豚留在鱼护里当诱饵，偷鱼贼盲吃翻车（positive，成立条件就是知识层没解锁，见猫册）。
- 夜里全队蹲在板前数今天攒了几页，数着数着开始翻旧账「那条是我抄的网」（positive，板上爪印是现成的话头）。
- 老玩家开局带着一叠已揭开的线索，新人满图是影，于是「带我去那片水域，我给你窝料」（positive，2026-08-27 拍定按好事看：熟人局本来就该老带新，不为此加追赶机制）。
- 图鉴完成度差距让新玩家露怯（negative 候选——靠「只比故事不比强度」与不做排名规避；线索层的落差不在此列，见上条）。

# 6. 体验锚定数字

- **对象总数**：调它改收集长线的长度与内容成本。
- **每层给的字段量**：调它改「待解锁」的钩子强度；给太多没悬念，给太少看不懂。
- **剪影触发的宽严**：调它改前期有多少目标可追——太松一晚上全揭开，太紧一直对着满屏黑影。
- **板上一页的信息量**：调它改回营地看板子这个动作值不值得——太少没人看，太多就成了第二本图鉴。

# 7. 视觉反馈通道

- 一眼可辨：纯黑影／有轮廓的影／彩页／「待解锁」，翻十秒就知道自己缺什么——是还没碰上、碰上了没钓着，还是钓着了没吃过。
- 入册反馈两层：当下的轻提示（不打断庆祝演出），回图鉴时的开页演出。
- 共用大鱼缸是活的图鉴：缸内按实际鱼种游动（营地册口径），看缸就等于翻一遍。
- 板子一眼看得出这一局攒了多厚：有页的和空的对比明显，页角的爪印说明谁有份。
- 已知缺口两条见 §10-3、§10-4：剪影触发口子开多少、多猫同看的同步表现。

# 8. Playtest 验收预期

- 新玩家翻一遍图鉴，能否自己说出「想钓到那条鱼，我该去哪，准备什么窝料鱼饵」。
- 篝火边会不会自发出现比图鉴、看别人图鉴的行为。
- 稀有鱼「献掉还是留缸」的讨论是否真的发生——发生了，说明「图鉴已记」的护栏让人敢献。
- 帮人抄网的玩家看到自己图鉴添页时的反应。
- 「待解锁」那一栏有没有真的驱动玩家去补。

| 钓鱼系统 | 登记时点＝上钩成立；贡献判定（合力拉竿、抄网命中、拽尾救援）的工程口径 |
| 猫咪与状态 | 吃鱼解锁知识层；毒鱼防盗陷阱依赖知识层未解锁 |
| 联机社交 | 局内互看默认开放、不做排名；按贡献登记是帮手猫路线的回报 |
| 营地 | 缸内游动＝活的图鉴；篝火边比图鉴的场景；局内图鉴的摆放位置与交互动线（跟鱼缸同类的场景物件） |
| 印记 | 本册④抛印记事件的接收；图鉴与相册不混；首钓事件与钓鱼册的接口去重 |
| 局与进程 | 个人图鉴与已揭开的剪影在跟人走清单里、局内图鉴在跟局走清单里 |
| 交互 | 图鉴呈现形态（交互总规） |
