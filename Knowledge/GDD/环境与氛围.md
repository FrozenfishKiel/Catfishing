# 1\. 设计意图

**1\.1 北极星贡献。**

- **惊喜的发起者（热闹）**：自然事件一出现，全队会放下手头的事聚过来。「都过来看！」这句话由世界喊出，不用任何任务指令去推。

- **印记的素材场（回看）**：特殊天气、自然现象、鱼群事件都能留下「那天我们一起遇到了……」这样的记忆。

- **支撑探索与发现**：森林湖特殊事件、风景点、隐藏观察点摆在那里，玩家会主动去看、去找，不是一路只算效率。

- **治愈的底色（不抢戏）**：光照、水声、风声铺在热闹底下；等待和看花观鸟的安静时刻由环境接住。湖畔一直在变，不是一张不动的地图，玩家会愿意一局一局回来。

**1\.2 体验设计。**

|体验|🎯 想塑造的体验|🛠️ 当前设计|🔍 达成度与缺口|
|---|---|---|---|
|体验一 · 这一局的湖畔有自己的一天|湖畔的每一天从清晨走到篝火，光线和气氛走完一条弧线（一局＝多天）。|局内时间流：开局就是起点，昼夜与天气随局内时钟推进，不读现实时钟；天气会改变画面和声音。|结构成立。旧方案担心「时间流速过快会错过事件」，局内时间流顺手解决了：事件跟局走，全员同局同时可见，这局没赶上下局还会来，不存在「没上线就错过」。缺口：一局时长与昼夜节拍的匹配归数值阶段。|
|体验二 · 世界会主动给玩家惊喜|玩家通过观察世界发现变化。|森林湖鱼群事件；彩虹、萤火虫等自然现象；鸟群、水面变化等环境反馈。|达成度较高。副作用沿自原稿：事件太少没期待，太多打乱日常节奏，用「少量高价值事件」原则约束。|
|体验三 · 探索比效率更重要|提供非资源目标。|河流负责日常生活，森林湖负责发现；沿途风景点、观察点、特殊植物与草药采集点。|中高。探索奖励不够时玩家还是会回到效率路线。目前主要的非资源奖励是环境事件抛出的印记。|

（原稿体验「玩家拥有属于自己的自然空间」随营地建设一起删掉：不摆装饰、不改景观；个性表达交给猫外观、图鉴与照片。剩下的种花可能性见 §3\.1\-6 取舍建议。）

**1\.3 玩家策略路线。**

- **日常生活型**：待在河流边钓鱼，顺便看看天色和水面，图个稳定休闲。

- **探索发现型**：往森林湖跑，蹲特殊事件、找隐藏观察点、顺路采草药，冲的是没见过的东西。

- **多人事件型**：把全队喊来一起赶鱼群、一起看彩虹晚霞，顺手推祭坛目标，要的是大家都在场。

**1\.4 设计禁区。**

- ❌ **复杂生态模拟**：吃掉开发资源，也冲淡核心体验。替代：少量高价值自然事件表达生命感。

- ❌ **高压力天气系统**：把治愈和自由都压没了。替代：天气只给氛围和鱼情机会（如雨天某些鱼更活跃），不做惩罚。

- ❌ **大规模地形改造**：湖畔是固定舞台，地形不给改。

- ❌ **环境强制影响玩家进度**：环境给的是机会，不是拦路的。

- ❌ **任何机制读现实时钟**：时间源只有局内时间流。

# 2\. 核心循环

开一局，湖畔的一天从头开始（待定：起点时段）
→ 光线与天气随局内时钟推移，鱼情跟着变
→ 自然事件按时段登场，一句「都过来看」把散开的人叫到一起
→ 事件里钓鱼、扑萤、围观、抓拍进印记
→ 天色沉下来，回营地篝火收尾（衔接营地册）
→ 局末环境状态随局清空；能带走的只有图鉴与照片，下一局从头再来

# 3\. 机制清单

## 3\.1 设计意图核心

### 1\. 局内时间流（昼夜循环）

**设计意图。**给一局一个「今天」的形状：开局是清晨的新鲜，收尾是夜里的余味，玩家会觉得这个世界一直在旁边过日子。

**机制。**时钟源为局内时间流，开局启动、随局推进、局末即弃；没有现实时间，也没有离线概念。昼夜会改光照与环境音；鱼情修正只发生在白天时段（清晨 / 黄昏差异，夜晚不钓鱼，供钓鱼册消费），也决定自然事件在哪个时段出场（萤火虫只在夜里、晚霞只在黄昏）。（已定：一局＝多天，每天一条从清晨到入夜的时间弧线，白天限时推进、夜晚无时限停摆，全员同意后开始新的一天（天结构见局与进程册）；篝火回看在每晚夜色里。白天时长与弧线走法待数值。）

**猫味演出①。**入夜全体猫瞳孔放大变圆，草丛里亮起两排反光的眼睛；清晨有猫伸懒腰打大哈欠；正午有猫找树荫瘫成一滩。

**抛印记事件④。**昼夜本身不单独抛印记，④交给时段专属的自然事件（晚霞 / 月光 / 萤火虫，见 §3\.1\-4 事件表），宁缺毋滥。

**⚠️ 最容易破的实施陷阱。**时间变化只剩画面好看，玩起来没区别。昼夜至少要挂上「事件出场时段」和「白天内的鱼情差异」两件事才算数（夜晚是营地段，不产鱼情）。

### 2\. 天气机制

**设计意图。**让每一局有不同的脸色，情绪跟着天气走。

**机制。**晴 / 雨 / 雾等按局内时钟切换，画面和声音跟着变；对鱼情做机会向修正；有些自然事件要看天气才出（雨后出彩虹）。天气在猫身上的痕迹（淋湿 / 抖水）只做演出表现，不带数值惩罚。淋湿规范归猫册（表现型状态），本册只触发。

**猫味演出①。**雨天炸毛甩水；一群猫挤在大叶子下躲雨探头探脑；有猫伸爪接雨滴；雾天猫走两步就回头找同伴、尾巴竖成小旗子；雨停全员集体抖毛，水花四溅。

**抛印记事件④。**全员挤在一处躲雨的团子同框，抛印记。

**⚠️ 最容易破的实施陷阱。**天气只剩装饰，玩家记不住。每种天气至少绑一个专属演出或专属事件。

### 3\. 双区域探索结构（河流 / 森林湖）

**设计意图。**两个区域要有区别：河流负责日常生活，森林湖负责发现。

**机制。**河流靠近营地，开阔顺手，是日常水域；森林湖藏得深一点，要走一段路，鱼种与事件偏稀有；风景点与隐藏观察点集中在沿途与湖区。森林湖沿途与湖区设**草药等采集点**，分布点位本册持有（草药用途见猫册的晕倒解除，获取定价见装备册），让「走这一段路」多一个理由。两区域同属「湖畔」主场景。（钓点已定义：玩家概念而非机制点位，任意水边可钓，打窝或看中风景即自发成为钓点；两区域鱼情差异由分布规则（鱼类图鉴）决定。装备册「捞浮木」的水域点位一并在此统一。）

**猫味演出①。**去森林湖的路上有可扑的蝴蝶、可追的落叶；猫穿过草丛沾一身草籽，停下来舔毛整理；采药凑近闻会打喷嚏（演出规范见猫册）。

**抛印记事件④。**首次抵达森林湖，穿过树林视野一下子打开的那个瞬间（单猫剪影或全队首达合影），抛印记。

**⚠️ 最容易破的实施陷阱。**两个区域只是换了张皮。差异要落在「能遇到什么」上：不同鱼、不同事件、不同风景、不同采集物。

### 4\. 自然事件机制（印记素材场）

**设计意图。**制造偶然的惊喜，让世界自己给出一个把全队聚起来的理由；印记相册「风景页」主要靠这里供给。

**机制。**事件按局内时钟与天气条件出场，少而精；必须隔着距离也能察觉（声音 \+ 光 \+ 猫身体语言，复用钓鱼册咬钩信号的思路），不然各玩各的，没人会过来。每个事件显式标注是否抛印记（触发写法等 C7 裁决：清单式还是规则式）：

|自然事件|出场条件（局内）|抛印记事件④|猫味演出①|
|---|---|---|---|
|彩虹|雨后放晴|抛——彩虹下的全员同框|猫歪头看天，有猫试图伸爪去够|
|萤火虫|夜晚 · 草木边|抛——猫跃起扑萤的瞬间|扑空空抓；萤火虫落在鼻尖上看成斗鸡眼；追着光点转圈|
|晚霞|黄昏|抛——湖边一排猫剪影|猫不自觉坐成一排看天，尾巴尖同步轻摆|
|月光湖面|夜晚 · 晴|抛——月下湖面与两排反光猫眼|有猫对着水里的月亮伸爪拍，拍碎了愣住|
|鸟群 / 蝴蝶|白天|不单独抛（作演出素材融入其他印记）|看鸟时喉咙发出咔咔咔；匍匐压低身子挪近；扑空后立刻舔毛装没事|
|森林湖鱼群|（待定，见机制 5）|抛——沸腾水面与手忙脚乱的猫|猫沿岸急得来回踱步，尾巴炸成瓶刷|

**⚠️ 最容易破的实施陷阱。**事件频率没调好：太少没期待，太多把日常节奏冲垮。

### 5\. 聚鱼时刻：一个机制、两种触发源（已与钓鱼册统一）

**现状。**本册原稿有「森林湖周期性鱼群事件」，钓鱼册（正式版）有多人叠窝触发的「盛宴聚鱼」，两者的表现与收益高度重叠。

**定义。**统一为一个机制「聚鱼时刻」，两种触发源：

- **玩家触发**：多人向同一水域叠加窝料（即钓鱼册「盛宴聚鱼」，规则以钓鱼册为准，本册不改动它）；

- **自然触发**：森林湖按局内时钟 / 天气条件自发涌现鱼群（本册供给）。

两种触发进入同一套演出与钓鱼收益（鱼群涌现、巨物预告、稀有概率提升）。玩家学一次就认识两个入口：「自己攒出来的盛宴」和「世界白送的盛宴」。（已统一命名；两种触发共用一个稀缺预算，按一个机制记一本账。自然触发的条件与频率待数值阶段，需与钓鱼册对齐后定稿。）

**猫味演出①。**水面开始沸腾时，全场猫耳朵齐刷刷转向同一方向；奔向水边的猫急刹不住，前爪撑地滑出一段；到岸边挤成一排探头，尾巴集体竖起轻抖。

**抛印记事件④。**全队奔向同一片水域的场面，抛印记。

**⚠️ 最容易破的实施陷阱。**两套鱼群各写各的逻辑，玩家要学两遍，程序要做两遍。

### 6\.（取舍建议 · 待定）种花：轻量环境交互，不是建造

**背景。**原稿「营地周围环境改造」（种花 / 摆放装饰 / 改变景观）中，摆放装饰与景观改造跟着营地建设一起删掉了。

**取舍建议。**种花若保留，只能是环境册自己的轻量交互：固定花坛点位，种下当局开花，局末随局清空；不存档、不成长、不装修。价值点是「花招来蝴蝶蜜蜂 → 给猫可扑的东西 → 给印记加布景」，定位是氛围道具，不是建造玩法。本册建议：砍掉也可接受（表达欲已由猫外观、图鉴与照片接住）；若美术余量允许再做，优先级排在自然事件之后。（待定：保留与否。）

**猫味演出①（若保留）。**猫埋种子刨土刨得满脸土；对着刚开的花打喷嚏；扑花间蝴蝶压倒一片花。

**抛印记事件④（若保留）。**花丛里滚作一团扑蝶，可抛。

## 3\.2 实施考量

- **环境丰富度 vs 开发成本** → 少量高价值事件。

- **真实模拟 vs 游戏节奏** → 保留真实感，但服务体验。

- **随机事件 vs 可控体验** → 系统按局内时钟排程周期事件，随机只做小抖动。

- **种花自由度 vs 系统复杂度** → 由原「限制营地附近改造」进一步收缩为「固定点位轻量交互或不做」（见 §3\.1\-6）。

- 所有环境状态（时间、天气、事件进度）都属于这一局，局末即弃、无持久化。多人同步按局内广播做，不需要跨局存档。

# 4\. 系统边界

**硬性。**

- 不读现实时钟，所有时间机制都以局内时间流为源。

- 不做复杂生态模拟、不做生存压力环境、不做大地图环境编辑、不做天气惩罚核心玩法。

- 无跨局环境存档，环境状态跟局走，局末清空。

- **轴的定义权在本册，鱼表在图鉴册**：区域 / 时段 / 天气三条轴的枚举（有哪些区域、哪些时段、哪些天气）由本册定义；鱼落在轴上哪一格，由「鱼类图鉴」册的分布表持有。本册只提供修正入口，不写鱼表。

- 猫的淋湿、疲惫值等状态归「猫咪与状态」册，本册只触发不定义；草药的用途归猫册、获取定价归装备册，本册只持分布点位。

**软性。**

- 环境变化优先服务情绪；事件要少，但得让人记住；玩家愿意抬头看世界；自然反馈做足。

- 每个新自然事件立项前先过四问④：会留下值得回看的瞬间吗？既不抛印记也没有演出的事件不要做。

# 5\. 涌现案例

- 钓鱼系统（positive）：白天时段与天气造成鱼情差异（雨天出特别的鱼），玩家挑钓点就有了理由；聚鱼时刻是环境和钓鱼的交汇处。风险：环境事件过强，玩家只等刷新不钓鱼。

- 营地（positive）：环境给营地的收尾做背景，天色沉下来就是全队往回走的信号，篝火在夜色里才显得暖（每天固定入夜，天色一收拢大家就回营）。

- 祭坛（positive）：自然鱼群帮助推进献祭目标，创造多人事件。风险：玩家只为任务进入环境。

- 联机社交（positive）：自然事件给了大家一起干点什么的理由，一句「都过来看」就是现成的聚拢广播。原稿担心的「错过事件导致玩家差距」在局制下不成立：事件对同局全员同时可见，不存在离线错过。

- 印记图鉴（positive）：本册是素材场，环境印记撑起篝火回看的「风景页」。

- 猫咪与状态（neutral）：雨天淋湿只做演出表现（猫册口径：表现型状态，不带数值惩罚），环境不作为惩罚来源。

- 待观察（neutral）：全员看晚霞，没人钓鱼。大概率是个治愈时刻，但如果高频打断主循环就得调事件时长。

# 6\. 体验锚定数字

（不写数值，只写调它会改什么。）

- **白天时长（天节拍）**：调它改每天的节奏与事件排布密度（夜晚无时限，不计入）。

- **天气变化频率**：调它改环境新鲜感和稳定性。

- **自然事件出现频率（含聚鱼时刻的自然触发）**：调它改世界惊喜程度与祭坛推进速度。

- **单个事件持续时长**：调它改「赶得上吗」的紧迫感与围观人数。

- **探索点密度（风景点 / 观察点 / 采集点）**：调它改玩家探索动力。

# 7\. 视觉反馈通道

- 视觉：天色与光照变化、湖面波纹、鱼跃、鸟群聚集、植物随时段的细节变化。

- 声音：雨声、水流声、风声、森林环境音；夜晚虫鸣是「入夜」的听觉信号。

- 行为（猫即信号）：猫群集体扭头看向同一方向 = 有事件发生；瞳孔变圆 = 入夜；全员抖毛 = 雨停。事件的远距离感知复用钓鱼册「声音 \+ 猫身体语言」的信号思路。

**已知缺口。**

- 一局昼夜节拍与时长匹配（数值阶段）。

- 双区域鱼类差异表（归鱼类图鉴册，待对齐）。

- 自然事件完整清单与出场条件表（本册补齐后交印记册对 C7）。

- 猫与环境互动的动画清单（与猫咪与状态册对齐）。

# 8\. 何时回审

- 聚鱼时刻自然触发的条件与频率定稿时。

- C7（印记触发形态）裁决后，回填事件表的触发写法。

- 捞浮木与草药点位落图定稿时。

- 一局时长与昼夜节拍第一版数值出来时。

- 首次多人 playtest 之后（事件聚拢力验证）。

# 9\. Playtest 验收预期

- 自然事件出现时，散在各处的玩家会不会放下手头事聚过来（聚拢力）。

- 一局结束后玩家能否说出「这局什么天气、遇到了什么」（记忆点）。

- 有没有玩家整局蹲守事件刷新而不钓鱼（事件过强的信号）。

- 篝火回看时，环境印记（彩虹 / 晚霞 / 萤火虫）是被停留观看还是快速划过。

- 玩家会不会为了草药或风景专程去一趟森林湖（探索理由是否成立）。
