# 1\. 设计意图

**1\.1 北极星贡献。**

- **成为一只猫**：玩家不是在操控角色，是在当一只湖畔的猫。行为表现、身体状态、对环境的反应一起做到位，玩家才会觉得「我正在作为一只猫生活」。全项目的猫味演出以本册为源头。

- **状态是喜剧发生器**：饥饿、疲惫、中毒、淋湿首先是搞怪素材（画龙走路、翻肚皮晕倒、炸毛抖水都是笑点），其次才用来调节奏。失败与翻车是内容，不是事故。

- **倒地是聚人事件**：玩家倒地 → 伙伴围观、舔脸、拖回营地。这一串下来会留下「朋友救过我一次」的记忆，也是现成的印记素材。

- **世界生命感**：舔毛、甩尾、打哈欠、打滚、对天气的反应，让湖畔像有猫在过日子，而不只是一张场景图。治愈的日常感就靠这些。

**1\.2 体验设计。**

|体验|🎯 想塑造的体验|🛠️ 当前设计|🔍 达成度与缺口|
|---|---|---|---|
|体验一·像真实猫一样生活|猫的身份认同。|舔毛 / 甩尾 / 打哈欠 / 打滚 / 伸懒腰 / 趴下休息等行为库，并与状态联动。|达成度高，猫咪行为是系统核心识别点；副作用是动作数量增加会提高动画成本，需按「高识别、高情感」排优先级。|
|体验二·能从身体读出状态|不看 UI 也知道自己饿了、累了。|饥饿值、疲惫值、淋湿表现，通过动作变化、行为反馈、状态限制外化。|达成度高；副作用是状态反馈过强会削弱自由探索。|
|体验三·探索中有好笑的自然风险|方便 vs 安全的取舍，翻车了也笑得出来。|有的鱼有毒，吃了会中毒；解法是草药解除、伙伴救援；中毒与晕倒全程做成喜剧演出。|达成度中高；副作用是中毒机制需要避免成为惩罚陷阱。|
|体验四·多人之间产生真实帮助|「朋友救过我一次」。|中毒 / 疲惫过度 → 倒地 → 伙伴寻找、围观互动、搬运回营地、草药恢复。|达成度高，自然形成合作；副作用是救援流程过长会降低体验，倒地者和救援者两边都得有戏看。|

**1\.3 玩家策略路线。**

- 路线一·安全生活型：只吃认识的安全鱼种、定期回营休息。稳定、安全。

- 路线二·探索冒险型：长时间在外，饿了不挑鱼，不认识的也敢吃。效率高，但可能吃到毒鱼。

- 路线三·多人互助型：结伴探索、互相救援、分享资源。靠团队降低风险。

- 路线四·独立生存型：单人探索、自己管理状态、野外休息。节奏自己定。

- 路线五·蹭吃蹭喝型（懒猫觅食）：不钓鱼，偷别人的鱼吃回饥饿。规则归「联机社交」册，本册只认「偷吃能回饥饿」这个出口。

**1\.4 设计禁区。**

- ❌ **复杂生存模拟**——破坏休闲治愈体验。不做：饮水系统、温度系统、多疾病系统。替代路径：少量核心状态 \+ 强表现反馈。

- ❌ **宠物养成结构**——破坏「玩家就是猫」的定位。不做：亲密度、等级成长、属性培养。替代路径：通过行为变化体现生命感。

- ❌ **高频死亡惩罚**——倒地要好笑，死亡不好笑；破坏治愈底色，也让人不想开下一局。不做：饥饿死亡、疲劳死亡、普通状态导致永久失败。替代路径：倒地 \+ 救援恢复，且单人不卡死。

- ❌ **复杂食物系统**——挤占钓鱼和营地核心体验。不做：烹饪、菜谱、食材组合（烹饪机制已拍定删除）。替代路径：鱼直接吃，一步到位。

# 2\. 核心循环

1. 外出：钓鱼、捣乱、探索，随局内时间与活动消耗饥饿值、疲惫值。

2. 补给选择：稳妥线（吃认识的安全鱼种）／赌一口线（饿急了不认识的鱼也吃，可能中毒）／蹭吃线（偷别人的鱼，见联机社交册）。

3. 状态压过头才触发：中毒或疲惫过度 → 倒地（喜剧演出，不是惩罚画面）。

4. 救援：伙伴围观、舔脸、拖回营地、喂草药复活；单人可缓慢爬行自救回营。

5. 恢复状态，继续下一轮生活。

倒地是支线不是必经环节；正常管理状态的玩家整局都见不到它，见到的人也应该笑着被拖走。

# 3\. 机制清单

## 3\.1 设计意图核心

### 1\. 猫咪行为表现机制

**设计意图。**让玩家感受到自己是猫。

**机制。**舔毛、甩尾、打哈欠、打滚、伸懒腰、休息、睡觉等行为库，并与状态联动：饿了舔嘴、盯着别人的鱼护看；累了瞌睡点头；无聊时追自己尾巴、拍水面、盯蜻蜓（与钓鱼册「等待期可自由活动」衔接）。

**猫味演出①。**本册即猫味源头。群体行为自带喜剧：打哈欠会传染，一只打完一排跟着打；营地睡觉挤成叠罗汉。

**抛印记事件④。**多猫同步打哈欠；篝火边叠罗汉睡成一堆。

**⚠️ 最容易破的实施陷阱。**只堆动作数量，没有状态关联。

### 2\. 饥饿值机制

**设计意图。**建立食物循环，给钓鱼一个「口粮」出口。

**机制。**随局内时间与活动消耗；恢复入口＝吃鱼：钓到的鱼直接吃，不需要加工（有的鱼种有毒，见本册毒鱼与中毒机制）、偷吃他人的鱼（懒猫觅食路线，规则见联机社交册）。吃掉的鱼不影响图鉴（钓到瞬间已记录）。（待定：小鱼干等食物系鱼饵能不能直接吃掉——「饵还是粮」的边界，与装备与道具册共同观察后定。）

**猫味演出①。**饿的程度全靠演：肚子咕噜声周围能听见、盯着队友鱼护舔嘴唇、趴在缸边挑鱼；吃鱼时叼住甩头吞下，吃完舔爪抹脸、满足眯眼。

**抛印记事件④。**一圈猫趴在缸边挑今天吃哪条；饿猫盯着别人鱼护咽口水被抓拍。

**⚠️ 最容易破的实施陷阱。**变成定时打卡任务，打断正在进行的热闹。

### 3\. 疲惫值机制

**设计意图。**控制探索节奏，并为演出提供状态输入。

**机制。**来源＝移动、钓鱼、特殊活动；恢复＝野外休息（应急、慢）、营地休息（安稳、快，设施见营地册）。疲惫程度分档外化：轻→打哈欠；中→走路拖沓、尾巴耷拉；重→坐下就瞌睡点头。

**对钓鱼的影响方式。**表现层（疲惫的猫拉竿软绵绵、钓鱼中打瞌睡等演出变形，不动数值）还是数值层（影响搏斗表现），（待定：C5 体力闭环——钓鱼册议题，两案未裁，与 A2 失败惩罚方案联动）。裁定前钓鱼册按「只读疲惫值、不被疲惫惩罚」理解。

**猫味演出①。**累猫走路四条腿打架、原地坐下秒睡、瞌睡点头点到差点栽进水里又惊醒。

**抛印记事件④。**一排猫在篝火边东倒西歪睡着；湖边钓着鱼瞌睡点头的剪影。

**⚠️ 最容易破的实施陷阱。**限制玩家探索自由。

### 4\. 毒鱼与中毒机制

**设计意图。**给吃鱼加一点自然风险：认识的鱼放心吃，不认识的赌一口；翻车过程本身是内容。

**机制。**有的鱼种有毒，吃到会中毒；毒性是鱼种属性（数据归鱼类图鉴册），钓到记入图鉴后这种鱼就认识了。中毒不是惨状而是好笑的失态：走路画龙（直线走成 S 形、脚步交叉绊自己）、瞳孔变成漩涡、打嗝冒泡泡、产生幻觉，头顶气泡里把队友看成一条大鱼、对着石头哈气、扑向不存在的小鱼扑空打滚。加重则晕倒：原地晃三晃、定格一拍、慢镜头翻成四脚朝天，舌头露出一小截，尾巴尖还一翘一翘（表示没事，就是躺会儿）。

**猫味演出①。**如上，幻觉与晕倒姿势全套喜剧化；不用骷髅、毒液等事故感符号，中毒标识用头顶转圈的小鱼。

**抛印记事件④。**画龙走路一头撞进队友怀里；翻肚皮晕倒瞬间（待定：C4 若裁定失败瞬间不进印记，此条降级，仅保留拖运与救醒入册）。

**⚠️ 最容易破的实施陷阱。**两头都会破：毒鱼太少太好认，机制没存在感；太多太难认，吃鱼变扫雷、中毒变惩罚陷阱。守住两条：损失必须可恢复，演出必须比损失更让人记得住。

### 5\. 倒地与救援机制

**设计意图。**创造多人故事，倒地是聚人事件。

**机制。**中毒 / 疲惫过度 → 倒地；倒地者可缓慢爬行（单人可爬回营地休息自愈或自带草药自救，保证不卡死）；伙伴可搬运回营地（营地是救援送回落点，见营地册）、喂草药解除。倒地者视角不黑屏：镜头贴地，能看见围过来的猫脸怼镜头。被救的人也有戏看。

**与钓鱼的衔接。**钓鱼中倒地（回应钓鱼册 B3 昏迷归属）：中断钓鱼、进入本册倒地流程；钓鱼状态机被打断后的回退细则归钓鱼册。落水后的湿毛表现见本册淋湿机制，落水的具体处置（待定：A2）。

**旁观者互动。**凑近嗅嗅、爪子戳戳肚皮、舔脸（把倒地猫舔得一脸毛乱；舔脸是否附带微量恢复，待定：数值阶段）、有的猫干脆在旁边躺平陪倒凑热闹。

**搬运演出。**叼后颈拖着走（猫妈叼小猫式），被叼住后颈的猫触发镇静反射，瞬间蜷成放松的一团；一路拖出两道痕；拖到一半掉了，滚一圈，捡起来继续拖；两猫可协作抬运（一个叼脖子一个托屁股）。

**猫味演出①。**见上，倒地—围观—拖运—复活全链路都是段子。

**抛印记事件④。**倒地被拖回营地全程；围观舔脸救醒瞬间；双猫抬运。

**⚠️ 最容易破的实施陷阱。**救援流程过长。拖运要短到是段子，不能长到变苦差。

### 6\. 草药机制

**设计意图。**连接探索与恢复，给森林湖一个采集理由。

**机制。**森林湖随机采集（分布见环境与氛围册，获取定价见装备与道具册）；用于解除晕倒。

**猫味演出①。**采药用嘴叼、爪子刨，凑近闻会打喷嚏；喂药时病猫先皱鼻子抗拒 → 打一个大喷嚏 → 原地弹起炸毛 → 抖抖毛没事了。

**抛印记事件④。**喷嚏复活的弹起瞬间。

**⚠️ 最容易破的实施陷阱。**变成必须刷的医疗资源。

### 7\. 淋湿与抖水机制

**设计意图。**让天气与落水在猫身上留下好笑又真实的痕迹（表现型状态，不是数值条）。

**机制。**雨天渐湿、落水全湿；湿毛贴身瘦一圈（原来是只小细猫）；上岸 / 回檐下后从头到尾波浪式抖水，水珠四溅；半干时毛蓬成一团。雨天猫会下意识往树下、叶子下钻。与钓鱼册「湿毛抖水＝落水收场」的表现衔接由本册持有规范。

**猫味演出①。**抖水甩旁边的猫一脸，被甩的一脸嫌弃跟着抖，连锁抖水。

**抛印记事件④。**雨天集体炸毛合影；抖水甩人一脸的连坐瞬间。

**⚠️ 最容易破的实施陷阱。**淋湿变成负面 debuff。它是演出素材，不该带数值惩罚。

## 3\.2 实施考量

- **状态真实感 vs 游戏压力**：更多状态更真实，但增加管理负担。选择：饥饿 \+ 疲惫两个核心数值状态，淋湿只做表现。

- **风险感 vs 休闲体验**：毒鱼中毒提供风险，但不能阻止探索。选择：晕倒可恢复，不永久损失。

- **多人互动价值 vs 单人可玩性**：救援增强社交，但不能依赖多人。选择：单人可通过休息与爬行自救恢复。

- **动作丰富度 vs 开发成本**：优先做高识别、高情感动作。

**通用动画规范（本册持有，各册引用）：实时物理动画混合关键帧动画，表现猫的软体感与笨拙：猫爪抓握 / 怀抱按目标物自动贴合，双脚随地面坡度调整站立；尾巴与耳朵由程序化动画驱动，随运动、情绪与风向摆动，紧张时尾巴炸毛变粗，害怕时耳朵压平；入水后毛发变塌，出水抖身水珠粒子四溅。多猫交互动作同属通用层**：扑倒滚成一团（恶作剧反制与偷鱼被抓共用一套演出，供联机册引用）、碰鼻子（打招呼与双人庆祝共用）、舔脸、叼后颈搬运。钓鱼场景的逐阶段演出细节归钓鱼册子页「钓鱼动作表现集」，本册持通用层。

# 4\. 系统边界

**硬性。**

- 不增加复杂生存指标；不做生命值系统。

- 不做宠物成长系统；不做复杂医疗系统；不做烹饪系统（拍定删除，鱼直接吃）。

- **状态跟局走**：饥饿 / 疲惫 / 中毒 / 淋湿均为一局内的状态，开局重置、局末即弃；跨局持久载体只有鱼类图鉴与印记相册（项目级已拍定），猫的状态不在其中。

- 状态术语以本册声明为准（猫的日常消耗＝「疲惫值」；搏斗内的力量 / 体力归钓鱼册），其他册不得另造叫法。

**软性。**

- 状态优先通过视觉表现，行为反馈优先于 UI 提示，鼓励玩家观察猫咪。

- 保持失败可恢复，单人不卡死。

- 休息的设施实体归营地册；本册只定义状态的进出规则。

# 5\. 涌现案例

- 钓鱼系统（positive）：鱼不只用于收集，也是猫的口粮，形成钓鱼 → 食物 → 状态管理；风险是避免强迫玩家重复刷鱼。

- 营地（positive）：营地成为恢复和生活中心，回家 → 休息；风险是不能让营地成为唯一选择。

- 环境与氛围（positive）：天气影响猫的表现（雨天湿毛、抖水）；风险是避免环境变成惩罚。

- 联机社交（positive）：倒地救援形成玩家故事；风险是避免依赖在线玩家。

- 装备与道具（neutral / positive）：草药、鱼竿等资源联动；风险是不要扩展成复杂生存装备体系。

- 装死骗舔脸（positive，待观察）：有猫故意躺平假装倒地骗围观，本身是搞怪内容，但要看会不会干扰真救援的判断。

- 围观救援变全员看戏（neutral，待观察）：一猫倒地全队来围观，没人钓鱼，与钓鱼册「全员围观」同款现象。

# 6\. 体验锚定数字

（数值本体交由数值模拟，此处只记调它会改什么。）

- **饥饿下降速度**——调它改玩家回营地频率。

- **疲惫积累速度**——调它改探索节奏。

- **毒鱼比例与毒性强度**——调它改吃鱼的风险感与认鱼知识的价值。

- **野外休息恢复效率**——调它改探索容错率。

- **倒地持续时间**——调它改救援紧迫感。

- **草药恢复效率**——调它改失败恢复成本。

- **搬运移动速度**——调它改拖运是段子还是苦差。

- **中毒幻觉时长**——调它改好笑与烦人的分界。

# 7\. 视觉反馈通道

- 动作反馈：打哈欠、舔毛、甩尾、动作迟缓、蜷缩休息。

- 环境反馈：淋湿毛发、雨天抖水、草地休息、往树下躲雨。

- 状态反馈：饿了舔嘴盯鱼护、累了瞌睡点头、中毒画龙走路 \+ 头顶转圈小鱼、晕倒四脚朝天。

- 社交反馈：围观舔脸、叼后颈拖运、双猫抬运、营地恢复。

已知缺口：动作库优先级未定；状态 UI 是否存在未定（软性倾向无 UI、纯表现）；倒地与中毒演出已有方案，待动画原型验证；休息动画与场景互动需要后续验证。

# 8\. 何时回审

- A2（失败惩罚）/ C5（体力闭环，钓鱼册议题）裁决落定时：疲惫对钓鱼是表现层还是数值层随之定稿，落水处置随 A2 定。

- C4 裁决落定时（中毒晕倒瞬间是否进印记需回改④清单）。

- 数值模拟给出饥饿 / 疲惫 / 中毒第一版参数时。

- 首次多人 playtest 之后（救援时长、倒地是否好笑的实测）。

- 动作库优先级排定、动画成本评估完成时。

- 联机册恶作剧细则（B4）落定时，若恶作剧会读写状态（如惊吓炸毛、追逐耗疲惫）需对齐。

- 「饵还是粮」边界与装备册有观察结论时（饥饿机制恢复入口随之增删）。

# 9\. Playtest 验收预期

- 不看任何 UI，玩家能否从猫的动作读出「我饿了 / 我累了」。

- 倒地的玩家是笑还是恼；贴地镜头 \+ 围观互动能否让等救援不无聊。

- 救援方是否觉得拖运值得做、像段子而不是跑腿。

- 中毒演出看第 N 次是否仍好笑，有无重复疲劳。

- 单人玩家倒地能否自行脱困，全程无卡死。

- 状态管理是否打断了钓鱼的热闹（有没有「被闹钟叫回家」的打卡感）。
