# 阅读与权威规则

> [!IMPORTANT]
> 本目录保存设计资料，不代表同名系统已经在工程中实现。设计状态与实现状态必须分别判断；截至 2026\-08\-10（v1\.6），以下分册均未发现对应的玩法代码、地图或资产落地。

1. 统一术语、废弃说法和跨分册职责以本页为入口，具体机制仍回到对应系统主册核对。
2. 系统框架以对应主册的最新版本为准；钓鱼相关内容发生冲突时，以「钓鱼系统」正式册为准。
3. 附属资料只补充主册，不取得同级权威；公式、参数、鱼种内容和演出速记应按各自状态阅读。
4. 标注为「待定」「暂定」「已知缺口」或仍引用决策编号的内容，不得写成已裁定事实。同级主册之间出现冲突时保留冲突，等待属主或决策源裁定。
5. 实现状态只由当前工程中的源码、配置、地图和资产证明，不能从 GDD 的完整度、版本号或「正式版 / 已成稿」反推。

# 术语总表

统一用词的一句话口径；细则见属主分册。

|统一用词|一句话口径|属主分册|
|---|---|---|
|鱼护|钓点边的随身渔获容器，可被偷（弃用「鱼篮」）|钓鱼系统 / 营地|
|共用大鱼缸|营地共用渔获容器：跟局走、跨天留存、鱼带主人色环，是明天额度的储备仓|营地|
|疲惫值|猫的消耗状态（不再用「体力」「生存系统」指代猫）|猫咪与状态|
|力量 / 体力（搏斗）|钓鱼搏斗内猫与鱼各有力量与体力（挣扎值弃用；搏斗体力与疲惫值的关系待 C5）|钓鱼系统|
|聚鱼时刻|一个机制两种触发源：玩家叠窝 / 环境自然事件，共用演出与稀缺预算|钓鱼系统＋环境与氛围|
|钓点|玩家概念而非机制点位——任意水边可钓，打窝或风景让一处自发成为钓点|钓鱼系统|
|浮木|修竿材料统一口径（旧称「木块」同物）|装备与道具 / 营地|
|局 / 天|局＝多天的一轮（run）；白天限时凑额度，夜晚无时限，全员同意翻天|局与进程|
|额度|每日献祭额度：逐日上升，前期纯数量后期附鱼种指向；未达成＝局失败|局与进程|
|跟人走 / 跟局走|跨局归属二分：身份（图鉴 / 印记 / 解锁）跟人走，物资（营地 / 缸 / 耗材 / 状态 / 祭坛进度）跟局走|局与进程|
|鱼类图鉴|收集数据唯一归属：钓到即记，此后献 / 吃 / 偷均不影响记录|鱼类图鉴|
|印记 / 印记相册|照片时刻唯一归属（「个人钓鱼图鉴」等混称不再使用）|印记图鉴|
|湖畔|主场景总称；河流 / 森林湖双区域是其内部探索结构|环境与氛围|

# 跨分册接口一览

一行一条只记口径；细则见双方分册的 §10 速查。

|接口|口径（谁持有 / 谁消费）|
|---|---|
|鱼种数据|鱼类图鉴持有分布 / 偏好 / 稀有度的 SSOT；钓鱼、装备、环境只消费不定义|
|聚鱼时刻|钓鱼（玩家叠窝）与环境（自然事件）双触发源，共用一套演出、收益与稀缺预算|
|失败预算|钓鱼「丢饵」与装备「断竿」同池分配——玩家一次失败只挨一刀（细则待 A2）|
|渔获流|钓到即记图鉴 → 鱼护 → 共用大鱼缸 → 献祭 / 吃 / 观赏，局末随局清空；钓鱼持钓获、营地持容器、联机持偷窃规则|
|偷窃|联机社交持规则（偷了就吃 / 进食追回窗 / 权限开关）；营地持大缸舞台；钓鱼持鱼护；上限＝单条鱼，装备不可偷|
|状态与救援|猫咪与状态持饥饿 / 疲惫 / 中毒倒地与救援；钓鱼消费疲惫读写；营地是休息 / 救援送回的出口|
|草药|装备管获取与携带；猫咪与状态管效果与演出；环境管分布|
|印记触发|各册在机制里显式抛「④事件」；印记图鉴持总清单与分发规则（清单式 / 规则式待 C7）|
|跨局归属|局与进程持「跟人走 / 跟局走」清单；装备、图鉴、印记按它执行解锁与留存（解锁形态待 A5）|
|天循环|局与进程持结构（白天限时 / 夜晚无时限 / 翻天）；环境持光影与额度告急氛围；营地持夜晚据点段|
|动画与演出|猫咪与状态持通用动画技术方案；「钓鱼系统 · 机制细案」附录持钓鱼逐阶段演出；各册「猫味演出①」持机制级要求；总索引见世界观与美术基调页|

# 统一模板

每份分册严格按以下结构写，区分框架层（§1\-§5 设计意图）、内容层（§6 数字）与交互层（§7 反馈通道）：

|§|段落|内容|
|---|---|---|
|1\.1|北极星贡献|系统对愿景哪几条做出贡献|
|1\.2|体验设计|每条体验三段：🎯 想塑造的体验 → 🛠️ 当前设计 → 🔍 达成度 \+ 副作用|
|1\.3|玩家策略路线|玩家视角的取舍空间|
|1\.4|设计禁区|❌ 硬性不做 \+ 会破坏哪条体验 \+ 替代路径|
|2|核心循环|玩家可感知的 4\-6 步定性循环|
|3|机制清单|3\.1 设计意图核心 / 3\.2 实施考量（trade\-off）|
|4|系统边界|硬性禁止 \+ 软性建议|
|5|涌现案例|跨系统涌现定性描述（positive / negative / neutral）|
|6|体验锚定数字|不超过 5\-6 个「调它会改什么」|
|7|视觉反馈通道|关键反馈通道 \+ 已知缺口|
|8|何时回审|触发器清单|
|9|Playtest 验收预期|真人测试观察点|
|10|实施细节速查|cross\-ref 代码 / 场景 / 数据 / 上下游分册|
