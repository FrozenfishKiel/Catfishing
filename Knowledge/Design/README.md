## 三条数据流

哪类文件往哪个方向走，决定了你该在哪儿改。**改错地方的后果是被覆盖或被忽略。**

### 一、九册正文、愿景、裁决账本 —— 在这里写，往飞书同步

`GDD 系统分册/`、`北极星愿景.md`、`世界观与美术基调.md`、`数值模拟与参数记录.md`、`设计修改记录.md`（里程碑页 2026-09-15 起只在飞书，它是排期不是设计文档）

改这些**直接改本目录里的文件**，走 git 提交。**飞书上的同名页不再镜像正文**（李前臻 2026-09-15 定）：每页只保留一份「规则版摘要」，用规则表述帮读者更快建立心智模型，不要求与仓库一致；判定细节、数值与出处只在仓库。摘要由人在设计有大改时重写，推到飞书用：

```bash
python Scripts/push_feishu_summary.py --doc 钓鱼规则 --file <摘要.md>   # 整页覆盖，页顶自动带「规则版摘要」横幅
```

摘要不进仓库（它不是经过审核的设计文档）；含内嵌表的页（商店）脚本会保留表格只换正文；覆盖会丢飞书页上的评论。

### 二、内容表 26 张 CSV —— 两边都能改，以仓库为准（2026-09-15 李前臻拍）

`GDD 系统分册/**/*.csv`（鱼表格、道具四表、ui 表、商店表、窝料表、动作表现集的内嵌表）

张佳、王甜甜照旧在飞书表格里填值，定稿后由人拉进仓库；裁决改表可以直接改仓库里的 CSV（09-13、09-14 已这么做过）。两边不一致时**仓库是真值**。
所以拉飞书表进来的人要先看仓库这张表自上次拉取后有没有改过（`git log -- 那张表`），改过的先回写飞书再拉，不能整张覆盖。
拉取用 `Scripts/export_feishu.py`（2026-09-15 从已废弃的设计项目搬回仓库）导出到临时目录后复制。`_manifest.json` 里 sheets 的 `revision` 仍是飞书原值；仓库直改的表要另刷 `content_sha1`（刷新脚本目前只管 docs）。
旧版鱼表格（饥饿口径）2026-09-15 起删除（飞书页签、仓库文件、配置与清单一并清）。

### 三、草稿、同步页与点子 —— 在飞书起草，审核通过才迁入本目录成为真值

新东西在飞书起草是正常路径（李前臻 2026-09-15 定）：策划案、方案、点子先在飞书写，属主与李前臻审核；**通过审核才迁入本目录、成为 SSOT**。没迁入的不算现行设计，对表工具也不把它当要求读。迁入的动作：导出 Markdown、补 front matter（`ssot: true`、node_token／obj_token、migrated_from_feishu_revision）、登进 `_manifest.json` 的 docs 与对表配置、跑一次哈希刷新、飞书原页页头挂横幅指回仓库。

这些页只在飞书：裁决同步下的属主页、程序页、两张 09-09 清单与分支交接页，点子库，临时美术资源表格，入侵物种（09-10 裁「点子库，不实装」），以及里程碑这类不是设计文档的页。**仓库不再放它们的快照**（2026-09-15 李前臻定：本地只留经过审核、用来指导实现的设计文档；原 `_feishu/` 目录与对表配置里的三处 refs 同日删除）。

## front matter 怎么读

```yaml
ssot: true                        # 本文件是真值；飞书同名页是副本
node_token / obj_token            # 飞书页身份，同步回去要用；也是对表稳定要求键的 doc 身份
migrated_from_feishu_revision     # 迁入时飞书的 revision，只作溯源
```

## `_manifest.json` 的三个坑

下游各读各的，改之前先看清楚：

1. **`node_token` 不得更改。** 它是 `sync-docs-ahead` 稳定要求键 `<doc>#<anchor>#<h8>` 里的 doc 身份，改了整份基线对不上，历史迁移表全废。
2. **`sheets[].revision` 保持飞书原值（整数）。** `Scripts/check_fish_table_vs_definition.py` 按 `sheet_name` 找表、读这个值判「资产是否落后于表」（当前：资产按 rev 580 生成、表已 872）。换成别的类型这条检查会静默降级成 `?`。
3. **`docs[].revision_id` 已改成内容哈希。** 正文在仓库里写，飞书 revision 不再是变更信号；`collect_gap.py --plan` 靠它判断哪些系统要重跑。原值留在 `feishu_revision_id`。
